# 织卷

织卷是一款面向本人使用的 Android AI 小说生成与阅读 App。用户只需给出简单设想、题材、篇幅和呈现偏好，App 负责规划、逐章生成、长篇记忆、检查和继续创作；完成章节可立即阅读。

## 当前状态

- 产品名已确认：织卷。
- 临时 Logo 已归档：`branding/selected/zhijuan-logo-draft.png`。
- 开发前产品、技术、测试和发布文档已完成第一版。
- Android 工程、Debug APK 和核心自动化测试可通过 Gradle Wrapper 构建。
- 首次启动说明、连接向导、本地连接管理、创建页和开始前确认占位已接入：支持四类官方服务、兼容中转、零生成模型发现、自动推荐、严格手填回退、可选完整验证、加密持久化和当前连接管理；已有连接时直接进入创作页，只输入一句设想即可创建本地书记录和不可变快照，也可按需展开五组自然语言补充项。短篇最低/默认目标 80 章，中篇最低/默认目标 300 章，长篇由用户填写 301–10,000 章；留白/均衡/细写已映射为版本化内部指令，细写不会连带提高暴力等题材维度。确认页会重新读取快照中的章数和模型，价格未知时不显示 0 或猜测金额；当前确认不会调用模型。界面不显示原始密钥，并支持浅深主题、大字体、横屏和窄屏。故事种子、故事圣经和全书总纲的三阶段引擎、严格结果契约及不可变提交已经完成本地假模型端到端验证；确认页、真实预算/目的地门禁、实际 Provider 和阅读界面仍未接通。
- 底层加密数据、任务审计、模型能力登记，以及 OpenAI Responses、Chat Compatible、Anthropic Messages 与 Gemini GenerateContent 四条 API 路径已经进入可测试实现。
- Android 前台生成服务骨架已接入正式构建：仅承载用户明确启动的活动任务，通知默认隐藏书名和正文，并提供暂停/停止；Android 15 系统限时会持久化为可恢复暂停后及时退出。它目前只负责生命周期和控制，不冒充尚未接入的真实章节执行器。
- 无网络的恢复/维护执行器已接入正式构建：App 启动后安排一次唯一恢复检查，并每天安排一次受电量与存储约束的维护；它只审计 SQLCipher 中已过期的 Job/Stage 双租约、保守处理未知结果和清理受保护草稿，不持有 Provider 生成能力，也不会创建新的 Attempt。
- `zhijuan.prompt-bundle.v1` 已冻结：不可变创建快照可以确定性绑定为覆盖全部 13 个生成阶段的契约；章节计划、正文、检查和修订会自动继承呈现档位与场景连续性规则。细写档在成年人门禁通过时要求关键过程覆盖 100%、淡出替代 0，并保持身体、空间、感官和余波连续；该规则不会连带提高冲突、伤害、语言或压迫尺度，也不增加默认页面操作。故事种子、圣经、总纲、有限窗口和第一章快车道的底层链路已经完成：首章可用种子与前三章粗计划提前准备，但第二章前必须存在适配已提交第一章的完整圣经、总纲和当前窗口证据。当前测试仅使用本地假模型，不发起真实模型请求。
- `chapter-draft.v1` 正文流与截断续接底层链路已完成：Provider 只返回单字段 `body`，增量 JSON 由本地解码后才进入加密草稿；达到输出上限时使用新 Attempt、独立 Usage 和精确尾部锚点自动续接，已保存正文先复制到新草稿，锚点只校验不重复写入。最多自动续接 3 次，格式/锚点/4 MiB 大小异常或再次截断会保存现场并转为需要处理；崩溃恢复不重新联网。
- `chapter-story-tracking.v1` 时间线/伏笔投影底层链路已完成：只从同一最终章节版本及其已验证章节记忆生成；时间线只记录正文实际事件，伏笔使用 PLANT/DEVELOP/RESOLVE/ABANDON 有限状态转换和追加式来源台账。当前版本、记忆、既有伏笔或人物快照变化时，会在联网前或提交前失败关闭；旧章节替换会把中间状态依赖标为失效，不允许继续污染后文。
- `chapter-consistency-report.v1` 一致性与呈现检查底层链路已完成：正文先经过本地确定性检查，再进入零温度模型语义检查。检查请求精确绑定候选正文、已知人物/事实、场景执行契约和关键过程节点；细写场景会逐项核对淡出替代、动作—反应、空间/身体/感官连续性、过程覆盖和相关余波。模型只能返回有界问题码、严重度、位置、已知 ID 与固定修订动作，不能在检查阶段直接改写正文。任何 blocker/major 都阻止候选发布，仅 minor 可继续；当前只完成检查结果草稿映射，有限修订和正文+派生数据最终原子提交由 TASK-059 接通。
