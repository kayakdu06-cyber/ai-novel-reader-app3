# 织卷工作报告 51：E4.9 前台生成服务与通知控制

> 日期：2026-08-02  
> 对应任务：TASK-048  
> 结论：完成并通过 Android 15 真实系统限时探针、双模拟器回归、全项目离线构建与安全门禁

## 1. 本阶段交付结果

织卷已经具备正式的 Android 前台生成宿主。它负责在用户明确开始后保持一次活动任务可见、接收通知栏暂停或停止，并在 Android 15 系统限时到来时安全退场；持久数据库仍是唯一任务事实来源。

- 正式组件是不导出的 `dataSync` 前台服务，使用 `START_NOT_STICKY`，不会在系统杀死后擅自重启；
- 持续通知默认不展示书名、人物、Job ID 或小说正文，只显示通用状态与暂停、停止操作；
- 通知暂停和停止不是界面假动作，会通过正式 Repository 写入持久控制意图；
- 系统限时使用独立原因 `SYSTEM_FGS_TIMEOUT`，与用户暂停和用户停止分开；
- 系统限时暂停可继续，继续只把任务恢复到 `READY`，不会直接联网、创建 Attempt 或产生模型费用；
- 服务仅观察和控制既有 Job，不创建小说任务，不推动 Stage 进入生成状态，也不持有 Provider 发送能力；
- 新增公开的 Job/Stage 组装入口，App 不需要接触 Room Entity 或 DAO，阶段数量、JSON 大小、幂等键和 attempt 上限统一验证。

这仍然不是“真实章节循环已完成”。当前服务是合规且可恢复的生命周期宿主，实际章节执行、预算预留、数据目的地确认和恢复调度将在后续任务接入。

## 2. 关键安全设计

### 2.1 服务存活不等于任务状态

Android Service 的创建、销毁、startId、通知 ID 和进程 PID 都不写入小说任务。服务进程消失不会自动把 Job 判为完成、失败或重新开始，避免进程回收后重复付费。

服务仅在 Job 为 `READY`、`RUNNING`、`PAUSING` 或 `STOPPING` 时保持；任务进入暂停、停止、完成、失败或需要处理后，服务立即移除通知并退出。

### 2.2 Android 15 系统限时不会卡死服务

`onTimeout` 不等待网络或长事务。应用级协调器负责持久化 `SYSTEM_FGS_TIMEOUT`，服务同时启动 1.5 秒硬停止计时，优先在系统宽限内退场。

若 Job 尚未发出请求，可直接原子进入 `PAUSED`；若已有活动 Attempt，则复用既有 `PAUSING → PAUSED` 安全点协议。持久化尚未完成也不能阻止服务按时退出，下一次恢复由数据库证据继续裁决。

### 2.3 通知权限不成为静默常驻借口

Android 不要求先取得 `POST_NOTIFICATIONS` 才能启动前台服务，但前台通知仍是必需的。权限被拒绝时，织卷不会省略通知要求或伪装后台运行；App 内仍保留任务状态和控制入口。

### 2.4 控制写库竞争失败时以数据库为准

暂停、停止、系统限时同时发生时，不用 Service 内存覆盖已经落盘的更强控制。竞争失败后服务及时退出，由数据库较新的状态决定下一步。

## 3. 主要实现落点

- `core/database/.../GenerationJobSetupRepository.kt`：App 安全创建 Job/Stage 的公开边界；
- `scripts/run-task048-foreground-timeout-probe.ps1`：只允许显式 API 35 模拟器的真实系统限时探针；
- Debug-only probe receiver：只在 Debug 包存在，正式 Release 清单中为 0。

## 4. 验证结果

| 验证范围 | API 35 | API 30 | 结果 |
|---|---:|---:|---|
| App 全量设备测试 | 42/42 | 42/42 | 通过 |
| Database 全量设备测试 | 82/82 | 82/82 | 通过 |
| Generation feature 设备测试 | 9/9 | 9/9 | 通过 |
| JVM 不重复用例 | 275 项 | 同一套 | 全通过 |
| 正式离线构建 | 371 个 Gradle task | 同一构建 | 通过 |

专项证据：

- 正式生产服务接收通知暂停后，Job 持久化为 `PAUSED(USER_PAUSE)`，Attempt 数仍为 0；
- `SYSTEM_FGS_TIMEOUT` 可恢复为 `READY`，不创建 Attempt；
- API 35 把 `data_sync_fgs_timeout_duration` 临时设为 3,000ms 后，约 4,648ms 观察到生产服务消失，Job 为 `PAUSED(SYSTEM_FGS_TIMEOUT)`；
- 探针脚本只接受 `emulator-N` 且要求 API 35，系统配置和兼容性开关在 `finally` 中恢复；
- Release Manifest 含 1 个正式 `dataSync` 服务、0 个 Debug 探针 receiver，并声明对应权限；
- 源码和 15 个 APK 疑似密钥命中均为 0；真实 API 调用 0，实体设备写入 0。

探针开发中发现：服务活动期间用第二个 SQLCipher 句柄反复查询会使测试探针互相等待。探针已改为服务活动时只观察系统 `dumpsys`，服务退出后再读取数据库。这是测试夹具的查询时序问题，不是生产服务丢失状态；修正后真实系统限时完整通过。
