## 1. 本阶段结果

本阶段新增可编译、可测试的 `:provider:openai-chat` Android library。它把 OpenAI Chat Completions、DeepSeek Chat Completions 和保守的 OpenAI 兼容中转站统一转换为既有 `ProviderAdapter` 领域事件，同时复用 TASK-021 的唯一安全传输出口。

本阶段没有调用真实 API，没有消耗额度，也没有把用户在聊天中提供的测试密钥复制到命令、进程环境、源码、文档、报告或 APK。

## 2. 已完成的能力

### 2.1 三种显式兼容模式

| 模式 | 请求策略 | 适用范围 |
|---|---|---|
| `OPENAI` | `max_completion_tokens`、`json_schema`、流式 usage、OpenAI reasoning effort | OpenAI Chat Completions |
| `DEEPSEEK` | `max_tokens`、`json_object`、JSON 提示约束、流式 usage、DeepSeek reasoning effort | DeepSeek 官方 Chat Completions |
| `RELAY_MINIMAL` | 只发送 `model/messages/stream`，提示合并为一个 user 消息 | 能力未知的普通中转站 |

兼容模式由连接配置的 resolver 明确提供，不按域名或模型名猜测。最小中转模式对温度、top-p、最大输出、seed、推理强度和结构化输出等未知高级字段失败关闭，避免静默发送中转站不支持的参数。

### 2.2 请求编码与安全

- 只通过 `SecureProviderHttpTransport` 访问 `/chat/completions` 和 `/models`；
- Bearer 凭据只使用 Secret Store 引用，适配器不持有原始 API key；
- 请求 JSON 由可清零的 UTF-8 byte buffer 增量编码，覆盖引号、反斜杠、换行、中文和 Unicode 代理对；
- 结构化输出 schema 在联网前验证为 JSON object；
- 请求正文、临时复制和传输 buffer 在各自生命周期结束时清零；
- 模型列表响应上限 2 MiB，生成响应上限 64 MiB；
- 服务端 error message 不进入标准事件或诊断，只使用 HTTP 状态与结构化 code/type 分类。

### 2.3 JSON、SSE 与终态

- 支持非流 Chat Completion JSON；
- 支持 SSE 任意字节分片与中文 UTF-8 跨片；
- 请求流式但中转站返回标准 JSON 时允许解析；
- DeepSeek `reasoning_content` 不写入正文；OpenAI `obfuscation` 被当作未知安全字段忽略；
- usage 可从非流响应或 `[DONE]` 前的最终空 choices chunk 读取；
- 流中出现的 finish reason 先暂存，直到 `[DONE]` 才产生唯一终态；
- 缺少 `[DONE]` 时，即使已有正文或 finish reason，也返回 `STREAM_INTERRUPTED`，不会伪装成功；
- refusal 有 32,768 字符上限，避免异常响应无限占用内存。

### 2.4 模型列表与连接测试

`GET /models` 支持列表去重并使用同一安全鉴权通道。当前 `testConnection` 只证明鉴权和模型列表可访问，明确标记：

- `minimalGenerationVerified=false`；
- `usageObserved=false`。

会产生少量费用的最小生成验证与能力探测属于 TASK-029，本阶段没有用“能列模型”冒充“已验证完整生成”。

## 3. 官方协议核对结论

核对来源：

- [OpenAI Create Chat Completion](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)
- [DeepSeek Lists Models](https://api-docs.deepseek.com/api/list-models/)
- [DeepSeek Error Codes](https://api-docs.deepseek.com/quick_start/error_codes/)

落实到实现的关键差异：OpenAI 当前优先 `max_completion_tokens` 和 `json_schema`；DeepSeek 使用 `max_tokens` 和 `json_object`，且 JSON 模式必须在消息中明确要求 JSON；两者的流式 usage 都可能在 `[DONE]` 前的额外 chunk 中出现；DeepSeek 402 映射余额不足，503 映射服务过载。

## 5. Android 测试夹具问题记录

当前 Android 设备测试环境中，MockWebServer 的 `chunkedBody(..., 2)` 会把 HTTP chunk framing 字节暴露为响应正文，并破坏中文内容。这是测试服务器夹具异常，不是生产 SSE parser 的错误。

处理方式：设备集成测试改为正常完整 response body，并使用 `throttleBody(2, ...)` 让 OkHttp 以两字节节奏接收，从而继续验证跨 UTF-8 边界的碎片读取。生产解析器没有因此放宽，也没有接受带裸 chunk framing 的非法 SSE。
