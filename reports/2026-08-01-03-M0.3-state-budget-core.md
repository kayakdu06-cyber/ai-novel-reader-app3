# 织卷工作汇报 03：M0.3 状态机与预算核心

- 日期：2026-08-01
- 阶段：M0.3
- 状态：完成（纯领域原型）

## 本阶段完成

- 建立生成任务（Job）状态机，明确创建、就绪、运行、暂停、完成、失败、取消等状态的合法转换。
- 建立生成阶段（Stage）状态机，覆盖准备、就绪、运行、重试等待、阻塞、完成、失败和取消。
- 非法状态转换统一抛出包含“当前状态、事件、目标对象”的明确异常，避免后台任务悄悄进入错误状态。
- 建立稳定幂等键：使用带长度前缀的规范化输入和 SHA-256，避免字段拼接歧义；相同阶段重试得到相同键，不同章节、模板版本或提示版本得到不同键。
- 建立请求级、单书级、每日级三层预算模型。
- 请求前一次性检查全部预算；任一层超限即整次拒绝，不留下半预留状态。
- 请求结束后释放预留量并按实际 token/费用结算；无价格数据时仍受 token 硬限制约束。
- 统一常见远程错误码和重试处置；服务商内容拒绝不会被自动重试或伪装成网络错误。

## 已覆盖的关键风险

1. 非法状态跳转会立即失败，不能把失败阶段误记为完成。
2. 相同生成阶段重复调度时可以用稳定键去重，降低重复扣费与重复写章风险。
3. 预算判断使用防溢出加法；极端大数不会绕过硬上限。
4. 三层预算按一个不可拆分的领域操作计算；有任一违规时原数据保持不变。
5. 价格未知不等于无限调用，token 上限始终有效。
6. 内容拒绝、鉴权失败、额度不足、限流和暂时性服务错误拥有不同恢复规则。

## 本阶段边界

- 目前完成的是不依赖 Android 和数据库的确定性核心，便于快速穷举测试。
- 真正的跨线程、跨进程“原子预留”仍需在 Room 数据库事务中落地；当前结果不能替代持久化事务测试。
- 幂等键目前只负责稳定标识，后续还需连接请求意图表、远程请求记录和章节唯一约束。
- 费用换算仍使用调用方提供的微单位估值；模型价格表和供应商用量解析将在 API 适配阶段接入。
