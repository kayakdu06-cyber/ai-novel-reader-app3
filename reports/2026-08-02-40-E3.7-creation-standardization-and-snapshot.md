## 本部分完成了什么

“开始织书”不再只产生内存草稿。现在它会在本地完成以下闭环：

1. 保留用户原始输入；
2. 统一整理文本、自动补齐未选题材并推导临时书名；
3. 冻结篇幅规则、呈现指令、题材基线、来源和当前模型引用；
4. 计算可复现的 SHA-256 内容哈希；
5. 在一个 SQLCipher/Room 事务中写入不可变创建快照和书记录；
6. 成功后显示“已安全保存、尚未发送给模型”，并锁定按钮，防止费用确认页尚未接通时重复建书。

这一步不创建网络请求、不发送故事内容，也不产生模型费用。

## 少操作的标准化规则

- 题材已选择：使用用户选择并记录 `USER`；
- 题材未选择但故事设想命中有序关键词：记录 `KEYWORD_INFERENCE` 和具体规则 ID；
- 没有命中：稳定使用都市默认并记录 `SYSTEM_DEFAULT`；
- 书名由标准化故事设想的首个分句推导，最长 24 个 Unicode code point，来源为 `SYSTEM_INFERRED`；
- 高级区的五组原始文本先原样进入草稿，再由唯一标准化器处理 NFC、换行和空白，避免 UI 与存储各自修剪后无法还原用户输入。

创建快照分别保存 raw/normalized/provenance JSON。相同内容即使使用不同随机 ID、不同创建时间重新建书，也得到相同内容哈希；随机 ID 和时间不会污染内容比较。

## 篇幅与呈现冻结

- 篇幅策略移动到共享领域层，短/中/长最低章数固定为 80/300/301；
- 所有新书必须使用 `lengthPolicySchemaVersion=1`，目标章数不得低于对应下限且不得超过 10,000；
- 呈现快照同时冻结外部指令和题材基线解析后的完整配置；“细写”仍不会暗中提高冲突、伤害、语言或压迫维度；
- 创建阶段的成年人门禁保持 `UNKNOWN/BLOCKED`，不会从自由文本草率推断年龄。后续只有结构化角色年龄确认后才可进入相关场景策略；
- `promptBundleVersion=unassigned-before-generation` 是明确哨兵。TASK-050 尚未建立的 Prompt Bundle 不会被伪装成已冻结版本，真正生成时必须在 Job/Stage 再保存实际版本。

## 数据库 schema v7

`MIGRATION_6_7` 为 `book` 增加：

- `minimum_chapters`；
- `length_policy_schema_version`。

新书在 DAO 和 SQLite 触发器两层检查篇幅规则，原始 SQL 更新也不能把短篇改为 79 章。快照字段、哈希、篇幅或外键任一失败时，快照与书记录整体回滚。

旧 v1~v6 数据不被重写成新规则：迁移后标为兼容 schema0，并按旧目标与当前下限的较小值填写最低章数。迁移夹具中的旧 200 章长篇仍保持 200 章，证明没有借规则升级清库或篡改旧书。
