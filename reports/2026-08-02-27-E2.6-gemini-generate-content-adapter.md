## 2. 为什么仍实现 GenerateContent

Google 当前已把新的 Interactions API 作为推荐方向，但 GenerateContent 仍是官方保留的成熟原生接口，适合织卷当前的无状态文本阶段生成。

首版没有把两套协议混合：

- `:provider:gemini` 只负责 GenerateContent；
- 后续需要 Interactions 时新增协议 ID 和独立适配器；
- 本地数据库继续保存全部小说状态，不依赖服务端会话；
- 模块边界允许以后升级，而不会暗中改变已保存连接的请求语义。

## 3. 请求与隐私边界

- API key 只从 Secret Store 注入 `x-goog-api-key`；
- URL 中不允许 `key`、`api_key` 或其他敏感 query；
- 流式 query 只有公开的 `alt=sse`，模型列表只有公开的 `pageSize=1000`；
- 模型 ID 先做单路径段校验，再拼接 RPC 后缀，拒绝斜杠、反斜杠、冒号和控制字符；
- 每次生成显式发送 `store:false`；
- 应用规则、阶段契约和小说资料进入 `systemInstruction`，本次要求进入 `contents[user]`；
- 没有单独用户要求时，以必有的阶段契约构造 user turn，避免空 contents；
- 请求正文继续使用可清零 UTF-8 字节缓冲，传输结束后清理；
- 传输层只新增允许读取非敏感 `x-goog-request-id`，没有开放任意响应头。

`store:false` 是请求侧隐私约束，不等于服务商完全不处理数据。后续连接向导仍需明确提示：选择外部 API 时，所选提示内容会发送给该服务。

## 4. 当前字段与模型能力

结构化输出使用当前官方字段：

`generationConfig.responseFormat.text = { mimeType: "application/json", schema: ... }`

新实现不再默认使用已标为旧方式的 `responseSchema`。同时采用保守能力策略：

- 协议基线：streaming、system instruction、stream usage、maxOutputTokens；
- 模型相关且默认未知：结构化输出、temperature、topP、seed、thinking level；
- 只有能力注册或探测明确支持时，才发送这些模型相关字段；
- reasoning effort 映射为 `thinkingConfig.thinkingLevel`，同时显式 `includeThoughts:false`；
- 即使服务端仍返回 thought part，适配器也不会把它写进小说正文；
- 不根据模型名猜功能。

## 5. 流式、终态与安全反馈

Gemini SSE 没有独立的 `[DONE]` 或 message_stop。适配器把最后看到的 finish reason 暂存到 EOF，允许服务端在 finish 后再发送 usage-only chunk；只有 EOF 时已有 finish reason 才提交唯一终态。

| 服务端证据 | 织卷结果 |
|---|---|
| `STOP` | `Completed(STOP)` |
| `STOP` + functionCall | `Completed(TOOL_CALL)` |
| `MAX_TOKENS` | `Completed(LENGTH)` |
| `SAFETY` / `IMAGE_SAFETY` / `SPII` | `Refused(SAFETY)` |
| `RECITATION` / `BLOCKLIST` / `PROHIBITED_CONTENT` / `ESCALATION` | `Refused(POLICY)` |
| `LANGUAGE` 等不支持结果 | `Refused(UNSUPPORTED_REQUEST)` |
| 畸形函数调用、缺失 thought signature、畸形响应 | `Failed(PROTOCOL_MISMATCH)` |
| 未知 finish reason | `Failed(UNKNOWN_RESULT)` |
| EOF 前没有 finish reason | `Failed(STREAM_INTERRUPTED)` |

`promptFeedback.blockReason` 与候选 `finishReason` 分开处理。服务商返回的 error message 和 finishMessage 不直接进入事件、日志或测试失败输出。

## 6. usage 与模型列表

usage 映射：

- `promptTokenCount` → input；
- `candidatesTokenCount` → output；
- `cachedContentTokenCount` → cached input；
- `thoughtsTokenCount` → reasoning；
- `totalTokenCount` → total。

负数或明显不可能的总量关系会被当作协议错误。模型列表只保留声明支持 `generateContent` 的条目，并读取 `inputTokenLimit` 与 `outputTokenLimit` 作为界面提示；embedding-only 模型不会出现在小说生成模型列表中。
