# 织卷工作汇报 15：M1.4 模板复制与来源分类 Schema

> 日期：2026-08-01  
> 对应：TASK-013  
> 结论：Template/Revision/UseSnapshot/Tag 正式 schema v4、v3→v4 迁移和模板新书事务完成

## 1. 本阶段目标

把“上一本书写得不满意，快速沿用模板重新生一本”变成可靠的数据能力，同时避免几个高风险误区：

- 模板不是旧书复制件；
- 修改模板不能改变已经开始生成的书；
- 来源、来源书和派生父链不能被用户展示编辑误改；
- 同一旧书反复点击不能制造大量相同模板；
- 内容相同但来源不同的模板不能被自动合并；
- 删除来源书不能让模板报废；
- 模板不能夹带旧章节、请求记录、费用记录或密钥。

## 2. 新增正式表

### `template`

保存用户可识别的稳定模板对象：名称、说明、来源类型、系统预设键、当前修订、收藏、置顶、归档和最近使用时间。

来源类型和系统预设键是系统事实，由数据库触发器禁止修改；展示信息可以独立修改，不会无意义地创建内容修订。

### `template_revision`

不可变内容修订，保存修订号、父修订、来源根、来源链快照、来源书 ID/书名快照、内容哈希、提取幂等键和版本信息。

模板内容没有使用一个任意大 JSON，而是拆成明确允许的类别：

- 故事种子；
- 题材和机制；
- 稳定人物；
- 世界规则；
- 写法；
- 结构与篇幅；
- 呈现维度；
- 内容规则；
- 生成策略；
- 模型能力角色偏好；
- 受限扩展区。

表中不存在章节正文、章节版本、摘要、伏笔运行状态、请求、用量、密钥、设备路径或阅读进度字段。

### `template_use_snapshot`

与新书一对一的不可变使用快照，冻结所用模板修订、`ALL_SETTINGS/STYLE_ONLY` 模式、本次覆盖项、最终允许字段、能力解析、内容哈希和 schema 版本。

模板后续产生新修订时，旧书继续引用原来的使用快照，内容哈希不变。

### `template_tag`

保存题材、故事机制、氛围、节奏、篇幅、呈现和用户自定义分类，包含规范值、展示名、来源、置信度、确认状态和推导修订。

低置信度且未确认的标签不能成为主分类；同一模板同一维度最多一个主标签；推导修订必须属于同一模板；标签来源身份不能被展示编辑改写。

## 3. 来源链和防循环

- 普通模板编辑只能从该模板当前修订创建下一版；
- 派生模板首修订可以指向另一个模板的既有修订；
- 来源根必须与父修订一致；
- 修订和父引用不可修改，新修订只能指向已经存在的父修订，因此不能事后把祖先改成后代；
- 自指父修订在 DAO 和数据库层均被拒绝；
- 10 层实际来源链已在 Android 模拟器中逐层写入和回读，根修订保持一致。

## 4. 书源模板的幂等和删除语义

书源首修订要求稳定 `derivationKey`，由“来源书 + 提取规则版本 + 规范化内容”形成。重复使用同一 key 时返回已有修订，不创建新模板。

若同一个 key 对应的来源书或内容哈希不一致，则按冲突失败，不静默复用错误来源。

来源书 ID 有意作为可失联的历史标识，而不是会阻止删书的强外键：

- 首次提取时必须核对来源书确实存在，且标题快照与当时书名一致；
- 来源书后来删除后，修订继续保留来源 ID 和书名快照；
- 模板仍可用于创建新书，界面后续可以显示“来源书已删除”。

## 5. 从模板创建新书

`createBookFromTemplate` 在同一事务中：

1. 验证模板修订归属；
2. 验证新书不是“章节分支”关系；
3. 验证 BookCreationSnapshot 和 TemplateUseSnapshot 冻结同一最终内容哈希；
4. 校验模板 payload 不含禁止字段；
5. 创建新的 BookCreationSnapshot；
6. 创建空白新书；
7. 创建一对一使用快照；
8. 更新模板最近使用时间。

事务没有接收或写入 Chapter、ChapterVersion、ChapterSummary、GenerationJob、RequestAttempt 或 UsageLedger，因此不会结构性复制旧正文和运行记录。设备测试还实际给来源书写入了旧章节正文，再从模板创建新书，确认新书章节、摘要和生成任务数量均为 0，来源书保持不变。

## 6. 内容排除防线

模板 payload 在 DAO 和数据库触发器两层检查：

- 拒绝常见 `api_key`、`Authorization`、access token 和 Bearer 凭据；
- 拒绝章节正文、流草稿、请求 attempt 和用量 ledger 等结构键；
- 限制单段和总 payload 体积，避免把整本旧书塞进扩展区；
- 使用白名单分段代替“复制旧书所有字段后再删几个字段”。

这能防止结构性误复制，但不冒充已经完成完整提取器。AI 提取、规范化哈希、正文语义清洗、`STYLE_ONLY` 去人物地点剧情仍分别由 TASK-071/072/076 实现并继续测试。

## 7. 相同内容、不同来源

`contentHash` 仅用于重复提示，不设全局唯一约束。两个来源不同但内容相同的模板可以同时存在，来源链不会被自动合并。

只有书源提取的 `derivationKey` 唯一，用于关闭“同一本旧书、同一提取版本、同一结果被重复保存”的问题。

## 8. 显式迁移

- 数据库版本从 v3 升到 v4；
- `MIGRATION_3_4` 明确创建四张表、复合外键、唯一索引和保护触发器；
- MigrationTestHelper 从导出的 v3 schema 建库，写入一本旧书后迁移；
- 迁移后旧书保持不变，四张新表和不可变使用快照触发器存在；
- 正式 schema 已导出到 `core/database/schemas/app.zhijuan.core.database.ZhijuanDatabase/4.json`；
- 没有使用破坏性迁移或清库回退。

## 9. 测试结果

1. 修订不可变，展示信息可改而来源不可篡改，旧书快照不受新版模板影响；
2. 10 层派生链根来源正确，自指父链失败；
3. 书源提取幂等，来源书删除后模板仍可用；
4. 模板新书不复制旧章节、摘要和运行任务，使用快照不可变；
5. 禁止运行/凭据字段会整体回滚，相同哈希不同来源保持独立；
6. 标签来源、跨模板修订、主标签和低置信度规则正确；
