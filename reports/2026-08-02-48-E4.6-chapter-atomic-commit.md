## 1. 本阶段交付结果

已经建立正式章节的唯一提交边界。结构化输出通过 TASK-044 校验后，不再由调用方凭 Stage ID 直接写正文，而是先取得与最新成功 Attempt、加密草稿修订/hash、校验时间和当前租约绑定的内部提交许可，再由 `ChapterGenerationCommitRepository` 在一个 SQLCipher/Room 事务中完成：

- 插入不可变 `ChapterVersion`；
- 插入章节摘要、人物事件、事实、时间线和新伏笔记录；
- 若替换旧章节版本，同事务执行派生数据 stale 级联；
- 用 CAS 切换章节当前版本并更新书籍完成章数/生成摘要；
- 把既有 UsageLedger 单向结算为 FINAL；
- 把当前 Stage 从 `COMMITTING` 提交为 `SUCCEEDED`；
- 激活创建 Job 时已经冻结的下一 Stage，或在确认所有 Stage 成功后完成 Job。

任意一步失败都会回滚正文、派生数据、用量、Stage、Job 和书籍进度，不会留下可读半章、缺记忆章节或错误计费状态。

## 2. 严重风险关闭情况

| 风险 | 处理结果 |
|---|---|
| 崩溃恢复重复插入正文或重复增加完成章数 | 成功 Stage 保存无正文提交证据；完全相同重放只回读既有版本 |
| 两个执行器同时提交同一输出 | 章节 currentVersion CAS、Stage 租约 CAS 与数据库事务共同去重 |
| 生成期间用户已经编辑章节 | 比较 `expectedCurrentVersionId`；迟到 AI 不得覆盖用户版本 |
| 正文成功但摘要/记忆/Usage/Stage 失败 | 所有正式写入位于同一事务，故障注入证明整笔回滚 |
| 旧校验许可或被替换草稿继续提交 | 首次提交前复核最新 Attempt、artifact 类型、修订、SHA-256 和非过期租约 |
| 下一 Stage 跳错或 Job 假完成 | 下一 Stage 必须同 Job、非自身、预冻结 PENDING、时间单调并通过状态机；无下一 Stage 时查询全部 Stage |
| 代码升级破坏幂等摘要 | 派生记录按 ID 排序后逐字段、带长度前缀计算 SHA-256，不依赖 data-class `toString()` |
| 提交证据泄露正文 | `outputReferenceJson` 只保存版本、ID/hash 和下一 Stage ID；对象默认字符串脱敏 |
