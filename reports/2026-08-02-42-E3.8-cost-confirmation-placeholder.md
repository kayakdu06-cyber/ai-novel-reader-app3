## 1. 本阶段目标

在 TASK-036 已经原子保存本地书记录和不可变创建快照的基础上，建立一个可靠的“开始前确认”交接页。该页必须从已提交快照读取章节规模和模型，不重新相信创建表单；价格未知时诚实说明，不伪造 0 元；在真实预算与生成执行器尚未接入时绝不调用模型。

本阶段同时继承已经更正的篇幅硬规则：短篇最低/初始目标 80 章，中篇最低/初始目标 300 章，长篇由用户填写 301–10,000 章。对应更正的完整记录见 `reports/2026-08-02-41-length-scale-correction.md`。

## 2. 已完成内容

### 2.1 数据回读与失败关闭

- `BookCreationRepository.create` 在事务提交后立即回读书与快照；无法回读时不返回假成功。
- 新增 `StoredBookCreationSummary`，只提供确认页必要的书 ID、快照 ID、书名、篇幅、章数、模型偏好 JSON 和内容哈希。
- 新增按 `bookId` 的只读回读；空 ID、缺失书/快照、空目标章数或非法 SHA-256 均返回不可用。
- 未增加数据库表，也没有复制一份容易漂移的确认数据。

### 2.2 App 交接边界

- 创建成功后导航只保存 `pendingBookId`；页面进入和进程状态恢复时重新读取 SQLCipher 中的冻结快照。
- 模型 ID 只从快照的 `modelPreferenceJson` 解析；缺失、空白或畸形 JSON 失败关闭，不从当前连接猜测。
- 确认动作只产生 `bookId + snapshotId + snapshotContentHash + priceState`，随后再次核对冻结引用。
- 返回创建页后已创建书仍保留，创建主按钮继续锁定，避免重复写入第二本相同书。
- 快照不可读时显示可恢复错误页，明确说明没有开始生成、没有调用模型，并提供唯一返回动作。

### 2.3 开始前确认页面

- 展示冻结书名、短/中/长篇、目标/最低章数和模型 ID。
- 当前固定为 `PRICE_CATALOG_UNAVAILABLE`，页面显示“费用暂时无法可靠估算”。
- 不显示独立的“0 元”，不构造金额，不根据模型名猜价格，也不虚构 token 范围。
- 确认一次后按钮锁定，结果明确写“生成尚未开始”。
- 加载使用进度反馈；页面采用 safe insets、单一滚动区、600dp 最大宽度、48dp 返回目标和 56dp 主动作。
- 真实竖屏截图：`D:\gptuser\cache\temp\zhijuan-task037-cost-confirmation.png`。

UI/UX Pro Max 规范影响了本页的适配与验收重点：保持低按钮密度、加载状态可见、触摸目标明确，并补做 375dp、200% 字体、横屏和深色检查。配色仍服从织卷既有暖纸/深墨基线，没有采用通用 AI 紫色或渐变建议。
