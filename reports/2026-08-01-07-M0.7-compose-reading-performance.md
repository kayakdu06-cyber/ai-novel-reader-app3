# 织卷工作汇报 07：M0.7 长章节与万章目录性能实验

> 日期：2026-08-01  
> 状态：模拟器验证通过，正式设备性能验收待后续完成

## 1. 本阶段目标

验证两个可能直接拖垮阅读体验的高风险场景：

1. 单章正文达到 200,000 个中文字符时，Compose 是否会一次布局全部正文并造成明显内存或卡顿风险。
2. 小说目录达到 10,000 章时，是否还能快速进入、直接跳到末章并正确响应点击。

本阶段只制作 Debug 性能夹具，不启动正式界面设计、视觉出图或产品原型。

## 2. 完成内容

- 新增 Debug 专用的长章节阅读夹具：200,000 字拆成 2,000 个稳定段落，以惰性列表呈现。
- 新增 Debug 专用的 10,000 章目录夹具：使用按数量生成的惰性行、稳定 key 和稳定 content type。
- 新增 3 项 Android 设备测试：
  - 20 万字首屏与末段定位；
  - 1 万章首屏、末章定位和点击；
  - 320×480dp 竖屏与 640×360dp 横屏挂载。
- 当前章除了强调色外还使用粗体和标题语义；目录行最小高度 56dp。
- 测试夹具与后台恢复探针都只存在于 Debug/AndroidTest source set；Release APK 未包含这些类、组件或调试权限。

## 3. 实测结果

测试环境：Android 15 / API 35 x86_64 模拟器，Debug 构建，Compose UI 仪器测试。

| 场景 | 数据规模 | 首次挂载 | 远端直接定位 | 实际组合项 | 结果 |
|---|---:|---:|---:|---:|---|
| 长章节阅读 | 200,000 字 / 2,000 段 | 212.11 ms | 95.84 ms | 首尾均 4 段 | 通过 |
| 超长目录 | 10,000 章 | 400.28 ms | 146.90 ms | 首尾均 13 行 | 通过，末章可点击 |

长章节挂载前后观测到 PSS 增量约 7,745 KB。这个数字包含 Compose、测试框架与进程页共享等影响，只适合作为本工程后续回归的同环境参考。

测试统计：

- M0.7 Android 测试：3 项，0 失败、0 错误、0 跳过。
- 当前项目 Android 35 模拟器测试累计：8 项，0 失败、0 错误、0 跳过。
- 当前 JVM 单元测试：62 项，全部通过。

## 4. 实验中发现并修正的问题

最初使用阻塞协程驱动 `scrollToItem`，与新版 Compose 测试规则的测量/布局阶段发生竞争并导致测试进程崩溃。改为在 Compose 空闲边界调用同步的 `requestScrollToItem` 后，连续执行稳定通过。

这也形成正式实现约束：跨越数千章的跳转必须直接定位，不应播放逐行滚动动画。

## 5. 已确定的实现路径

- 正文按段落窗口化呈现，禁止用一个巨型 `Text` 布局整章。
- 阅读位置保存“章节 ID + 段落锚点 + 段内偏移”，避免字体或屏幕变化后像素坐标失效。
- 目录保持惰性加载、稳定 key 和稳定类型；正式数据库接入后按需查询，不把全部章节实体复制进 UI 状态。
- 段落切分和索引准备在非主线程完成，并缓存不可变结果；只有正文版本变化时重建。
- 远距离跳章直接定位目标；普通短距离移动才考虑动画。
- 当前项状态不只依赖颜色；正式实现补全 `selected` 语义、TalkBack 文案和大字体布局。

UI/UX 规则对本阶段的实际影响是：采用虚拟化列表、稳定项身份、至少 48dp 的触摸目标、非颜色唯一状态和横竖屏夹具。未建立正式设计系统，因为用户此前明确本轮不启动界面设计。

## 7. 尚未完成与风险边界

本阶段证明了“窗口化正文 + 惰性目录”方向可行，但不能冒充发布级性能结论。仍需：

- Macrobenchmark 与帧耗时/jank 百分位；
- 物理中档 Android 设备；
- 真实中文小说混合段落、长对话和标点；
- 系统字体放大、TalkBack、深色模式和更多横屏尺寸；
- 正式分页算法及字体变化后的阅读位置恢复；
- 长列表搜索、分组和数据库分页接入。

## 8. 阶段结论

TASK-007 在 Android 35 模拟器上通过，可以把正文阅读器确定为“段落级惰性窗口”，把目录确定为“稳定惰性行 + 直接跳转”。这些选择可以进入 M1/M2 实现；物理设备与 Macrobenchmark 继续作为发布前门禁保留。
