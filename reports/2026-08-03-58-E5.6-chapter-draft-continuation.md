## 1. 本阶段结果

TASK-055 已完成章节正文流和有限截断续接的底层闭环。系统现在能把 Provider 的正文 JSON 流安全地解码为纯正文，在单次输出达到上限时保留全部已生成内容，并通过精确尾部锚点自动续接；正常路径不要求用户手工复制、拼接或逐次确认。

本阶段没有接入真实 API，也没有操作实体设备。所有生成效果测试均使用本地假 Provider 和项目专属 API 35/API 30 模拟器。

## 2. 已交付能力

### 2.1 正文输出契约

- 新增 `chapter-draft.v1`：Provider 只允许返回必填字符串字段 `body`，禁止标题、状态、解释、第二候选和额外字段。
- 增量解码器支持任意流分片、JSON 转义和 Unicode 代理项；只有完成解码的 `body` 内容能够进入受保护草稿。
- JSON 外壳、Markdown 围栏和解释性文字不会写入小说正文。
- `STOP` 只有在 JSON 完整、正文有效且续接锚点满足时才进入后续校验，不直接冒充正式章节。

### 2.2 截断续接

- `LENGTH` 与输出 hash、成功响应证据、`OUTPUT_TRUNCATED` 和 Stage `VALIDATING` 同事务落库。
- 每次续接都新建 Attempt、独立 Usage 和独立加密 artifact；新草稿先预置累计正文，父草稿不会被原地覆盖。
- 续接提示绑定父输出、保存尾窗、96 个 Unicode 码点精确锚点、续接序号和原 Stage 输入。
- 模型必须在新正文开头精确复现锚点；本地校验后只剥离一次，禁止模糊相似拼接。
- 最多自动续接 3 次。第 4 次截断、Stage attempt 用尽、累计正文达到 4 MiB、空/过短片段、结构错误或锚点错误都会保存现场并进入 `NEEDS_ACTION`。

### 2.3 崩溃与费用审计

- 修复了“响应终态已经到达、续接结算尚未完成”这一崩溃窗口。
- 恢复器只验证本地加密 artifact、修订、hash、UTF-8、父链和持久分类，然后完成原结算；不会访问 Provider，也不会创建第二次请求。
- 每个 Attempt 独立结算 Usage。若崩溃导致仅存在内存的 usage 丢失，则如实记录为 `UNKNOWN`，不会为了补齐账目而重发。
- 重启不会清零自动续接次数，也不会绕过费用/token、attempt 或大小硬限制。

关键 Android 场景已经覆盖：

1. `LENGTH` 分类先持久化，租约过期后可以本地恢复结算，重复恢复保持幂等。
2. 首次截断后新 Attempt 预置旧正文，正确锚点只剥离一次，每个 Attempt 独立结算用量。
3. 未绑定当前父输出的续接提示在联网前拒绝，Provider 调用数为 0。
4. 错误锚点被标记为 `FORMAT_INVALID`，新内容不追加，原累计正文保持不变。
5. 初次请求加 3 次自动续接后，第 4 次截断停止在 `NEEDS_ACTION`，不会建立第 5 次请求。
