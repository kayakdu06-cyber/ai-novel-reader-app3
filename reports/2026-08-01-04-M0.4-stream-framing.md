# 织卷工作汇报 04：M0.4 流式数据分帧

- 日期：2026-08-01
- 阶段：M0.4
- 状态：完成（协议分帧核心）

## 本阶段完成

- 实现增量 SSE 分帧器，可把网络连续收到的任意 `ByteArray` 数据块恢复为完整事件。
- 实现增量 NDJSON 分帧器，可逐行交付 JSON 记录，并在流结束时保留最后一条不带换行的完整记录。
- 先按字节寻找行边界，确认整行后再严格解码 UTF-8，避免中文字符被拆在两个网络包之间时出现乱码或丢字。
- 同时支持 LF、CRLF 和单独 CR 三种行结束方式。
- SSE 支持默认事件、多行 `data` 合并、`event`、持久化 `id`、持久化合法 `retry`、注释心跳和未知字段忽略。
- SSE 严格遵循“空行才提交事件”；网络中断时未闭合事件会被丢弃，不把半段正文误当成完整增量。
- NDJSON 忽略空白行，保留原始 JSON 文本，具体 JSON 结构留给各服务商适配器解析。
- 在公共协议模块建立服务商无关的标准流事件：开始、正文增量、用量更新、完成、拒绝、失败和心跳。

## 安全与稳定性边界

- 每一行默认最大 1 MiB，超过即明确失败，防止异常服务端或错误响应造成内存无限增长。
- UTF-8 使用严格模式，非法字节会抛出 `MalformedStreamException`，不会静默替换成乱码后写入小说。
- 解析器完成后不可再次喂数据或重复完成，避免复用旧状态污染下一次请求。
- 支持流开头 UTF-8 BOM，但不会把 BOM 误当成字段名或 JSON 内容。

## 覆盖的异常场景

1. 在每一个可能的字节位置切开同一段中文 SSE 数据，结果均一致。
2. 在每一个可能的字节位置切开包含两条记录的中文 NDJSON 数据，结果均一致。
3. 一个网络块内同时包含多个 SSE 事件。
4. SSE 多行正文、事件名、事件编号和重连时间组合。
5. 注释心跳与未知字段共存。
6. CRLF 跨网络块、单独 CR 和普通 LF。
7. NDJSON 最后一行没有换行符。
8. 非法 UTF-8、超长行、完成后错误复用。

## 本阶段边界

- 当前层只解决“字节流怎样可靠切成完整消息”，尚未解析 OpenAI、Anthropic、Gemini、Ollama 等不同 JSON 字段。
- 服务商 JSON 映射、结束原因、用量字段、错误体和 `[DONE]` 规则将在各适配器实现时分别用官方夹具验证。
- 本阶段不发真实 API 请求，因此没有产生调用费用，也没有写入任何密钥。
