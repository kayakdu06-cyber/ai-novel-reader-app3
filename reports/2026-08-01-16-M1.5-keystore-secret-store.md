# 织卷工作汇报 16：M1.5 Android Keystore 密钥存储

> 日期：2026-08-01  
> 对应：TASK-014  
> 结论：API 密钥与敏感请求头的独立加密、锁定、轮换、撤销和失败关闭完成

## 1. 本阶段目标

让连接配置只保存随机 `secretRefId`，不直接保存或传播 API 密钥本身，并保证：

- 每条 secret 独立加密，不复用数据库口令密钥；
- App 锁定后，已经取出的明文也立即失效；
- 密钥轮换不需要修改连接引用；
- 删除连接时能够立即让旧 secret 不可用；
- Keystore 失效、记录损坏或元数据被改动时失败关闭；
- 普通业务接口不能一次列出全部明文密钥。

## 2. 存储结构

每条 secret 使用：

- 一个随机 UUID `secretRefId`；
- 一个独立 Android Keystore AES-256-GCM 别名；
- 一个单调递增的 `keyVersion`；
- 一个独立原子记录文件；
- 一个只含用途、尾四位、状态和时间的 descriptor；
- ACTIVE 状态下的一份认证密文，或 REVOKED 状态下的无密文墓碑。

记录文件位于 Android `noBackupFilesDir/security/api-secrets`。业务对象以后只保存随机引用，不能从数据库字段直接得到可用密钥。

## 3. 密文与元数据绑定

AES-GCM 的 AAD 覆盖：

- secretRefId；
- API_KEY / SENSITIVE_HEADER 用途；
- 尾四位显示；
- ACTIVE 状态；
- keyVersion；
- createdAt。

攻击者或损坏文件即使只修改用途、尾四位、状态或版本号，解密认证也会失败。`updatedAt/lastUsedAt` 不进入 AAD，因此正常使用时间更新不需要重新加密 secret。

## 4. 明文生命周期

- `createAndClear` 和 `rotateAndClear` 明确消费调用方传入的 ByteArray；成功、校验失败或写入失败都会在 finally 中清零；
- `read` 不返回 String，也不暴露永久 ByteArray 属性，只返回 `SecretLease`；
- 调用方只能在 `withBytes` 作用域使用值；lease 关闭后缓冲区清零；
- Store 锁定、该 secret 轮换或撤销时，会主动关闭相关现存 lease；
- 设备测试保留了一个借出的缓冲区引用，执行锁定后验证其每个字节均已变为 0。

这不能阻止恶意调用方在回调中自行复制明文，但避免普通业务层长期持有或无意缓存同一底层明文。

## 5. 原子轮换

轮换保留原 `secretRefId`，只把 keyVersion 从 N 升为 N+1：

1. 用新 Keystore 别名加密替代 secret；
2. 原子替换记录文件；
3. 关闭该引用的旧 lease；
4. 删除旧版本 Keystore 别名。

连接表无需在“密钥文件更新”和“引用字段更新”之间跨存储协调，避免半完成状态。若在替换前失败，旧记录仍可用；若替换后、旧 key 删除前中断，新记录已经可用，旧 key 只会成为无旧密文的孤立条目，不会让连接指向错误引用。

## 6. 撤销与删除

撤销顺序是：

1. 原子把记录改成 `REVOKED`；
2. 删除密文和尾四位；
3. 关闭现有 lease；
4. 删除当前 Keystore 别名。

因此即使进程在最后一步前中断，Store 也会先看到无密文墓碑并拒绝读取，不会因为 Keystore key 尚存而恢复为 ACTIVE。重复撤销幂等返回既有墓碑。

## 7. 锁定和用途隔离

- Store 可进入内存锁定状态；锁定时创建、读取、轮换、撤销、单条 descriptor 和 descriptor 列表全部拒绝；
- 锁定会同步清零所有未关闭 lease；
- 只有 `unlockAfterAuthentication` 能恢复访问，该方法后续必须只接在设备凭据/生物识别成功路径；
- API_KEY 引用不能作为 SENSITIVE_HEADER 使用，反向也不允许；用途不匹配发生在解密和 lastUsed 更新前。

## 8. 失败关闭

以下情况不会自动生成新 key、空 secret 或覆盖旧记录：

- secretRefId 不存在或格式错误；
- record magic、版本、长度、状态或尾部数据损坏；
- 记录身份与文件名不一致；
- Keystore key 缺失或失效；
- AES-GCM 标签失败；
- AAD 元数据被篡改；
- 用途不匹配；
- App 已锁定。

设备测试删除实际 Keystore 别名后读取，确认原记录字节完全不变，且 Store 没有静默生成替代 key。

## 9. 列表与日志边界

公开列表只返回 `SecretDescriptor`：随机引用、用途、尾四位、状态、keyVersion 和时间。不提供 `listSecrets` 或批量明文接口。

实现不记录 secret、Authorization、密文、完整 header 值或解密失败内容。文件扫描验证密文记录中找不到测试明文。

## 10. 测试结果

新增 JVM 测试 4 项：

1. ACTIVE record codec 往返；
2. REVOKED 墓碑无密文；
3. ACTIVE 无 envelope 拒绝；
4. 尾随字节和非法随机引用拒绝。

新增 Android 专项测试 6 项：

1. 创建消费并清零输入，仅可通过可关闭 lease 读取，文件无明文；
2. 锁定清零借出缓冲并阻止所有 Store 操作，解锁后可恢复；
3. 轮换保持引用、升级 keyVersion、删除旧别名并只读到新 secret；
4. 撤销写无密文墓碑、关闭 lease、删除 key 且重复调用幂等；
5. 用途错误和 Keystore key 缺失均失败关闭、记录不变；
6. descriptor 不含完整 secret，修改 AAD 元数据后认证失败。

全项目最终回归：

- JVM 单元测试：99 个不重复测试，0 失败、0 错误、0 跳过；
- Android 35 x86_64 模拟器测试：49 个，0 失败、0 错误、0 跳过；
- 离线构建和 Debug APK 组装通过；
- 源码与 7 个 APK 的 secret/canary 扫描 0 命中。
