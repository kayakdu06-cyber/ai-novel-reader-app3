# 织卷工作报告：E2.7 模型能力登记表与探测证据

> 日期：2026-08-02  
> 对应任务：TASK-027  
> 状态：完成

## 1. 本阶段结果

织卷已经具备可持久化、会过期、可解释且失败保守的模型能力登记机制。它不再根据模型名猜测高级参数，也不会把上一个中转站或旧适配器版本的能力直接带到新连接。

本阶段没有进行真实 API 调用，没有读取或使用聊天中提供的密钥；所有网络相关适配器回归仍使用本地夹具。已连接的小米实体机没有安装、写入或变更，设备测试只在两个指定模拟器运行。

## 2. 关键实现

### 2.1 多来源能力解析

每个能力证据按以下维度隔离：

`connectionId + endpointFingerprint + protocolId + modelId + capabilitySource`

解析顺序固定为：

1. 保守未知默认；
2. 随 App 发布的内置协议基线；
3. 官方模型元数据；
4. 仍在有效期内的最近成功探测；
5. 已由用户确认风险的覆盖值。

合并按字段进行。高优先级来源中的 `UNKNOWN` 不会擦除低优先级已经确认的值；只有 `SUPPORTED` 才能授权适配器发送对应可选字段。

### 2.2 地址、版本和时间失效

- 规范化 base URL 与协议生成 SHA-256 端点指纹；地址改变后旧记录不命中；
- 指纹默认字符串不输出原值，登记表不保存原始 URL 或密钥；
- 自动证据必须有过期时间，到达过期时刻立即失效；
- 探测证据有效期限定在 1 小时至 30 天，默认 7 天；
- 适配器版本不一致、证据时间位于未来、协议或模型不一致时均不采用。

### 2.3 探测证据约束

探测结果明确分为：

- `SUPPORTED`：测试明确成功；
- `EXPLICITLY_UNSUPPORTED`：服务端明确拒绝被测试字段；
- `INCONCLUSIVE`：超时、网络、鉴权、余额或其他不能证明能力的结果。

只有前两类会形成肯定结论；不确定结果始终保持 `UNKNOWN`，避免一次偶然错误长期关闭模型能力。

### 2.4 用户覆盖与一键恢复

- 用户覆盖必须带明确的本地风险确认时间；
- 用户覆盖与自动探测分开保存；
- “恢复自动”只删除该模型的用户覆盖记录；
- 删除后会立即显露仍有效的探测、官方或内置值，不要求重新填写连接。

### 2.5 加密持久化与并发刷新

- 正式 Room/SQLCipher schema 从 v4 升至 v5；
- 新增 `provider_capability` 表及 `MIGRATION_4_5`；
- 同一来源刷新在事务内比较 `verifiedAt`，迟到的旧结果不能覆盖新结果；
- 损坏枚举或不合法记录在映射层被丢弃，解析回退到保守状态；
- 协程取消会继续向上传递，不会被误吞成一次“保守成功”。

### 2.6 模块边界

- `:provider:common`：纯 Kotlin 的登记、过期、探测证据和覆盖规则；
- `:core:database`：原始实体、DAO、schema v5 和迁移，不反向依赖服务商领域；
- `:provider:capability-storage`：Room 与能力领域之间的唯一映射桥；
- 四个首发提供方模块：各自提供 registry-backed resolver，能力查询和生成请求使用同一模型级快照。

## 3. 关闭的严重疏漏

| 风险 | 本阶段处理 |
|---|---|
| 只按模型名猜测能力 | 三态登记，未知字段不发送 |
| 换中转站后沿用旧能力 | 端点指纹绑定并自动失配 |
| 撤销覆盖时自动探测值一起丢失 | 各来源独立记录 |
| 旧探测永久生效 | 强制过期与适配器版本校验 |
| 网络失败被误判为模型不支持 | `INCONCLUSIVE` 保持未知 |
| 并发旧刷新覆盖新证据 | `verifiedAt` 单调事务写入 |
| 数据损坏后乐观发送高级字段 | 丢弃坏记录并保守回退 |
| 数据库层反向依赖具体提供方 | 独立 capability-storage 桥接模块 |
| 取消被吞掉、任务继续运行 | `CancellationException` 明确透传 |
