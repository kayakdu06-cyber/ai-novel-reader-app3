# 织卷工作汇报 57：E5.5 章前上下文预算组装

> 日期：2026-08-03  
> 对应任务：TASK-054

## 1. 本次完成了什么

织卷现在可以在每一章正式计划前，自动从当前故事圣经、总纲/窗口、上一章和运行记忆中组装一份不可变上下文。系统先完整保留不能丢的事实，再按稳定优先级整项选择可选记忆。模型容量未知或必需事实装不下时，会在任何网络请求之前停止，而不是删除硬事实或发送一份残缺上下文。

本次仍只完成底层链路，没有把确认页接到真实 Provider，也没有生成小说正文。

## 2. 核心产品结果

- 冻结策略版本 `zhijuan.chapter-context-policy.v1` 与清单版本 `chapter-context-manifest.v1`。
- 必需事实包括应用硬规则、阶段任务、写作/呈现规则、人物成年与虚构身份、世界规则、禁改事实、目标卷章计划，以及第二章起的上一章摘要。
- 已存在的当前状态、到期伏笔和本次用户补充同样按必需事实处理，不被普通裁剪。
- 主题、旧章节摘要、历史事件/时间线、未到期伏笔和远期计划属于可选材料，只能整项保留或整项省略。
- 预算以规范 Provider payload 的 UTF-8 字节数作为保守 token 上界，另留 128 token 封套、10% 上下文安全余量和输出额度。
- 未确认的未知容量默认阻断；用户明确确认时只采用 8192 的保守回退值，不从模型名称猜测。
- 成功结果写入不可变 `ContextSnapshot`；相同已成功 Stage 可精确重放，不重复写入。
- Provider 打开前再次复核 Prompt Bundle、当前 Bible/Outline、目标窗口/卷章、上一章当前版本和推进证据。来源变化时拒绝旧快照。
- 本地组装不创建 RequestAttempt 或 Usage，不产生远程 token 和费用。
