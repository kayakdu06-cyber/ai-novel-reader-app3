# 织卷工作汇报 22：E2.1 统一模型适配器契约

> 日期：2026-08-01  
> 对应：TASK-020  
> 结论：供应商无关的连接、能力、请求、事件、用量和取消契约已落地；未知能力失败保守；默认字符串不会输出正文、schema、端点或远端标识

## 1. 本阶段完成了什么

新增并收束 `:provider:common` 的正式领域契约：

- `ProviderAdapter`：连接测试、模型列表、能力查询、流式生成和取消；
- `ProviderAdapterRegistry`：按协议选择实现，每种协议只允许一个有效版本；
- `ProviderConnectionProfile`：端点、协议和 Secret Store 引用；
- `ProviderCapabilitySnapshot`：服务商/模型能力三态快照；
- `GenerationRequest`：分层提示、参数、结构化输出、超时和幂等意图；
- `ProviderStreamEvent`：统一开始、增量、用量、完成、拒绝、失败与心跳；
- `ProviderEventGate`：统一流顺序与单终态规则；
- `ProviderUsage`、标准结果与取消结果。

上层生成编排以后只依赖这些类型，不需要知道 OpenAI、Anthropic、Gemini、Ollama 或中转站各自的 JSON 结构。

## 2. 防泄漏设计

以下值不使用普通 `String` 直接参与默认日志表示：

- 小说提示和响应增量；
- 拒绝说明；
- 结构化输出 schema；
- 模型 ID；
- 服务端 request ID；
- base URL。

相应值对象的 `toString()` 只显示类型或字符数。`GenerationRequest` 只显示本地 request ID、分层数量、总字符数和布尔状态；`ProviderConnectionProfile` 只显示协议、是否有主密钥引用、敏感请求头数量和是否显式允许本地 HTTP。

连接配置只保存 Secret Store 的 UUID 引用，不保存 API 密钥。敏感请求头引用表使用不可修改视图，不能在运行期通过集合强制转换篡改。

## 3. 连接安全边界

连接配置创建时即执行失败关闭校验：

- 远程地址必须是 HTTPS；
- URL 不允许嵌入用户名或密码；
- base URL 不允许 query 或 fragment，避免把密钥放入地址；
- 只有用户明确确认的 `localhost`、回环、私网或链路本地字面地址允许 HTTP；
- 远程域名即使勾选“本地明文”也不会被放行；
- 自定义敏感头只允许已知鉴权头或 `x-` 前缀，值必须是 Secret Store 引用。

这只是领域入口校验。DNS 固定、TLS、重定向、真实 header 注入和请求发送仍由 TASK-021 的唯一安全网络出口负责。

## 4. 能力失败保守

能力值使用 `SUPPORTED / UNSUPPORTED / UNKNOWN`，不是简单布尔值。只有 `SUPPORTED` 允许发送可选字段；`UNKNOWN` 与 `UNSUPPORTED` 都不会被当成“应该能用”。

能力快照带有协议、模型、来源、验证时间、过期时间和 adapter 版本。请求检查能力时必须同时满足：

- 快照协议等于连接协议；
- 快照模型等于请求模型。

这避免中转站切换模型后继续使用旧缓存，错误发送 `seed`、结构化输出、reasoning 等不兼容字段。

## 5. 分层请求契约

提示按稳定优先级排列：

1. 应用硬规则；
2. 当前阶段契约；
3. 故事圣经；
4. 当前规划；
5. 运行记忆；
6. 近期摘要；
7. 写作风格；
8. 用户要求。

请求至少包含阶段契约，最多 64 个部分、总计最多 2,000,000 个字符。适配器可以根据原生协议映射为 system/user/content，但不能改变层次顺序。

温度、top-p、最大输出、seed、reasoning、schema 和幂等键均有值域或格式约束。连接、首字节、流空闲和阶段总时限独立表达，避免以后只用一个模糊的“超时”。

## 6. 标准流与终态

统一事件：

- `Started`；
- `TextDelta`；
- `StructuredDelta`；
- `UsageUpdate`；
- `Completed`；
- `Refused`；
- `Failed`；
- `Heartbeat`。

`ProviderEventGate` 规定：

- 开始前的普通增量不进入业务层；
- 重复 `Started` 被忽略；
- 一条流最多发出一个完成/拒绝/失败终态；
- 终态后的迟到增量被忽略；
- 网络结束但服务商没有给终态时，生成一次 `STREAM_INTERRUPTED`，不得假装成功。

用量分为服务方报告、客户端估算和未知。未知用量不能夹带看似准确的数字；总量小于输入加输出会被拒绝。

## 7. 二次审查补强

首轮实现编译通过后又做了一次专门的边界复查，并补上两项：

1. 禁止跨模型、跨协议复用能力快照；
2. 把敏感请求头引用表改为不可修改视图。

这两项均新增失败路径测试，不依赖代码评审者“记得正确调用”。
