## 1. 本阶段结果

织卷已经形成跨 OpenAI Chat Compatible、OpenAI Responses、Anthropic Messages 和 Gemini GenerateContent 的统一失败证据与重试决策。系统不再只看“429、5xx、断网”就决定重发，而是同时判断请求是否可能已送达、是否已经收到正文、是否存在重复费用风险、预算是否允许以及自动重试窗口是否耗尽。

本阶段没有调用真实 API，没有读取或使用聊天中提供的密钥。所有网络夹具均为本地 MockWebServer。已连接的小米实体机没有安装、写入或变更；Android 命令全部显式锁定模拟器。

## 2. 关键实现

### 2.1 四态请求送达证据

新增 `FailureRequestState`：

| 状态 | 含义 | 自动处理边界 |
|---|---|---|
| `NOT_SENT` | 已确认请求没有离开本机 | 可等待网络或执行有界重试 |
| `PROVIDER_REJECTED` | 服务端返回明确失败 | 只有限流/过载白名单可有限重试 |
| `RESPONSE_STARTED` | 已收到响应或流已经开始 | 视为可能计费；正文出现后不自动重放 |
| `RESULT_UNKNOWN` | 无法确认服务端是否执行 | 用户确认前不重发 |

安全传输层为本地凭据失败、端点校验、DNS 和 TLS 失败提供 `NOT_SENT` 证据；无法证明送达结果的网络错误保留为 `RESULT_UNKNOWN`。四个适配器透传该证据，并把非 2xx 服务端响应标记为 `PROVIDER_REJECTED`。

### 2.2 统一纯决策策略

`ExternalRequestRetryPolicy` 位于 `:core:task`，不执行睡眠、网络调用或数据库写入，只返回一种明确动作：

- 等待网络恢复；
- 按延时自动重试；
- 执行一次上下文或格式修复；
- 进入专用截断续写；
- 要求用户确认；
- 停止。

策略先检查预算和正文，再检查错误类别：

- 自动重试最多 3 次；
- 同一逻辑请求累计等待最多 15 分钟；
- 采用带抖动的指数退避；
- 合法 `Retry-After` 是最小等待时间；
- 预算耗尽立即停止；
- 已收到正文时，除专用截断续写外，不自动重放原请求；
- 结果不明时明确暴露可能重复计费风险。

### 2.3 `Retry-After` 完整解析

统一解析器支持：

- 非负秒数；
- RFC 1123 HTTP-date；
- 最大 24 小时的单值上限；
- 过去日期归零；
- 非法值、负数、控制字符和无法解析的日期返回空值。

四个首发适配器已经移除各自重复的整数解析代码，统一使用同一个解析器。

### 2.4 Gemini 配额保守分流

Gemini 的 `RESOURCE_EXHAUSTED` 可能同时代表限流、日配额或账单问题。现在只有存在合法 `Retry-After` 时才映射为 `RATE_LIMITED`；缺少该证据时映射为 `QUOTA_EXHAUSTED`，避免额度耗尽后持续自动重试。

## 3. 13 类失败矩阵

| 类别 | 默认动作 |
|---|---|
| 无网 | 仅确认未发送时等待网络 |
| DNS | 仅确认未发送时有限重试 |
| TLS | 停止，不绕过安全校验 |
| 鉴权失败 | 停止并修复密钥 |
| 模型不存在 | 停止并重新选模型 |
| 协议不匹配 | 停止并修复连接配置 |
| 限流 | 仅服务端明确拒绝且无正文时有限重试 |
| 额度耗尽 | 停止 |
| 服务过载 | 仅服务端明确拒绝且无正文时有限重试 |
| 策略拒绝 | 停止，不规避、不循环改写 |
| 上下文过大 | 最多一次既定缩减 |
| 流中断 | 无正文可有界重连；有正文要求确认 |
| 结果未知 | 用户确认前不重发 |

另外，格式无效只允许一次修复；输出截断进入续写流程，不重放原始请求。

## 4. 关闭的严重疏漏

| 风险 | 本阶段处理 |
|---|---|
| 超时后服务端已生成，客户端再次付费请求 | `RESULT_UNKNOWN` 要求用户确认 |
| 半章已经显示后自动从头重发 | `contentObserved` 先于错误码判断 |
| HTTP 客户端或适配器各自偷偷重试 | 传输/适配器只提供证据，唯一决策位于 core task |
| 429/5xx 高频或无限重试 | 3 次上限、15 分钟总等待、指数退避 |
| 服务端要求等待却被忽略 | 秒数与 HTTP-date `Retry-After` 统一解析 |
| Gemini 日配额被当瞬时限流 | 缺少重试证据时按额度耗尽停止 |
| 格式/上下文修复形成循环 | 每类最多一次修复 |
| 预算耗尽后重试策略仍放行 | 预算闸门优先于所有动作 |
