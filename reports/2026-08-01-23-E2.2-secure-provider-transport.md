# 织卷工作汇报 23：E2.2 Provider 安全传输出口

> 日期：2026-08-01  
> 对应：TASK-021  
> 结论：ProviderAdapter 到 HTTPS、Android Keystore 和加密诊断之间已有唯一安全接线；真实服务商适配器不能绕过路径、密钥、重定向、取消和响应上限规则

## 1. 新增模块

新增 `:provider:transport`，职责限定为：

- 接收已经验证的 `ProviderConnectionProfile`；
- 从 base URL 和安全路径段构造请求；
- 在发送时短暂租借 Secret Store 密钥；
- 使用关闭自动重试/自动重定向的 OkHttp；
- 登记和取消活动请求；
- 返回受限、必须关闭的 response lease；
- 把网络开始、响应打开、失败和取消转换为加密低敏诊断。

没有把这些职责塞进 `:core:network`。基础网络策略继续独立，不反向依赖 Android Keystore 或诊断存储；后续每个服务商 adapter 依赖统一传输层即可。

## 2. 请求构造边界

服务商 adapter 不能提交任意绝对 URL，只能提交：

- 逐段路径；
- 明确为公开的 query 参数；
- 明确为公开的 header；
- 主密钥 header 绑定；
- 连接配置里的自定义敏感 header 引用；
- 可关闭的敏感请求正文；
- 响应最大字节数。

本地创建阶段拒绝：

- `.`、`..`、斜杠、反斜杠、`?`、`#` 等危险路径段；
- `key`、`api_key`、`api-key`、`token`、`secret`、`credential`、`auth` 等敏感 query 名；
- 从公开 header 通道写入 Authorization、API key、cookie、token/secret/credential 命名或连接登记的敏感头；
- 覆盖 Host、Content-Length、Connection、Transfer-Encoding；
- 把主密钥注入不受支持的任意 header。

测试首轮确实发现 `api_key` 下划线形式没有被 query 规则覆盖。实现随后收紧，失败测试通过；没有删除或弱化该断言。

## 3. 密钥生命周期

主 API key 与自定义敏感 header 均只以 UUID 引用进入连接配置。生产绑定在请求发送前调用 `AndroidSecretStore.read`：

- 主密钥要求 `API_KEY` 用途；
- 自定义敏感头要求 `SENSITIVE_HEADER` 用途；
- lease 使用后立即关闭并清零；
- body 的原始 `CharArray/ByteArray` 和内部发送 buffer 均在所有成功/失败路径清零；
- response lease 中的 request 副本移除所有密钥 header；
- 请求、response lease 和诊断对象的默认字符串不打印密钥、正文、base URL 或异常 message。

HTTP header 库不可避免需要构造短生命周期字符串，因此传输层不把含密钥的 OkHttp Request 返回给业务层；活动 response 必须及时关闭，让底层 Call 与短生命周期对象尽快释放。

## 4. 重定向和重试

- `followRedirects=false`；
- `followSslRedirects=false`；
- `retryOnConnectionFailure=false`；
- 可能创建付费任务的 POST 遇到任意 3xx 都不会自动重放；
- 当前传输请求枚举中的 GET 只有同 origin HTTPS 才可有限跟随（底层执行器也已为后续 HEAD 保留同样规则）；
- 跨 origin、HTTPS 降级、循环、异常 Location 和超限重定向全部失败关闭；
- 跨 origin 测试中源站收到 1 次请求，目标站收到 0 次，Authorization 和自定义 API key 均未到达目标。

局域网 HTTP 仍只在领域层支持“显式确认的本机/私网字面地址”。Android 平台当前保持全局明文关闭；ADR-006 未完成前不会为了 Ollama 打开全局 cleartext。

## 5. 超时、响应与取消

四类超时分别落实：

- connect timeout；
- first-byte/read-header timeout；
- stream idle timeout；
- total stage timeout。

GET 重定向每跳会按已经消耗的时间收紧剩余总时限，不能每次获得一个新的完整阶段预算。

响应有两层大小保护：

1. 已知 `Content-Length` 在交给 adapter 前预检；
2. 未知/chunked 流通过计数 source 检查，超过调用方上限立即 `ProtocolException`。

全局硬上限为 256 MiB，默认单请求上限 64 MiB；具体 adapter 应按模型阶段给出更小上限。

活动请求按 requestId 唯一登记：

- 重复 `open` 返回 `AlreadyActive`，不会替换原 Call；
- 等待响应头时取消会调用 `Call.cancel()`；
- 响应已经打开时取消会关闭 body/response；
- 重复取消不会产生第二个网络动作；
- response 正常关闭或读取失败后从活动表移除。

## 6. 错误语义补强

新增尾部标准错误码 `CREDENTIAL_UNAVAILABLE`，专指：

- 本地 Secret Store 被锁定；
- Android Keystore key 失效或缺失；
- 本地密钥记录损坏或用途不匹配。

这类错误发生在联网前，不会再被误报成远端 `AUTH_FAILED`。后者只留给服务商 401/403 等协议响应，由具体 adapter 映射。

枚举值追加在末尾，避免改变既有诊断编码中的旧 ordinal。

## 7. 加密诊断接线

新增 `EncryptedProviderTransportDiagnosticSink`：

- 记录 request started、response opened、request failed、request cancelled；
- connection、endpoint、requestId 进入 `DiagnosticEventFactory` 后变为域分离哈希；
- 保存协议、标准错误码、HTTP 状态、耗时、API level 和异常类型；
- 不保存 query、header 值、正文、响应正文、异常 message 或 stack trace；
- 诊断写入失败不会让网络请求崩溃，也不会回退明文。

真实 Android 集成测试解密诊断后确认每个事件只有 3 个 96-bit 十六进制关联哈希，没有连接 ID、密钥或正文 canary。
