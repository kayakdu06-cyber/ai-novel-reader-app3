# 织卷工作汇报 54：故事种子、故事圣经与全书总纲

> 日期：2026-08-03

## 1. 本阶段结果

初始创作规划已经从“只有 Prompt 准备契约”推进为可执行、可恢复、可审计的三阶段链：

1. 故事种子：把用户的一句话设想稳定为核心承诺、冲突、结局方向、目标章数和初始人物；
2. 故事圣经：在种子成功后固化人物、成人事实、世界规则和硬事实；
3. 全书总纲：在圣经成功后形成连续覆盖冻结目标章数的宏观节拍。

三个阶段已由本地假 Provider 完整走过发送前审计、加密流草稿、严格结构化校验、内部提交许可、SQLCipher 事务、Usage 结算和下一阶段激活。它不是只在内存里拼出三个对象的演示夹具。

## 2. 交付内容

### 2.1 严格结构化契约

- 新增 `story-seed.v1`、`story-bible.v1`、`master-outline.v1` 三份完整 Provider JSON Schema。
- 所有嵌套人物、世界规则、事实和节拍都有明确字段、枚举、长度、数量、数字范围和 `additionalProperties: false`。
- 本地独立执行严格 UTF-8、JSON、重复键、字段、类型、ID、hash、唯一性和跨文档业务校验，不能只信 Provider 的结构化输出声明。
- 人物成人状态拒绝“不适用”；年龄与状态必须一致。涉及亲密关系的人物必须是虚构且明确成年。
- 总纲必须从第 1 章连续覆盖到快照目标末章，不能缺章、重叠、从 0 开始、擅自缩短或越界。

### 2.2 三阶段 Job

- Job 创建时冻结 `zhijuan.prompt-bundle.v1`。
- 固定建立“故事种子 → 故事圣经 → 全书总纲”三个阶段，不允许运行时动态插入、删除或换序。
- 阶段输入 hash 和幂等键可确定性复算；损坏、重复或错误依赖在任务创建前失败关闭。

### 2.3 持久化与来源

- 故事种子正文保存在加密 ArtifactRevision，成功引用只留 schema、稳定 ID 和 hash，不在日志或 Stage 引用中保存明文。
- 故事圣经保存为不可变修订，并映射人物实体、成年年龄事实、世界规则及 `HARD_CANON` 硬事实；每条记录保留书籍、阶段和来源。
- 全书总纲保存为不可变修订及唯一 BOOK 根节点。
- 所有稳定实体 ID 均由书籍范围内的确定性 SHA-256 推导，精确重放不会重复插入。

### 2.4 原子提交和恢复

- 每个阶段只依赖已经存在的前序结果，校验成功后立即提交并激活下一阶段。
- 提交事务复核校验 permit、最新成功 Attempt、加密草稿修订/hash、书籍、Stage、目标类型、当前 Job 指针、租约、Usage 和下一 Stage。
- 任一记录、依赖、时间、hash 或状态不匹配时整笔事务回滚；不会留下半套圣经、半套人物事实或假成功总纲。
- 完全相同的成功提交只回读已有结果；不同载荷不能借“重试”覆盖历史。

## 3. 本阶段发现并修正的严重设计问题

最初的组合映射要求故事种子、故事圣经和总纲同时存在后才允许第一次提交。但状态机又规定：圣经只能在种子成功后激活，总纲只能在圣经成功后激活。这会形成循环依赖，导致第一个阶段永远无法合法完成。

现在已经拆成增量校验和增量提交：

- 种子只校验冻结篇幅；
- 圣经校验已提交种子；
- 总纲校验已提交圣经和目标章数；
- 完整三件套校验只作为最终一致性复核。

这个修正同时把崩溃后的重做范围限制在当前失败阶段，避免重复费用和重复生成前序结果。
