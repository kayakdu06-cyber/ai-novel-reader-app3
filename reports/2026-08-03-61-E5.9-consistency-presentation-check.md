## 1. 本轮结果

TASK-058 已完成“本地确定性检查 + 模型语义/呈现检查 + 接受/退修门禁”的底层闭环。

候选正文现在不会因为模型说“没问题”就直接进入书库。系统会先在本地检查来源、正文边界、人物/成年人事实、离场状态、地点移动、物品归属、时间顺序和计划必需事件；只有本地没有 blocker/major 且成年人场景门禁允许时，才准备模型检查。

模型检查固定为 `chapter-consistency-report.v1`。模型必须按固定顺序逐项返回 23 个检查标准，只能报告白名单问题码、固定严重度、Unicode 码点位置、已知对象 ID 和固定修订动作，不能续写、改写、摘录正文或自由决定什么算 blocker。

任何 blocker/major 都进入 `REVISE_CANDIDATE`；只有 minor 或无问题才能进入 `ACCEPT_CANDIDATE`。这里的“接受”只是允许 TASK-059 尝试最终提交，不代表章节已经成为正式可读内容。

## 2. 严格场景连续性

严格模式只能从冻结的场景执行契约自动推导，调用方不能用一个布尔值强行开启或绕过：

- 细写并要求避免淡出；
- 场景存在冻结的关键过程节点；
- 所有相关人物都是已知虚构角色；
- 所有相关人物均已明确成年且年龄不低于 18。

满足后，每个关键过程节点都必须按原顺序返回 `COVERED` 或 `MISSING`，目标覆盖率为 100%。检查同时覆盖：

- 淡出或一句话概述替代；
- 动作没有对应反应；
- 空间、姿势或身体状态无因跳变；
- 相关触觉、视觉、声音、呼吸、语言和心理承接缺失；
- 相关场景余波缺失；
- 为了“显得详细”而机械罗列词汇。

成年人或虚构身份门禁不通过时，系统在 Provider 打开前阻断，不会静默改成留白继续，也不会新增逐场确认步骤。

## 3. 本地确定性检查

新增的本地检查包含：

- 候选内容 SHA-256 与冻结来源不一致；
- 空正文、低于计划最小长度、超过 4 MiB；
- 代码围栏、意外章节标题、长段精确重复；
- 未知实体引用、成年人/年龄事实冲突；
- 已死亡或离场人物无解释返回；
- 地点移动不满足时间约束；
- 物品无解释转移或同时归属多人；
- 章节/故事时间顺序冲突；
- 计划要求的关键事件未覆盖。

本地 checker 不做模糊相似度猜测，不保存正文摘录，最多返回 64 个有界问题。已经足以要求退修时不调用模型，避免无意义费用。

## 4. 模型输出与来源防串线

请求同时绑定：

- 候选版本 ID、正文 hash、章节 ID 和序号；
- 本地检查快照 hash；
- 场景执行契约 hash；
- 已知实体、证据和关键过程节点快照；
- 持久 RequestIntent 的规范 `inputHash`。

Provider 打开前会再次比较持久 `inputHash` 与本次规范来源绑定 hash。测试中把候选正文替换后，旧 RequestIntent 保持在原状态，Provider 调用数为 0。

输出上限为 512 KiB，问题最多 128 条。23 个标准必须恰好出现一次且顺序正确；每个问题必须被一个标准准确引用；实体、伏笔和过程节点只能引用请求白名单。严重度与修订动作按问题码固定，防止模型把普通语气差异升级为硬阻断。

## 6. 持久化边界

`ChapterConsistencyPersistenceMapper` 已能确定性生成 `ConsistencyReportEntity` 草稿，包含来源 hash、标准结果、过程结果、问题码、严重度、位置、已知 ID 和修订动作，不含正文或证据原文。

它当前不会单独插入数据库。原因是候选 `ChapterVersion` 尚未正式存在，提前插入会违反外键或把未发布候选伪装成正式报告。TASK-059 必须在正文 hash 最终稳定后，把正文、章节记忆、时间线/伏笔、检查报告、Usage、Stage 和 Job 放入同一原子提交闭环。

本轮复用现有 Room schema v8，没有新增迁移。
