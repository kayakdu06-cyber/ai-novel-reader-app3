# 织卷工作汇报 21：M1.9 加密脱敏诊断基础

> 日期：2026-08-01  
> 对应：TASK-018  
> 结论：诊断事件不接受自由文本；敏感关联值只留哈希；本地记录加密滚动保存；损坏时不回退明文

## 1. 为什么不能只做“关键词替换”

API 密钥可以通过模式识别脱敏，但小说正文、人物设定和用户自己命名的模型/连接没有可靠通用模式。若日志先接受完整请求、响应、异常 message 或任意字符串，再靠正则擦除，迟早会漏。

本轮采用更严格的入口设计：默认日志根本不接收完整提示、响应体、正文、书名、URL、header 值或自由文本 message。

## 2. 结构化事件契约

新增 `:core:diagnostics` 模块。事件仅允许：

- 严重级别、类别、事件码和操作枚举；
- 标准错误码与协议枚举；
- HTTP 状态、是否可重试、耗时和 Android API 等数字/布尔字段；
- 随机事件 ID；
- 经过单向哈希的关联标识；
- 最多四层异常类型名。

连接、endpoint、模型、书、job、stage 和 attempt 的原值会按字段类型做域分离 SHA-256，并只保留 96 bit 十六进制摘要。相同原值在不同字段类型下不会得到相同摘要。

异常只记录 Java/Kotlin 类型，例如 `java.net.SocketTimeoutException`；不记录 `Throwable.message`、cause message、suppressed message 或 stack trace 文本。

## 3. 有界编码

诊断编码格式包含固定 magic、格式版本和事件数。所有字符串、事件数、关联字段数、异常层数和总字节数都有硬上限；重复字段、未知枚举、畸形长度和尾随数据都会被拒绝。

默认本地上限：

- 最新 512 条；
- 解密后最多 512 KiB；
- 超限仅淘汰最旧的已经脱敏事件。

## 4. Keystore 加密持久化

诊断存储复用已经验收的 `AndroidProtectedArtifactStore`，新增尾部枚举类型 `DIAGNOSTIC_LOG`，保持旧草稿/恢复点类型编号兼容。

每份当前诊断记录：

- 使用独立随机 artifact 引用；
- 使用独立 Android Keystore AES-GCM key；
- 采用 64 KiB 分块认证、认证头和认证尾记录；
- 每次追加通过 AtomicFile 原子换版；
- `diagnostics/current-log.ref` 只保存随机 UUID，不含事件或私人数据；
- Android 系统备份规则继续全域排除这些文件。

## 5. 失败关闭

若索引、密文、认证标签或 Keystore key 不可用：

- `append` 返回 `FAILED_CLOSED`；
- `snapshot` 返回 `Unavailable`；
- 不抛出原异常 message 给日志层；
- 不创建 `.log`、`.txt` 或 `.jsonl` 明文备用文件；
- 不覆盖或删除损坏的诊断证据。

诊断记录失败不能破坏小说生成或数据库事务；后续编排层只消费成功/失败状态，不允许把原始输入作为兜底日志。
