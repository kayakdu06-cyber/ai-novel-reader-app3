## 2. 请求、版本与隐私边界

- 每个 Anthropic 请求固定发送 `anthropic-version: 2023-06-01`；
- 密钥只通过 Secret Source 注入 `x-api-key`，不进入普通配置、日志或测试夹具；
- Anthropic 要求 `max_tokens`，织卷不会静默猜测默认值：缺少 `maxOutputTokens` 时在联网前失败；
- 应用硬规则进入顶层 `system`，其余内容按 Anthropic 允许的 `user`/`assistant` 角色组织；
- 当本次阶段契约中没有独立用户指令时，阶段契约本身成为用户消息，避免构造空消息数组；
- 结构化输出使用 `output_config.format` 下的 `json_schema`；
- `effort` 使用 `output_config.effort`；
- 请求正文通过可清零 UTF-8 字节缓冲构造，传输结束后清理，不建立包含完整提示的普通请求字符串；
- 模型相关能力默认保持 `UNKNOWN`，只有后续能力注册或探测明确支持时才发送结构化输出、采样和 effort 等可选字段；
- 不根据模型名称猜测能力，也不在失败后静默降级重试。

本阶段同时在 `provider:transport` 中加入可复用的 `SensitiveJsonBodyBuilder`，供新适配器安全地逐段构建敏感 JSON 请求体。现有 OpenAI 两条路径没有在本阶段做高风险机械重构。

## 3. 流式生命周期与终态

Anthropic SSE 按官方生命周期处理：

`message_start → content_block_start/delta/stop → message_delta → message_stop`

| 服务端证据 | 织卷结果 |
|---|---|
| `end_turn` / `stop_sequence` | `Completed(STOP)` |
| `max_tokens` | `Completed(LENGTH)` |
| `tool_use` | `Completed(TOOL_CALL)` |
| `refusal` | `Refused(POLICY)` |
| `model_context_window_exceeded` | `Failed(CONTEXT_TOO_LARGE)` |
| `pause_turn` 或未知 stop reason | `Failed(UNKNOWN_RESULT)` |
| EOF 前没有 `message_stop` | `Failed(STREAM_INTERRUPTED)` |

- Anthropic 流不等待 `[DONE]`；`message_stop` 才关闭正常流；
- `ping` 只作为心跳，不写入正文；
- 未知非终态事件允许向前兼容，但不能伪造成功终态；
- `thinking_delta` 与 `signature_delta` 不进入小说正文，只有 `text_delta` 进入正文；
- `message_delta.usage` 按累计值处理，并在唯一终态前发出；
- `529 overloaded_error`、429、鉴权、计费、413 等错误映射到统一错误类型，服务端原始错误文字不直接显示或落盘。
