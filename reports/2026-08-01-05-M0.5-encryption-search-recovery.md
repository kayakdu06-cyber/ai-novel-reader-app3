# 织卷工作汇报 05：M0.5 加密、中文检索与恢复安全边界

- 日期：2026-08-01
- 阶段：M0.5
- 状态：完成本轮尖峰；物理设备专项仍待后续闸门

## 本阶段完成

- 新增独立 `:core:security` 与 `:core:database` Android 模块。
- 接入 Room 2.8.4、SQLCipher for Android 4.17.0、AndroidX SQLite 2.6.2。
- 首次运行生成 32 字节随机数据库口令；口令由 Android Keystore AES-256-GCM 密钥包装后写入 `noBackupFilesDir`，不把数据库口令明文写进 Room 或偏好设置。
- 建立带 magic、版本、IV 长度和密文长度校验的密钥信封格式；截断、尾随数据、错误 magic 和异常长度均拒绝。
- 建立加密搜索尖峰数据库、FTS4 表、内容表同步触发器和 schema 导出。
- 完成 schema 1 → 2 显式迁移并在加密库上实际验证旧数据保留。
- 建立后台恢复安全策略：未显式允许自动续写、人工暂停、预算耗尽、无网络、重试时间未到或租约仍有效时，不允许产生新的付费请求。
- 对已写请求意图、正在流式传输或结果未知的阶段，只允许“核对旧请求”，禁止直接补发一个新请求。
- 建立源码和 APK 密钥扫描器，并接入 `scripts/verify-build.ps1`。

## 真机环境说明

本轮使用本机现有的 Android 35 x86_64 模拟器。它能验证 Android Keystore、SQLCipher 原生库、Room、迁移和 FTS 的真实 Android 行为，但不能替代不同厂商物理设备的 Keystore、闪存和系统调度差异。

## 加密验证结果

- Keystore 同一明文两次加密得到不同 IV 与不同密文，均可正确解密。
- 加密数据库文件头不等于 `SQLite format 3`。
- 已知正文的 UTF-8 明文字节未出现在数据库文件中。
- 数据库关闭后使用同一受保护口令可重新打开并召回旧内容。
- 加密 schema 1 → 2 迁移后正文、FTS 索引和新增字段均通过校验。

## 提前发现并修正的问题

SQLCipher 4.17 与 Room 连接池会延迟打开额外连接。如果在首次 `writableDatabase` 返回后立即清零传给 SQLCipher 的口令字节，后续只读连接会报“文件不是数据库”。

当前修正为：数据库句柄在 Room 存活期间持有口令；`close()` 先关闭全部数据库连接，再在 `finally` 中清零口令。这个结论已用多连接查询复现和回归验证，不能在后续重构时改回“首次打开后立即清零”。

## 中文检索方案与结果

连续中文不依赖 SQLite 自带分词。索引在同一加密库内保存 ASCII 化的单字和相邻双字 token；多字查询使用相邻双字 `AND` 组合，避免 FTS 查询语法注入。

固定规模测试：

- 加密文档：10,000 条。
- 固定中文查询：20 个。
- 命中：20/20，夹具召回率 100%。
- 10,000 条批量插入：约 1,335 ms。
- 首次冷连接最慢查询：约 388 ms。
- 预热后查询中位：约 1.45 ms。
- 预热后最慢查询：约 2.37 ms。

最初使用普通 JOIN 时，查询规划器先扫描整本书，导致热查询中位约 1.61 秒。改为先由 FTS 子查询产生少量 rowid，再回表读取章节后，规模测试回到毫秒级。App 后续应在启动或进入书架时预开加密库，避免把首次密钥派生约 388 ms 暴露给第一次搜索操作。

## 大章结果

- 正文：200,000 个汉字。
- 派生索引：约 778 ms。
- 加密写入：约 732 ms。
- 查询：约 2.37 ms。
- 测试正文高度重复，派生索引字符串只有 334 个字符；该数字不能代表真实小说的索引体积，只证明大正文读写链路不会因字符数直接崩溃。

## 尚未完成，不能提前宣称安全闭环

- 物理中档 Android 设备性能。
- Keystore 被系统失效、锁屏限制、系统升级和生物识别配置变化。
- 强制杀进程、系统回收和设备重启后的数据库恢复。
- 10 万段落、真实非重复小说语料和多书并发。
- Release APK 接入 SQLCipher 后各 ABI 的体积变化与裁剪策略。
- SQLCipher Community Edition 许可证归档。
- API 密钥需要独立用途密钥和独立 SecretRecord；本轮只实现数据库口令，不把二者混用。
