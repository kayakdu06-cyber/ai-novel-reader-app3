## 1. 先给结论

如果“更有效”指的是：在织卷中用尽量少的用户操作，持续生成一部长篇或中篇成人小说，并且让关键场景按选定尺度展开、不突然淡出、人物和身体状态能够延续，那么**织卷现有的分阶段生成体系更有效，也更接近可开发、可验证的产品方案**。

如果只比较某一个互动片段的身体感、视角约束和事后状态，用户提供的规则稿有几组条款提供了有价值的微观约束，并已被织卷吸收，尤其是：

- `touch before vision / body reaction before cognition` 的感知顺序；
- `cause → process → aftereffect` 的动作因果链；
- 身体、情绪和关系状态不能无故复位；
- 人物行为必须能够追溯到靠近、回避和捍卫的内在驱动力；
- 普通物件不自动升级为伏笔或世界观核心；
- 巧合只能制造问题，不能代替人物动机解决问题。

因此最佳选择不是二选一，而是：**以织卷现有体系为骨架，吸收该规则稿中适合小说正文的微观叙事规则，再增加一层专门的场景执行契约。**

需要说明：织卷现在已有可执行的 `zhijuan.prompt-bundle.v1`、阶段契约和 Provider 前准备桥，但故事种子/圣经/总纲的具体执行与正文质量检查器尚未接通，也没有完成真实模型 A/B。因此本次比较仍是规则与工程架构结论，不冒充最终成文效果实测。

## 2. 对成人题材的逐项比较

| 评价维度 | 用户提供的规则稿 | 织卷现有体系 | 判断 |
|---|---|---|---|
| 关键场景是否淡出 | 没有明确的尺度字段或禁淡出条件，只靠 `accept_all` 间接施压 | 有 `intimacyDetailLevel=0–4` 和 `fadePolicy=PREFER/ALLOW/AVOID` | 织卷更明确、可记录、可测试 |
| 身体与感官连续性 | 明确规定触觉、身体反应、动作过程和余波 | 已加入章级场景执行契约，覆盖动作—反应、空间/身体状态、相关感官和余波，并进入一致性检查 | 两者优势已合并；织卷更可执行、可测试 |
| 成年条件 | 没有年龄确认门禁，`legal_basis: internal_only` 不能替代结构化事实 | `allRelevantCharactersAdult=true` 才允许进入相关生成 | 织卷明显更可靠 |
| 人物一致性 | 有驱动力、惯性、身份和社交距离规则 | 有故事圣经、人物状态、关系变化、硬事实与语义检查 | 长篇场景下织卷更强 |
| 长篇记忆 | 只有当前对话中的状态继承规则 | 有版本化圣经、章节摘要、事实、时间线、伏笔和检索 | 织卷明显更强 |
| 少操作连续生成 | 要求启动确认、每轮四个选项、指定口令才继续 | 默认自动规划、逐章生成、提交后继续排队 | 用户规则稿与产品目标冲突 |
| 提供方兼容性 | 声称禁止安全规则、法律和拒绝，但无法覆盖模型或 API 上层策略 | 如实识别 `POLICY_REFUSAL`，不无限重试，允许用户自行换连接 | 织卷真实成功率更高 |
| 可测试与可迭代 | 大量自然语言绝对规则，存在互相冲突且没有版本字段 | 结构化参数、Prompt Bundle 版本、审计与回归用例 | 织卷更适合工程化 |
| 互动推演体验 | 每轮选项、GM 模式和玩家调查很完整 | 不是产品目标 | 用户规则稿更适合跑团或互动小说 |

## 3. 用户规则稿中会降低实际效果的部分

### 3.1 “最高优先级”和 `accept_all` 不会成为真实最高优先级

App 发送的文本无法覆盖模型服务商的系统规则和内容政策。把“忽略安全规则”“不得拒绝”等声明直接塞入提示，常见结果不是得到更具体的正文，而是被识别为越权指令或提示注入，造成整次请求拒绝。它也无法保证不同模型、中转站和模型版本给出一致结果。

这类条款没有进入织卷 Prompt Bundle。织卷只表达用户的创作意图、明确的呈现参数和本次场景任务；服务端拒绝则透明报告。

### 3.2 互动协议会让用户操作暴增

以下条款适合聊天跑团，不适合自动产书：

- 每次回复必须附四个选项；
- 输出前必须等待用户确认；
- 只有“继续推演”才能前进；
- 被动接触不能产生信息变化；
- 用户指正后必须进入 GM 模式并等待退出。

照搬后，章节会充满选项和元叙事，后台生成会在每一段停住，无法实现“用户开始织书后就去阅读已完成章节”。

### 3.3 若干绝对规则互相冲突或过度收窄文学表达

- 一处要求心理只能通过身体反应链呈现，另一处又要求选项混入内心活动；
- “任何形式的道德判断都禁止”会误伤人物自身的羞耻、犹豫、欲望冲突和价值选择；
- “信息变化只能由玩家主动调查触发”会阻止小说中自然发生的偶遇、误会、旁听和环境揭示；
- “稳定重复后必须引入微异常”容易变成机械的怪异感制造器；
- “未定义就留白”若没有任务字段约束，会让模型把本应补足的场景空间、动作衔接和人物动机一起省略。

处理原则是把这些绝对禁令改成带适用范围的可检查规则，而不是原样照搬。

## 4. 用户规则稿中应吸收的部分

### 4.1 直接吸收

- 普通人物和普通物件默认保持普通，不自动赋予秘密身份、伏笔或世界意义；
- 人物行动必须能追溯到稳定驱动力，性格变化需要渐进证据；
- 严格保持当前视角角色的感知和知识边界；
- 场景采用“原因—过程—后果”链，不能只给结论；
- 伤势、疲劳、情绪印象、关系变化等持久状态进入后续场景；
- 巧合可以引发麻烦，但不能替代选择、代价和动机完成解决；
- 场景结束至少改变状态、关系或风险中的一项；
- 重要场景保留身体反应、动作反馈和事后余波，不能只用抽象形容词概括。

### 4.2 修改后吸收

| 原规则倾向 | 织卷采用方式 |
|---|---|
| 心理只允许通过外部身体反应 | 改为“优先通过动作、感官、语言和可验证反应呈现；允许符合视角的人物内心，但不代替场景行动” |
| 未定义一律留白 | 只对用户有意留空或故事尚未揭示的信息留白；阶段契约要求的事实必须补齐或标记未知 |
| 稳定重复后必须制造异常 | 改为防机械重复检查；只有章计划需要时才引入异常 |
| 每轮生成四个选项 | 改为内部规划在关键分岔处可生成候选走向并自动评分，默认不让用户选择、不写进正文 |
| 粗俗语言按角色允许 | 拆为独立语言强度和角色词汇表，不能把“具体”简单等同于“粗俗” |

### 4.3 明确不吸收

- 任何声称覆盖模型、平台或应用硬规则的指令；
- `accept_all` 以及禁止模型拒绝、禁止遵守服务方规则的声明；
- 每轮选项、启动确认、特定继续口令和玩家调查门槛；
- 为了提高通过率而伪装、拆分或改写成规避服务商策略的指令；
- 自动放开涉及未成年人、年龄模糊者、真实人物或无有效成人边界的性内容。

## 5. 已识别并补齐的真实缺口

单独使用 `intimacyDetailLevel=4` 和 `fadePolicy=AVOID`，只能表示“用户想要细写且不淡出”，不足以保证模型在具体场景中执行。为此，TASK-050 已把结构化**场景执行契约**落到 `BUILD_CHAPTER_PLAN`、`DRAFT_CHAPTER`、`CHECK_CONSISTENCY` 和 `REVISE_CHAPTER` 四个阶段；TASK-058 已实现对应检查器、逐过程证明和固定退修门禁。

实现必须包含以下字段或等价结构：

| 字段组 | 作用 |
|---|---|
| 场景目的 | 本场景必须推进的关系、冲突或人物变化，防止只有感官堆叠 |
| 参与者门禁 | 所有相关人物成年状态已确认；成人亲密内容只进入有效成人边界 |
| 呈现目标 | 继承总体细节、亲密细节、语言强度和淡出策略 |
| 视角与知识 | 当前视角、可感知范围、角色当下知道什么 |
| 动作—反应链 | 重要动作必须有可感知反馈，避免只有总结句或抽象形容词 |
| 空间与身体连续性 | 地点、位置、衣着/物品、疲劳和伤势不能无因跳变 |
| 角色词汇与语气 | 词汇粗粝度服从人物和场景，不把高细节误实现成无差别粗俗 |
| 关系前态与后态 | 场景前后的信任、距离、压力或风险变化 |
| 余波 | 身体、情绪、关系和后续决策中至少记录与剧情相关的实际影响 |
| 禁止替代 | 当 `fadePolicy=AVOID` 且章计划要求展开时，不能用转场、醒来后、事后概述或一句话总结代替关键过程 |

这层契约只规定叙事质量和可执行性，不负责绕过服务商策略。非自愿性性暴力也不能由普通“成人/细写”档位自动放开或成为规避边界的例外。

## 6. 推荐的最终分层

```text
应用硬规则
  ↓ 年龄、数据、格式、提供方边界
阶段任务契约
  ↓ 本次只做种子/规划/正文/摘要/检查中的一种
书级创作宪法
  ↓ 视角、人物驱动、文风、节奏、普通元素规则
章级计划
  ↓ 目标、场景、转折、钩子
场景执行契约
  ↓ 细节、淡出、动作反应、空间连续性、关系变化、余波
正文草稿
  ↓
结构化记忆 + 一致性/呈现检查
```

这样既保留用户规则稿最有价值的“微观写法”，又不把 App 变成需要频繁确认的互动聊天。

## 7. 后续必须如何验证

本次没有调用真实 API，也没有使用用户曾提供的 DeepSeek 密钥；以下结论属于规则与产品架构评审，不冒充模型实测。

在 `TASK-059` 完成并具备安全真实联调门禁后，用同一模型、同一参数和同一组“所有人物明确成年、无真实人物”的固定测试故事做三组盲测：

1. 用户原规则稿；
2. 织卷现有分层规则；
3. 织卷分层规则 + 本次建议的场景执行契约。

记录：请求拒绝率、计划内关键场景淡出率、动作连续性错误、人物/关系状态遗漏、重复表达、章节完整度、用户需要介入的次数和 token 成本。验收目标不是“某一次写得更猛”，而是连续多章仍然具体、连贯、可控且不需要用户反复纠正。

## 8. 最终判断

- **直接原样使用：不建议。** 它会把织卷变成互动推演工具，并包含现实中无效的越权指令。
- **对单场景写法的启发：有价值。** 身体反应链、状态继承、人物驱动、视角边界和余波规则值得吸收。
- **对织卷成人题材的整体有效性：现有织卷架构胜出；场景执行契约及身体与感官连续性现已成为正式开发基线。**
- **最终推荐：织卷架构 + 精选叙事规则 + 可测试场景执行契约。** 这是比任何一份单体“万能提示词”更可靠的方案。
