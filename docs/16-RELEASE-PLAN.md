# 织卷开发与发布计划

## 1. 排期口径

以 1 名主开发者在 AI 辅助下推进。原 16 周日历估算不再作为交付承诺；当前项目以可靠性、章节速度和恢复闸门为准，完成 TASK-062/063 的基准后再按实测速率更新剩余排期。若只求能演示的原型，时间可以更短；但不能把原型当成可长期保存私人小说和付费调用 API 的稳定版。

所有阶段以“闸门完成”而不是日历到点为准。

## 2. 里程碑

### M0：技术风险验证（第 1–2 周）

交付：

- Android 工程、模块边界、CI 基线；
- Room + 加密候选 + FTS 技术尖峰；
- OpenAI/Anthropic/Gemini/Ollama 流夹具解析原型；
- FGS timeout/进程回收实验；
- 长中文章节阅读性能实验；
- 加密备份流式写入、损坏包/错口令和原子恢复尖峰；
- 自定义中转站 HTTPS、重定向、证书失败和秘密边界尖峰；
- ADR：最低 Android、依赖注入、加密方案、包名。

退出闸门：E0 中所有 P0 尖峰均有可复现实验和结论；不存在会导致丢书、泄密、重复付费或大规模返工的未验证架构假设。物理设备差异可以作为带责任人和截止点的发布前验证项保留，但不得被描述为已经通过。

状态（2026-08-01）：已通过桌面 JVM 与 Android 35 x86_64 模拟器闸门，ADR-001～005 均已接受。物理设备、真实中文语料、OEM 后台行为、最终签名包体积、App 内许可证页和真实服务商兼容性保留为后续发布硬门禁，详见 `22-WORK-STATUS.md` 与 M0 收口报告。

### M1：本地骨架与连接（第 3–4 周）

交付：

- 书架、设置、连接管理骨架；
- Keystore secret 存储和网络安全策略；
- OpenAI Responses/Chat Compatible + 一个假服务端；
- 能力表、连接测试、错误标准化；
- 数据库 v1 和迁移测试框架。

退出闸门：密钥扫描为 0；连接成功/失败路径清楚；release 不信任任意证书。

### M2：单章可靠底座（进行中）

交付：

- 极简创建；
- 生成任务/阶段/attempt 状态机；
- 第一章流式草稿、检查和原子提交；
- 阅读所需的正式章节/生成中草稿数据契约；
- 请求用量台账和单次硬上限。

退出闸门：断流、崩溃、提交重放均不丢旧章、不重复提交；TASK-061 编辑重建链完成。

### M2.5：可靠 runner 与章节速度闸门（M2 后、真实生成前）

交付：

- 脱敏生成时序、固定延迟 Fake Provider 和可重复性能报告；
- 全阶段 dispatcher / total runner；
- 生成中正文只读投影；
- 5 分钟慢服务 watchdog；
- 20 章故障注入闭环。

退出闸门：参考章普通后续章首段 P95 ≤ 20 秒、正文结束 P95 ≤ 180 秒、正式提交 P95 ≤ 240 秒；5 分钟安全处置、10 分钟发布阻断均有自动化证据。真实 Provider 在费用硬限制和目的地确认完成前保持关闭。

### M3：最小可日常使用纵向闭环（排期待速度基准更新）

交付：

- 多章队列、暂停/恢复/停止；
- 单次/单书/每日预算与数据目的地确认；
- 书架、滚动阅读器、目录和生成中正文；
- 20 章 Fake Provider 故障注入；
- 用户授权后的受控真实模型速度/质量档案。

退出闸门：20 章闭环通过；至少一个推荐模型档案满足速度和质量门槛；断网、杀进程、达限和慢服务均有可恢复结果。

### M4：模板、阅读体验与长篇一致性（排期待前序闸门）

交付：

- 暖纸/夜间、字号、行距、边距、滚动/分页；
- 目录性能、阅读位置、生成状态融入；
- 模板提取、一键新书、来源链和分类；
- 时间线、事实、伏笔、中文检索；
- 一致性检查和编辑失效链；
- Ollama；
- 不含私人正文的通用生成通知。

退出闸门：真实中文一致性基准、万章目录压力、无障碍主流程通过。

### M5：稳定化（排期待前序闸门）

交付：

- 所有 P0 错误恢复；
- 数据库多版本迁移和升级恢复点；
- 手动加密备份/恢复；
- 诊断包、TXT/Markdown 导出、许可证清单；
- 真实 API 小额回归；
- 性能、内存、电量和长期流测试；
- 完整安全检查。

退出闸门：`17-ACCEPTANCE-CRITERIA.md` 的所有 P0 通过，S0/S1 缺陷为 0。

### M6：1.0 发布（闸门通过后）

交付：

- 正式签名 APK；
- APK SHA-256、版本说明、已知限制；
- 签名密钥双备份记录；
- 从上一候选版覆盖安装证据；
- 加密备份与恢复演练记录；
- 文档和追踪矩阵同步。

风险缓冲：最多第 17–20 周处理真实中转站兼容、加密/迁移性能、后台时限和 OEM 差异。不能用删除 P0 安全需求来赶日期。

应用锁、生物识别、`FLAG_SECURE` 和最近任务遮挡已由用户明确取消，不属于被日期压力删除的 P0 安全需求；密钥、数据库、费用、目的地、备份和迁移安全仍不可降级。

## 3. 首发范围

### 3.1 1.0 必须

- 一句话创建、题材/篇幅/呈现选择；
- OpenAI Responses、OpenAI Chat 兼容、Anthropic、Gemini；
- 分阶段分章生成、边生成边阅读；
- 故事圣经、摘要、人物/事实基本状态、一致性检查；
- 模板一键重开、来源、分类和版本；
- 用量台账和三层硬限制；
- 加密本地数据、密钥安全、系统备份排除、手动备份恢复；
- 阅读器、目录、阅读位置；
- 中断恢复、迁移、签名和覆盖升级。

### 3.2 可延期到 1.1

- Ollama（若 M4 协议/HTTP 安全风险未过闸门）；
- 章节可视化版本对比；
- 高级模板导入导出；
- 向量检索；
- EPUB；
- 高级字体包和复杂翻页动画。

但延期功能不得导致数据格式无法兼容后续加入。

## 4. 版本策略

- `0.1.x`：内部骨架，不承诺迁移；不得存放唯一正式小说。
- `0.5.x`：MVP，开始要求显式迁移和备份测试。
- `0.9.x`：候选版，schema 冻结，只修 S0/S1/S2。
- `1.0.0`：首个稳定版。
- `1.0.x`：只做兼容和缺陷修复。
- `1.1.0`：新增延期能力，仍需迁移演练。

从 `0.5.0` 起正式禁用破坏性迁移。

## 5. 分支与构建

- 主分支始终可构建；
- 每个里程碑打内部 tag；
- Debug/Release 分离，Debug 数据不得与正式库混用；
- 正式签名不进入 CI 和仓库；
- 每个 release 保存依赖锁、许可证、构建环境摘要和源提交；
- 用户在正式使用前必须先完成一次应用内备份。

## 6. 发布清单

### 产品

- 功能清单状态和已知限制准确；
- 首版内容呈现名称保持 `留白/均衡/细写`；内部维度保留扩展能力，但不为自定义参数增加默认操作；
- 模板新书、分支、章节重试文案不混淆；
- 隐私声明明确本地保存和外部模型调用。

### 数据

- 旧版覆盖升级；
- 迁移计数/哈希检查；
- 备份创建、自检、恢复；
- 系统 Auto Backup 排除验证；
- 低空间/损坏恢复不覆盖。

### 网络与费用

- 所有适配器夹具；
- 真实低成本调用；
- TLS/重定向/密钥脱敏；
- 预算并发、重启、跨日；
- 价格表时间和未知价格提示。

### Android

- Android 12/14/15/最新稳定；
- FGS timeout、通知、锁屏、进程回收；
- 后台遮挡、动态字体、TalkBack；
- 签名、versionCode、APK 哈希。

## 7. 发布物目录建议

```text
releases/<version>/
├─ zhijuan-<version>-release.apk
├─ SHA256SUMS.txt
├─ RELEASE_NOTES.md
├─ KNOWN_ISSUES.md
├─ MIGRATION_REPORT.md
├─ BACKUP_RESTORE_REPORT.md
├─ LICENSES.html
└─ build-metadata.json
```

所有发布物也必须位于 `D:\gptuser`。

## 8. 主要进度风险

| 风险 | 影响 | 提前处理 |
|---|---|---|
| 加密数据库与 FTS 冲突 | 重构存储 | M0 实机尖峰 |
| 中转站协议差异 | 适配器碎片化 | 夹具+能力表+保守字段 |
| OEM 后台限制 | 长任务中断 | 检查点+短批次，不依赖常驻服务 |
| 长篇一致性难量化 | 功能有但质量虚 | 建立固定中文测试故事和冲突集 |
| 费用估算变化 | 误导/超限 | token 硬限+价格版本 |
| 数据迁移后期补 | 丢书风险 | M1 建框架，0.5 起强制 |
| 设计过早膨胀 | 核心迟延 | 先完成状态/数据/阅读骨架再精修视觉 |
