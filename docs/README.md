## 1. 这套文档怎么用

本目录是后续产品、设计、开发和验收的唯一执行基线。旧的 `PROJECT_PLAN.md` 保留为早期讨论记录；两者冲突时，以本目录中编号更高、更新时间更新的具体文档为准。

需求变更必须同时更新：

1. 对应的需求或设计文档；
2. `02-FEATURE-INVENTORY.md` 中的功能状态；
3. `20-TRACEABILITY-MATRIX.md` 中的追踪关系；
4. 必要时在 `18-DECISION-LOG.md` 追加决策，而不是悄悄覆盖历史。

## 3. 优先级定义

- `P0`：缺失会导致核心链路不可用、丢书、费用失控、密钥泄露或无法升级。
- `P1`：正式可用必需；可在内部原型中短暂缺失。
- `P2`：增强体验，不阻塞首个稳定版。
- `P3`：远期候选，未经重新评审不得提前开发。

## 5. 当前不可擅自改变的基线

- 单用户、无账号、无会员、无支付、无社区、无管理后台。
- 小说、模板、设置和用量台账默认本地保存。
- 用户只需给出最少资料；系统负责补全、规划、生成、检查和续写。
- 已完成章节立即可读，后续章节在后台按队列继续生成。
- “模板重开”是一等功能，必须保留来源链、分类和版本，不复制旧正文与密钥。
- 首版对外内容尺度命名采用克制的 `留白 / 均衡 / 细写`；内部字段保持明确、版本化、可测试，自定义不进入默认创建流程。
- 任何 API 服务的拒绝或限制都应如实显示，不设计规避服务商限制的逻辑。
- 自动重试必须同时满足错误白名单、请求送达证据、正文未出现、重试/等待上限和费用预算；结果不明时用户确认前不重发。
- 首次向某个远程 host 发送小说内容前，必须说明发送内容和目的地；“本地优先”不能误写成“完全离线”。
- 所有角色必须明确为成年人；不生成涉及未成年人、年龄模糊者或真实人物的性内容。
- 章节速度分别验收首段、正文结束和正式提交；5 分钟进入慢服务安全处置，10 分钟仍未结束阻断发布。
- 应用锁、生物识别、`FLAG_SECURE` 和最近任务遮挡已取消；其他加密、密钥、备份和传输安全不变。
- 所有项目文件、缓存和交付物只允许写入 `D:\gptuser`。
