# 织卷模板系统规格

## 1. 目的

模板不是一段提示词，也不是旧书的复制件。它是“如何从一个故事设想生成一本书”的可版本化配置包。核心目标是：旧书不满意时，用户无需重新填写人物、题材、风格和篇幅，就能快速开始一本全新小说，同时知道这套设定来自哪里。

## 2. 基本概念

### 2.1 模板（Template）

用户可识别的逻辑对象，拥有稳定 `templateId`、名称、来源、分类和多个修订。

### 2.2 模板修订（TemplateRevision）

不可变内容版本。任何改变故事种子、人物设定、结构、风格或呈现维度的操作都创建新修订，不原地改写。

### 2.3 使用快照（TemplateUseSnapshot）

创建新书时，把所选修订解析、合并用户本次改动后冻结为快照。之后模板再编辑，也不能改变这本书。

### 2.4 书源模板（Book-derived Template）

由一本既有书的创建快照和稳定设定提取；不从旧正文直接“全文复制”。

## 3. 五种来源

| 枚举 | 用户名称 | 定义 |
|---|---|---|
| `SYSTEM_PRESET` | 系统预设 | 随 App 发布、可升级，用户不可覆盖原版 |
| `USER_CREATED` | 我创建的 | 用户从空白或创建页保存 |
| `BOOK_DERIVED` | 来自某本书 | 从书的创建快照/稳定设定提取 |
| `TEMPLATE_FORK` | 从模板调整 | 基于另一个模板修订产生 |
| `IMPORTED` | 外部导入 | 从经过校验的模板包导入 |

来源是系统事实，不允许用户手改。用户可以改展示名称、标签、说明、收藏和归档状态。

## 4. 模板包含什么

### 4.1 默认包含

- 原始故事设想与系统标准化后的故事种子；
- 题材、子题材、故事机制；
- 稳定人物定义：明确成人年龄、身份、性格、初始关系；
- 世界观、时代、地点和硬规则；
- 叙事人称、视角、文风、句式倾向；
- 节奏、章长、分卷方式和总体篇幅目标；
- `留白/均衡/细写`映射后的内部呈现维度、映射 schema 与内容控制 schema；
- 必须出现、禁止出现、结局倾向；
- 生成策略引用，如规划深度、每章检查级别；
- 推荐模型能力角色（不是密钥和强绑定配置）；
- schema、提示模板和应用版本。

### 4.2 默认排除

- 已生成书名、简介、封面；
- 任何章节正文、候选版本和临时流式草稿；
- 章节摘要、人物运行状态、关系变化、当前时间线；
- 伏笔运行台账、检索索引和模型原始响应；
- 请求/错误/费用日志；
- API 密钥、Authorization、自定义敏感请求头；
- 设备路径、设备 ID、应用锁密钥、备份口令；
- 阅读进度、书签和阅读设置。

### 4.3 特殊排除规则

模型 ID 可以作为“偏好提示”保存，但创建新书时必须重新根据当前连接验证。若原模型不存在，默认使用当前推荐模型并只提示一次。费用上限采用当前用户默认值，不继承旧书已经消耗的额度。

## 5. 两种重开模式

### 5.1 沿用全部设定（默认）

保留故事种子、稳定人物、世界、题材、机制、风格、节奏、篇幅和呈现维度；重新生成标题、简介、故事圣经的可变部分、总纲、分章和正文。

适合：上一本写坏了，但基本设定仍喜欢。

### 5.2 只沿用风格

只保留叙事人称、文风、句式、节奏、章节结构、篇幅倾向、呈现维度和通用写作规则；清除人物姓名/身份/关系、具体世界、具体冲突、故事事实和结局。

适合：喜欢“写法”，但想换一个完全不同的故事。

## 6. 一键交互

入口：书籍详情 → `重新织一本`。

默认确认页只显示：

```text
会沿用：人物、世界、题材、文风、节奏、篇幅、呈现偏好
会重新生成：书名、故事规划、全部正文
不会复制：旧章节、旧进度、请求记录、API 密钥

[这次想改什么（可不填）]

[开始织新书]
```

用户无需先保存模板、命名模板或手工分类。后台行为：

1. 查找该书当前创建快照对应的有效书源模板；
2. 没有则自动建立 `BOOK_DERIVED` 模板和修订；
3. 应用用户本次改动；
4. 冻结 `TemplateUseSnapshot`；
5. 创建新书和来源关系；
6. 执行正常新书生成流程。

## 7. 分类体系

系统自动生成分类，用户只在需要时整理。

| 维度 | 示例 | 多选 |
|---|---|---|
| 主体题材 | 都市、悬疑、玄幻 | 主 1 + 辅 2 |
| 故事机制 | 重生、系统、破案、成长、群像 | 是 |
| 氛围 | 轻松、克制、阴郁、热烈 | 是 |
| 节奏 | 慢热、均衡、快节奏 | 否 |
| 篇幅 | 短篇、中篇、长篇 | 否 |
| 呈现 | 留白、均衡、细写及其冻结内部指令 | 否 |
| 来源 | 系统、我创建、来自书、派生、导入 | 否 |
| 时间 | 最近使用、最近创建、年份 | 自动 |
| 用户状态 | 收藏、置顶、归档 | 可组合 |

自动标签必须保存生成方式和置信度；低置信度标签不进入主筛选，显示在详情页供确认。

## 8. 来源链与防循环

每个修订保存：

- `parentTemplateRevisionId`：直接父修订，可空；
- `sourceBookId`：来源书，可空；
- `sourceBookTitleSnapshot`：来源时书名，书后来改名也不改变；
- `originRootId`：来源树根；
- `originChainJson`：只读展示链快照；
- `contentHash`：规范化内容哈希；
- `createdAt`、`createdByAppVersion`、`schemaVersion`。

创建新修订前检测父链，禁止把后代设为祖先。删除来源书不删除模板；模板保留书名快照并显示“来源书已删除”。

## 9. 版本规则

- 修改展示名称、收藏、置顶、归档：不创建内容修订。
- 修改任意生成内容字段：创建新修订，修订号 `+1`。
- 系统预设升级：创建新系统修订；用户既有书和快照继续指向旧修订。
- 两个内容哈希相同的修订可提示重复，但不自动合并不同来源链。
- 模板删除默认为归档；硬删除前检查是否被书快照引用。被引用时只允许隐藏，不允许破坏引用。

## 10. 冲突合并优先级

新书最终快照按以下优先级合并，越靠后优先级越高：

1. 系统默认；
2. 所选模板修订；
3. 当前用户全局生成默认值（仅允许覆盖运行偏好，不覆盖故事事实）；
4. 本次“想改什么”的结构化结果；
5. 用户在确认页明确编辑的字段；
6. 内容边界和数据安全硬规则。

合并后执行 schema 验证、年龄明确性检查、冲突检查和模型能力检查。硬规则不能被模板覆盖。

## 11. 导入导出

P2 模板包使用带清单的 ZIP 容器，扩展名建议 `.zhijuan-template`：

```text
manifest.json
template.json
README.txt
```

要求：

- 不含可执行代码、任意绝对路径、密钥和网络请求配置；
- 限制解压总大小、文件数量和路径，防止 Zip Slip；
- 导入前校验 schema、哈希和内容大小；
- 未知字段保留在扩展区但不执行；
- 导入对象来源固定为 `IMPORTED`，原作者字段只是普通说明，不当作可信身份。

## 12. 删除和保留

| 动作 | 模板 | 既有书 | 来源链 |
|---|---|---|---|
| 归档模板 | 隐藏于默认列表 | 不变 | 保留 |
| 删除来源书 | 模板仍可用 | 书进入回收/删除流程 | 保留书名快照，ID 标记不可达 |
| 编辑模板 | 新修订 | 不变 | 新修订指向旧修订 |
| 删除未引用修订 | 可硬删除 | 不变 | 前提是无子修订和无快照引用 |
| 从模板织书 | 不变 | 新建 | 新书保存使用快照和修订引用 |

## 13. 数据与验收要点

必须通过：

- `TEST-050`：模板新书无旧正文、旧摘要和旧日志。
- `TEST-051`：模板 JSON 和备份中搜索不到 API 密钥。
- `TEST-052`：编辑模板后，已创建书的快照哈希不变。
- `TEST-053`：删除来源书后模板仍可使用且来源说明准确。
- `TEST-054`：父链循环被拒绝。
- `TEST-055`：同一旧书一键重开不重复制造无意义相同修订。
- `TEST-056`：“只沿用风格”不保留人物姓名、具体地点和剧情事实。
- `TEST-057`：模板新书、书分支、章节重试产生不同的数据关系。
- `TEST-058`：系统预设升级不改变旧书和旧模板快照。
- `TEST-059`：分类可编辑但来源字段不可篡改。

## 14. TASK-013 已实现的数据库基线

正式 `ZhijuanDatabase` schema v4 已加入 `template`、`template_revision`、`template_use_snapshot` 和 `template_tag`：

- Template 保存稳定来源类型、当前修订、展示名称、收藏、置顶、归档和最近使用时间；来源类型与系统预设键由数据库禁止篡改；
- TemplateRevision 按明确允许字段拆分故事种子、题材、稳定人物、世界规则、写法、结构、呈现、内容规则、生成策略和模型能力偏好，不提供章节正文、请求、用量、密钥或阅读状态字段；
- 修订与使用快照不可原地更新；普通编辑只能从当前修订创建 `revisionNo + 1`，已有书继续引用旧快照；
- 模板派生允许跨模板父修订，但后续普通编辑必须留在同一模板；父链不可变，因此无法在事后制造循环；10 层来源链已通过设备测试；
- 书源模板使用唯一 `derivationKey` 幂等复用；同一来源和内容的重复提取不制造新模板，但相同内容哈希、不同来源仍保留为独立对象；
- 来源书 ID 与书名保存为历史事实，不使用会阻止删书的强外键。提取时必须核对真实书名；来源书删除后 ID 和标题快照仍保留，界面可显示“来源书已删除”；
- TemplateUseSnapshot 与新书一对一，在同一事务中冻结最终允许字段；事务不会创建章节、摘要、生成任务、请求或用量记录；
- payload 合约和数据库触发器共同拒绝常见密钥、Authorization、章节正文键、流草稿、请求与用量字段，并限制模板体积；完整提取清洗仍由 TASK-071 接入；
- 标签保存维度、规范值、展示名、来源、置信度、确认状态和推导修订；低置信度且未确认的标签不能成为主分类，同一维度只能有一个主标签。

v3→v4 使用显式 Migration，保留旧书库并通过 Room 结构验证。当前仅完成可靠数据底座；“只沿用风格”的语义清洗、系统预设装载、AI 提取和三次点击内的界面流程仍分别属于 TASK-070、071、075、076。

## 12. 初始规划结果与模板来源

- TASK-051 的故事圣经、人物实体、世界规则、硬事实和总纲均带稳定书籍/阶段/修订来源，可作为后续“来自某本书”的模板提取证据。
- 模板复制不能直接引用正在变化的内存规划，也不能把加密流草稿当模板；只能从成功提交的不可变修订提取允许字段，并记录来源书、来源阶段和来源修订。
- 故事种子虽不另建可编辑表，但其加密 Attempt 产物和内容哈希可以证明后续圣经来源。TASK-071 提取时应通过后续结构化修订读取安全字段，不把原始请求、密钥、用量或正文带入模板。

## 13. 窗口计划与模板边界

- TASK-052 的窗口修订属于运行中的近程计划，不是默认模板内容。复制上一书模板时可提取稳定的结构偏好，例如卷长和节奏类型，但不得复制具体 1–8 章计划、当前 head、下一窗口指针或运行 Job。
- 若用户明确复制“结构”，来源必须指向成功提交的窗口 revision，并经 TASK-071 的允许字段清洗；旧窗口正文、请求、Usage 和连续性运行状态仍全部排除。
