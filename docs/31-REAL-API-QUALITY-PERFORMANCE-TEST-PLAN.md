# 织卷 DeepSeek V4 Flash 真实 API 小说逻辑与性能测试计划

> 状态：执行前基线
> 日期：2026-08-11
> 首个真实测试模型：DeepSeek V4 Flash
> 本文不授权把密钥写入源码、文档、日志或 Git

## 1. 测试目的

离线测试能证明状态机、schema、预算和恢复逻辑，不能证明真实模型会：

- 按 schema 返回；
- 快速给出第一段；
- 返回完整、非乱码、没有协议残留的中文正文；
- 执行最高内容呈现档位下的敏感场景合同，而不是拒绝后伪装成功、淡出、跳过或只做事后概述；
- 维持人物、关系、道具和特殊机制；
- 不重复剧情；
- 在连续章节中保留关键后果。

真实 API 测试必须在可亲手验证版本之前进行，而不是等 1.0 才进行。

本文不评价文笔、辞藻、语言审美、文学感染力或“是否好看”。句子只有在乱码、残缺或无法判断事件含义时才作为技术失败；其余只验小说逻辑、冻结内容合同、状态连续性、返回速度和 App 数据安全。

## 2. 前置条件

全部满足后才允许 App 发出真实小说请求：

- TASK-129 的 3–5 章 Fake 闭环通过。
- TASK-130/131 的启动、书架和阅读入口完成。
- 当前 Git 根目录是 app3。
- 真实 API Key 只存在于用户配置或隔离 secret 环境。
- 目的地 canonical origin 和协议已由用户确认。
- 单次、每日、单书预算已设置。
- 请求时序和脱敏诊断已启用。
- secret 扫描在测试前通过。
- Provider 拒绝和限流路径可见。
- 测试数据中所有相关角色均明确为虚构成年人。

任何一项不满足，先修本地产品，不用真实 API 掩盖问题。

## 3. 密钥和数据规则

- 不读取、显示、复制或重复 API Key。
- 不在命令行参数中直接传明文 Key。
- 不在 Markdown、截图、异常 message 和 shell transcript 中保存 Key。
- 不记录完整 Prompt、正文和响应。
- 诊断只记录脱敏 ID、阶段、字节/token 计数、时间、标准错误和响应终态。
- 测试结束后运行源码、日志、构建产物和 APK secret 扫描。
- 真实小说正文仅保存在 App 加密存储和明确的脱敏评分产物中。

## 4. 测试环境记录

每次运行保存：

- app commit；
- APK SHA-256；
- Android 设备型号、系统版本和网络类型；
- Provider protocol；
- canonical origin 的不可逆脱敏指纹；
- model ID；
- temperature、topP、maxOutputTokens；
- PromptBundle、WritingPolicyPack、schema 和 capability manifest 版本；
- 目标章节字数；
- 开始时间、结束时间和中断事件；
- 请求次数、输入/输出 token 和价格来源；
- 是否流式；
- 结果：通过、拒绝、限流、协议失败、超时或用户停止。

## 5. 最小真实测试序列

需要生成 token 的真实测试只保留 R1、R2、R3 三组；R0 优先复用零生成能力证据，不为协议、流式、题材和小说逻辑分别重复付费请求。

### R0：连接能力确认

- 优先复用已有模型发现证据；
- 证据不足时才运行一次最小 16-token 通用探针；
- 不发送小说正文；
- 通过条件：model ID、streaming/structured output 能力明确，且无 Key 泄漏。

### R1：一个结构化合同 smoke

- 只请求一个小型 chapter-plan.v2；
- 首次格式失败时允许一次有界修复，成功后停止；
- 通过条件：严格 schema 和业务 validator 通过；
- 若连续两次失败，不再靠更多样本碰运气，返回本地修合同或模型适配。

chapter-post-analysis 不单独做 smoke，由 R2 的完整章直接验证，避免重复请求。

### R2：一个最高敏感度的完整混合逻辑章节

- 3,000–5,000 中文字；
- 同一次完整链覆盖计划、流式正文、首段、usage、合并分析、校验和提交；
- 内容呈现固定为“细写”，所有相关角色必须明确为虚构成年人；本章安排一个对主线有实际推动作用的成年人亲密关系事件，并同时包含至少两类需要跨章记录的机制或物品/关系状态；
- 亲密事件必须改变至少一项后续权威事实、关系状态或叙事义务，不能成为与主线无关的插入段；
- 具体背景和机制名称仅用于形成可复现样本，不定义 App 支持范围；本章只激活实际相关的状态适配器；
- 正常路径不主动制造修订、取消或断网。

Provider 若明确拒绝，应按拒绝结束并记录该模型/端点不满足此产品目标；不得改写测试意图、降低档位或循环换词规避后再把结果记为通过。

通过：

- 本章第一可读段 ≤25 秒；
- 本章正文 ≤300 秒，正式提交 ≤360 秒；
- 无乱码、重复 chunk 或丢尾；
- 正文、状态和 Usage 原子一致；
- 未激活能力不进入 Prompt；
- 冻结的敏感场景关键过程节点完整执行，淡出、跳过和事后概述替代数为 0；
- 本章有明确推进、因果和后果，关键状态无严重矛盾。

### R3：同一本书连续 3–5 章

- 复用 R2 的书继续生成，不新建第二套题材样本；
- 中途只安排一次暂停并重启 App；不同时强制断网、取消和多次杀进程；
- 已完成章节必须可读，后续章节连续；
- 关键义务不丢，核心剧情不重复，无无证据状态回退；
- R2 的敏感关系事件及其状态变化必须在后续章继续生效，不能遗忘、重演为首次发生或无证据复原；
- 逐章记录实际值、样本中位数和最慢值；3–5 章样本不宣称 P95；
- 恢复不产生重复收费事实，10 分钟故障为 0。

只有某个故障无法从现有时序定位时，才增加一个针对该故障的复测。

## 6. 小说逻辑验收

每章由自动指标和人工通过/不通过清单共同决定，不设置文笔分数。

### 6.1 自动指标

| 指标 | 计算 |
|---|---|
| obligationResolution | 到期义务有完成/推进/延期/有理由取消的比例 |
| evidenceCoverage | 权威状态变化具有正文证据的比例 |
| repeatedEventRate | 与最近章节核心事件高度重复且无新后果的比例 |
| stateViolationCount | 人物、关系、道具、系统、修炼和时间线非法转移数 |
| planFulfillment | 本章计划必需事件已经发生、延期或有明确取消证据的比例 |
| causalConsequenceCoverage | 关键事件具有直接后果并进入下一章权威上下文的比例 |
| sensitiveSceneContractCoverage | 冻结敏感场景关键过程节点覆盖率；淡出、跳过和事后概述替代单独计数 |
| promptSelectivity | 未激活策略片段进入 Prompt 的数量 |
| remoteCallsPerChapter | 每章实际远程请求次数 |

### 6.2 人工逻辑清单

- 本章计划中的核心事件是否真实发生，或有可追踪的延期/取消原因；
- 人物行动是否有动机，事件前因、过程和结果能否接上；
- 人物身份、位置、知识、关系、身体、道具归属、特殊机制和时间线是否与已有事实一致；
- 核心剧情是否没有换词复述，已经发生的事件是否没有被重演为首次发生；
- 最高敏感度场景是否按冻结合同完整执行，并产生后续关系、义务或剧情状态；
- 用户设想与本章任务是否被兑现，模型是否擅自改题材、降档或删掉关键事件。

不评价辞藻、修辞、句式美感、文风偏好、文学感染力和继续阅读意愿；这些项目不能导致通过或失败。

P0 通过条件：

- 正文完整、非乱码且可确定事件含义；
- planFulfillment、causalConsequenceCoverage 和到期 obligation 均无无证据缺失；
- sensitiveSceneContractCoverage 为 100%，淡出、跳过和事后概述替代数为 0；
- stateViolationCount 的 P0 错误和严重一致性错误均为 0；
- 连续样本没有核心事件换词复述或关键后果遗忘。

## 7. 速度指标

### 7.1 时间点

- T0：用户点击开始；
- T1：Job/Stage 持久化；
- T2：Provider open；
- T3：首个响应字节；
- T4：首个可读段落盘；
- T5：正文流结束；
- T6：章后分析结束；
- T7：正式 ChapterVersion 提交；
- T8：UI 可见正式完成。

### 7.2 阈值

VS-1 只有 3–5 章，不用少量样本伪造 P95。该阶段逐章验硬上限并报告每章、样本中位数和最慢值；至少 20 章后才计算推荐模型的 P50/P95。

| 指标 | VS-1 每章硬上限 | 至少 20 章后的目标 |
|---|---:|---:|
| T2-T0 | ≤3 秒 | P95 ≤2 秒 |
| T4-T0 | ≤25 秒 | P50 ≤10 秒、P95 ≤20 秒 |
| T5-T0 | ≤300 秒 | P95 ≤180 秒 |
| T7-T0 | ≤360 秒 | P95 ≤240 秒 |
| 任一正常章 | <10 分钟 | 10 分钟故障为 0 |

“测试命令可无限等待直到返回数据”表示测试人员可以保留长尾证据，不表示 App 可以一直显示无反馈。5 分钟进入慢服务状态；10 分钟进入故障并阻断发布。

## 8. 费用指标

记录：

- plan 输入/输出 token；
- draft 输入/输出 token；
- post-analysis 输入/输出 token；
- revision 输入/输出 token；
- 每章总 token；
- 估算和实际费用差异；
- 被拒绝、取消、UNKNOWN 和重试的占用。

目标：

- 正常章不为每个启用能力增加独立请求；
- 正常章不触发 revision；
- Prompt token 随章节增长保持有界，不随全书字数线性增长；
- 3–5 章总费用必须在用户确认预算内；
- 价格未知时只展示 token，不伪造货币金额。

## 9. 条件触发的 A/B

A/B 不是固定测试。只有 R1～R3 出现以下任一情况才执行：

- 新策略比旧 Prompt 明显慢；
- 输入 token 异常增加；
- 小说逻辑或最高敏感度场景合同未通过；
- 未激活能力污染正文；
- 无法判断问题来自模型波动还是策略改动。

比较对象：

- A：现有 PromptBundle v1；
- B：WritingPolicyPack 编译后的最小策略集合。

固定：

- 同一故事输入；
- 同一模型和参数；
- 同一章节任务和上下文；
- 同一目标字数；
- 先用同一输入各运行一次；结果接近且仍无法裁决时，最多补到每组 2 次。

比较：

- 首段和完成时间；
- 输入/输出 token；
- schema 成功率；
- 小说逻辑指标和敏感场景合同结果；
- obligation/state/repetition 自动指标；
- 修订率；
- Provider 拒绝率。

采用 B 的条件：

- P0 小说逻辑和敏感场景合同不退化；
- 未激活能力零占用；
- 输入 token 或延迟有实质改善，或组合能力可靠性显著提高；
- 没有新增状态污染。

## 10. 失败归因

| 现象 | 首查 |
|---|---|
| 没有首段 | DNS/TLS、Provider open、模型排队、Prompt 大小、streaming |
| 有思考无正文 | 适配器事件映射、模型输出模式、max token、超时 |
| JSON 反复失败 | schema 复杂度、response format、示例、模型能力 |
| 章节慢 | Prompt token、计划调用、分析调用、续接、模型服务 |
| 重复剧情 | 义务/计划、召回、prohibitedRepetitions、上一章承接 |
| 系统/道具乱跳 | capability activation、state transition validator、证据映射 |
| 关系事件无后果 | obligation 和 relationship delta 是否进入下一章上下文 |
| 费用异常 | 重试、UNKNOWN、reservation、调用数和续接 |
| App 重启后重复请求 | lease、Attempt send evidence、recovery decision |

必须先用时序和权威状态定位，不靠主观猜测修改 Prompt。

## 11. 报告格式

R0 只记连接证据；R1～R3 合并成一份 Markdown 报告，不为每个 Gate 重复建报告：

- commit 和 APK hash；
- 环境；
- 样本 ID；
- 脱敏模型/目的地；
- 请求次数；
- 延迟分位数；
- token 和费用；
- 自动逻辑指标；
- 人工逻辑清单结果；
- 最高敏感度场景合同结果或 Provider 拒绝；
- 失败和修复；
- 是否通过；
- 未完成风险。

完整正文不进报告。需要举证时只引用短小、去身份、无密钥的片段。

## 12. 停止条件

立即停止真实测试并回到本地修复：

- Key 或正文进入日志/仓库；
- 未确认目的地仍能发送；
- 预算失败仍打开 Provider；
- 同一 Attempt 可能重复发送；
- 正式章节出现部分提交；
- 连续两次 schema 失败且修复策略相同；
- 正常章超过 10 分钟；
- 明确的 P0 状态污染；
- Provider 明确拒绝而 App 伪装为成功。

## 13. 完成定义

真实 API 阶段完成必须同时满足：

1. R0～R3 全部有证据；
2. 至少一个 3–5 章连续样本；
3. R2/R3 使用同一个组合能力样本；
4. 性能、小说逻辑、最高敏感度场景合同和费用有报告；拒绝或限流若实际发生则如实记录，不为覆盖该分支主动付费造错；
5. 用户在物理设备上实际阅读；
6. secret/API 数据扫描通过；
7. 修复已进入 Git 并同步；
8. 未达到的指标被明确列为阻断或已接受风险，不能省略。
