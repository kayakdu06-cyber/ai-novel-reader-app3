# ADR-004：加密数据下的中文检索

- 状态：Accepted
- 日期：2026-08-01

## 决策

MVP 使用同一加密数据库内的 Room FTS 表，并配合确定性的实体别名、最近章节、硬事实和未解决伏笔多路召回。不在未加密文件中建立第二份正文索引。

## 验证内容

- SQLCipher 数据库中的 FTS4/FTS5 实际可用性。
- 中文无空格文本、人物别名、地点/物品和跨章伏笔的召回率。
- 1,000 章、10,000 章元数据规模下的索引大小和查询延迟。
- 编辑章节后的增量删除/重建和失效链。

## 退出标准

固定中文测试集的硬事实/实体查询召回率达到 95%，普通查询在中档设备目标 < 200ms。若不能达到，再评估受保护的 n-gram 表或本地向量检索；不得直接建立明文索引。

## M0.5 已验证结果

- 采用同一加密数据库内的 FTS4 派生索引；汉字以确定性 ASCII 单字/相邻双字 token 入库，查询长度大于 1 时只组合相邻双字，避免依赖 SQLite 对连续中文的分词行为。
- Android 35 x86_64 模拟器，10,000 条文档、20 个固定无空格中文查询：20/20 命中，夹具召回率 100%。
- 10,000 条批量插入约 1,335 ms；首次冷连接最慢查询约 388 ms；预热后查询中位约 1.45 ms、最慢约 2.37 ms。
- 最初的普通 JOIN 会诱导查询规划器先扫描整本书，热查询中位约 1.61 秒；改为先让 FTS 子查询产出 rowid、再回表取文档后解决。
- 编辑文档后 FTS 触发器同步更新，新增关键词可立即召回。

模拟器固定集已达到退出指标，且查询计划的数量级问题已被实际发现并修正，因此架构方向改为 `Accepted`。真实中文小说语料、物理中档设备、删除/失效链和多书并发仍是 TASK-060/061 与发布性能门禁；若真实集不能达到指标，再以新 ADR 评估替代 tokenizer 或本地向量检索，不能建立明文索引。
