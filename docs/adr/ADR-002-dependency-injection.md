# ADR-002：使用 Hilt 作为依赖注入框架

- 状态：Accepted
- 日期：2026-08-01

## 决策

织卷使用 Hilt，不使用 Koin，也不在业务代码中建立全局 Service Locator。

## 原因

- Hilt 与 Android 生命周期、ViewModel、Worker 和前台服务集成明确。
- 编译期依赖图比运行时字符串/动态定位更容易提前发现缺失绑定。
- 项目虽为单人使用，但连接适配器、加密存储、数据库、任务编排和测试替身较多，手工组装会快速变得脆弱。

## 约束

- 领域模型不依赖 Hilt 注解；注入只发生在应用组装边界。
- Provider adapter 通过接口集合注入，不在业务层按字符串查找单例。
- 单元测试可以直接构造对象，不强迫启动 Android/Hilt 容器。
- Hilt 版本在工程版本目录固定，升级需验证与 AGP/Kotlin/KSP 兼容。
