# 织卷产品需求文档（PRD）

## 1. 范围与默认假设

- 平台：Android 手机优先，原生 Kotlin + Jetpack Compose。
- 数据：本地优先，无应用业务后台。
- 网络：仅在调用用户配置的模型服务、检查模型列表或用户主动检查更新时使用。
- 用户：单用户；不做多身份权限系统。
- 首发语言：简体中文。
- 默认生成模式：先建立最小可行故事规划，尽快产出第一章，再在后台扩展后续计划和章节。

## 2. 核心需求

### PR-001 首次启动与傻瓜化 API 配置（P0）

系统应提供“选服务 → 填密钥 → 自动测试 → 选推荐模型”四步内的配置流程。默认测试只读取模型列表，不产生生成费用；低成本“完整验证”属于可选高级动作，不阻塞首次配置。

- 内置官方 OpenAI、Anthropic、Gemini、Ollama 和“OpenAI 兼容服务”。
- 中转站默认只要求基础地址与密钥；路径、协议、流式选项使用自动探测或推荐值。
- 测试必须区分：地址不可达、证书错误、鉴权失败、模型不存在、协议不兼容、余额/额度问题、服务端拒绝。
- 测试响应不写入小说库；诊断日志必须脱敏。
- 默认模型选择来自能力登记表；连接状态区分“基础已验证”“完整已验证”“尚未验证”，无法读取模型列表时允许手填模型，但不得假装已经验证。
- 完整验证只能在用户明确同意可能产生极少费用后发送一次固定通用探针，输出上限 16 token，不发送人物、设定、模板、正文或其他私人小说内容。
- 模型列表与可选完整验证共享 60 秒总时限；鉴权失败、额度失败和其他明确失败不得退化成“手填即可”，也不得自动重试。

验收：正确配置能在 60 秒内完成连通性测试；默认流程不触发付费生成；密钥不以明文出现在界面重开、日志、模板或备份中。

### PR-002 极简创建小说（P0）

默认创建页只展示：

1. “你想读一个什么故事？”自由输入；
2. 题材快捷选择；
3. 篇幅选择；
4. 隐蔽命名的呈现档位“留白 / 均衡 / 细写”；
5. 主按钮“开始织书”。

题材快捷选择只是降低输入成本。用户可以完全不选，直接在故事设想或高级自由输入中描述任意题材、背景、关系、机制、叙事结构和文风；原文必须保存并进入规划，未命中预设不能触发拒绝、丢弃或默认题材覆盖。

人物资料、关系、时代、视角、节奏、文风和呈现档位的内部细分维度放在“再补充一点”中，均可留空。首版高级区按“人物与关系 / 世界与背景 / 叙事与文风 / 希望保留 / 不想出现”五组自由输入，避免把用户变成填写专业表单的人；涉及亲密关系时可在人物组中直接写明相关人物均为 18 岁以上。内部强度维度由 TASK-035 的版本化映射承接，不在首版创建页增加专业参数入口。

高级区默认折叠，用户展开后应在旋转、Activity 重建以及临时进入连接管理再返回时保持展开状态和已经输入的内容。系统必须自动补齐留空项并标记推断来源；TASK-036 已把原始输入、标准化结果、推断来源和版本保存为不可变创建快照，只有该事务成功后才提示书已保存。

TASK-037 在本地保存成功后进入“开始前确认”。确认页必须按 `bookId` 重新读取不可变快照，只展示快照中的书名、篇幅下限/目标和模型 ID，不重新解释上一页表单。价格目录尚不可用时明确显示“费用暂时无法可靠估算”，不得显示 0 元或猜测金额；读取失败必须停在可返回的错误页。当前占位确认只锁定本次确认并说明尚未生成，不创建请求、不调用模型，也不允许绕过确认页进入生成。

验收：题材可跳过，篇幅默认中篇（最低 300 章），呈现默认均衡；只输入一句设想即可继续；所有自动推断均可在书籍详情中查看和修改。

### PR-003 常见题材快捷预设与开放组合（P1）

首发提供都市、言情、悬疑、玄幻、仙侠、科幻、末日、历史架空、职场、校园、无限流、轻小说、现实向等快捷预设。它们只是操作入口和可版本化模板，不是支持清单。快捷标签界面可以为清晰度限制“主选一个、辅选最多两个”，但用户自由描述和实际小说内容不受该数量或词表限制，可以包含任意题材、关系、机制、结构和风格组合；预设不能硬编码成生成白名单。

### PR-004 隐蔽但明确的呈现选项（P0）

面向用户采用：

- `留白`：关键场景更多靠转场、暗示和情绪余韵；
- `均衡`：情节与感官描写保持平衡；
- `细写`：更多篇幅落在过程、动作、心理和场景细节。

首版创建页只提供这三档，不提供第四个“自定义”入口。内部维度仍然完整建模，未来只有在确有使用证据时才在高级设置中开放；这避免为了专业参数增加默认操作。

内部维度至少拆为：亲密描写强度、冲突强度、血腥强度、语言强度、情绪压迫度、淡出倾向。外部名称不能导致实现含糊；所有维度必须可测试和记录版本。

`contentControlSchemaVersion=1` 的固定字段：

| 字段 | 值 | 含义 |
|---|---|---|
| `narrativeDetailLevel` | 0–4 | 总体过程、动作、心理和环境细节 |
| `intimacyDetailLevel` | 0–4 | 成年角色亲密场景的细节程度 |
| `conflictDetailLevel` | 0–4 | 威胁、冲突和暴力过程的叙述程度 |
| `graphicInjuryLevel` | 0–4 | 受伤后果和感官细节 |
| `languageIntensityLevel` | 0–4 | 粗粝、冒犯性语言的允许程度 |
| `emotionalPressureLevel` | 0–4 | 恐惧、羞耻、控制、压迫等情绪强度 |
| `fadePolicy` | PREFER/ALLOW/AVOID | 关键场景是否倾向淡出 |
| `allRelevantCharactersAdult` | true/false/unknown | 硬门禁，只允许 true 进入相关生成 |

预设映射：

| 外部档位 | 总体细节 | 亲密细节 | 淡出 | 其余维度 |
|---|---:|---:|---|---|
| 留白 | 2 | 1 | PREFER | 保持题材默认，不随档位自动加重暴力 |
| 均衡 | 3 | 2 | ALLOW | 保持题材默认 |
| 细写 | 4 | 4 | AVOID | 保持题材默认，不随档位自动加重暴力、血腥、语言或压迫 |

`presentationMappingSchemaVersion=1` 的映射先形成呈现指令；冲突、血腥、语言和情绪压迫四个维度明确标为继承题材基线，由创建标准化阶段解析成 0–4 的完整配置。三个档位都不得改变这四个题材维度，防止“细写”暗中等于“更暴力”。年龄门禁不由档位推断，始终在具体场景按参与人物重新判断。

映射控制“请求意图”，不表示外部模型一定接受或完全遵循；服务方拒绝仍按 PR-021 处理。

#### 细写档位的正文执行要求

`细写`不是“多用几个形容词”，也不是简单增加粗俗词汇。对计划内相关场景，只有当 `intimacyDetailLevel=4`、`fadePolicy=AVOID` 且相关人物成年人门禁为 `CONFIRMED_ADULTS` 时：

产品把“足够成人”定义为成熟向内容在用户选择的尺度内得到完整、具体、连续的叙事执行，而不是只贴成人标签、只写暧昧气氛或用粗俗词代替过程。验收看场景是否真正完成了计划内的动作—反应链和状态变化，不以某几个固定词是否出现作为判断标准。

- 场景必须按人物视角呈现连续的动作、可感知反应、空间位置、身体状态、语言/心理变化和事后余波；
- 不能把成熟向场景弱化为一般亲昵或含混暗示，也不能用转场、黑屏、醒来后、事后一笔带过或一句抽象总结代替章计划要求展开的关键过程；
- 前一动作造成的位置、衣着/物品、疲劳、伤势和情绪变化必须传递到下一动作与后续场景，不能无因复位；
- 细节强度服从人物、关系、情境和用户选择，不把“足够成人”错误实现为无差别脏话、器官清单或脱离剧情的重复堆叠；
- 场景仍必须改变关系、状态、风险或人物决策中的至少一项，不能成为可以整段删除而不影响小说的孤立插曲。

固定验收夹具中，由场景执行契约标为“必须展开”的关键过程节点覆盖率必须为 100%，淡出/转场/事后概述替代数必须为 0，空间或身体状态无因跳变等阻断级连续性错误必须为 0。该门槛只评价是否完整执行用户已经选择的成熟向尺度，不要求堆叠固定词汇，也不把普通文风差异误判为缺失。

身体与感官连续性由系统根据档位和成年人门禁自动启用，不新增默认页面操作。未知或未确认成年人时，相关场景执行策略必须返回阻断结果，不能把细节降级后偷偷继续。它进入版本化场景执行契约和正文质量检查；若模型或服务商拒绝，仍按 PR-021 如实处理，不通过提示词规避。

### PR-005 篇幅规划（P0）

- 短篇：最低 80 章，初始规划目标 80 章；
- 中篇：最低 300 章，初始规划目标 300 章，也是默认选择；
- 长篇：由用户填写目标章数，系统不代填固定默认值；必须填写 301–10,000 章；
- 三种模式均按卷、按章分阶段推进，不允许一次请求生成整本；
- `lengthPolicySchemaVersion=1` 必须随创建输入和快照保存，后续调整规则不能静默改变旧书。

章数是规划下限/目标，不是模型单次输出保证。短篇和中篇允许因故事完整性超过下限；长篇以用户目标为规划基准。系统按章动态调整剩余计划，费用确认必须按该章数重新估算，禁止用单次超长请求冒充长篇能力。

### PR-006 分阶段生成（P0）

生成顺序：输入标准化 → 故事种子 → 故事圣经 → 总纲 → 分卷/分章计划 → 章前上下文 → 章节草稿 → 结构化摘要 → 一致性检查 → 可读提交。

- 第一章可采用最小规划快车道，但在提交第二章前必须完成完整故事圣经和足够的后续规划。
- 每阶段写入检查点，拥有唯一任务标识和幂等键。
- 未完成流只能保存在草稿缓冲，不覆盖上一个可读版本。

### PR-007 边生成边阅读（P0）

- 章节一旦完成提交，书架、目录和阅读器立即可见。
- 正文流已经产生完整段落并写入加密草稿后，阅读器可显示明确标记的“生成中正文”；它不是正式章节，不进入后续上下文、模板、导出或搜索索引。
- 生成中正文只追加已完整解码的段落；未完成尾段单独显示生成状态。检查要求修订时显示“正在修整本章”，正式提交后按段落锚点恢复阅读位置，不把初稿静默冒充最终版。
- 正在生成的下一章显示状态和预计步骤，不在正文末尾滚动展示大量技术日志。
- 用户可在阅读时暂停、继续或停止全书任务。
- 暂停在发送前不得产生新请求；在途时先取消远程请求、保存加密草稿并结算本次用量，再反馈完成。继续只恢复排队，不因一次点击隐式重发。
- “停止”保留已完成章节、当前加密安全检查点和用量台账，取消所有未完成阶段；不删除书。
- “取消当前章”与全书停止分开：只取消当前 Attempt 并暂停在该章，等待用户继续或调整。

### PR-008 长篇记忆与一致性（P0）

每章完成后必须更新：章节摘要、人物状态、关系变化、地点/物品状态、时间线事件、已埋伏笔、已回收伏笔、禁改事实、文风指纹。章前按相关性和最近性组装上下文，并进行冲突检查。

检查采用“本地确定性规则优先、模型语义检查随后”的双层结构。模型只能报告结构化问题，不能在检查阶段直接覆盖正文；正文来源、成年人事实、人物/地点/物品/时间约束和严格场景过程均必须可复核。`BLOCKER/MAJOR` 阻止发布并交给有限修订，`MINOR` 不得被随意升级为阻断。

### PR-009 模板重开（P0）

每本书提供“按这套设定重新织一本”。默认复制创建快照、角色/世界观、题材、风格、节奏、篇幅和呈现偏好，重新生成书名、总纲和正文。

- 不复制旧正文、章节摘要、人物运行时状态、伏笔运行台账、请求日志和密钥。
- 新书保存所用模板的不可变快照、来源书和模板版本。
- 三个动作必须区分：模板新书、当前书分支、重试当前章。
- 高级动作“只沿用风格”清除故事专属人物和世界设定。

### PR-010 模板来源、分类与版本（P0）

模板来源：系统预设、用户创建、由书提取、由模板派生、外部导入。系统自动按题材、故事机制、氛围、节奏、篇幅、呈现、来源、时间和收藏归类，用户可修改展示分类而不破坏来源链。

### PR-011 章节编辑与派生数据失效（P0）

用户编辑已完成章节后：

- 原版本保留为本地快照；
- 从该章开始的摘要、人物状态、伏笔台账、检索索引和后续章上下文标记为过期；
- 系统重建受影响派生数据；
- 若后续章节已生成，提示“保留后续但可能不一致”或“从下一章重新生成”，默认不自动删除。

### PR-012 任务恢复与幂等（P0）

应用退出、网络断开、系统回收或接口超时后必须能恢复。恢复前先查询本地 Stage、Attempt、Usage、加密草稿和正式提交证据；适配器明确支持按请求 ID 查询时，只查询既有请求状态，不调用生成接口。

- 只有提供方明确证明原请求未执行，并且本地草稿可读且为空、没有已知用量、发送证据一致时，系统才可自动回队；
- 原请求仍在运行或查询暂时无结论时，保留原 Attempt，等待后续对账，不创建新 Attempt；
- 本地已有完整响应时只恢复校验/提交，不再次请求模型；
- 仅记录 RequestIntent、查询不受支持、查询超时，或提供方已完成但本地无输出时，均标记“结果未知”；
- “结果未知”必须由用户明确确认后才解除重试门禁，确认动作本身不联网，新请求仍需重新经过预算、租约和发送审计。

### PR-013 模型与服务切换（P0）

- API 配置称为“连接”；可配置多个连接但默认只显示一个当前连接。
- 每个生成阶段可引用推荐能力角色，如规划模型、写作模型、摘要模型，但默认使用同一个模型减少操作。
- 切换连接不修改历史章节，只影响未开始的任务。
- 保存实际使用的提供方、模型 ID、协议、参数与能力表版本，以便复现和诊断。

### PR-014 费用保护（P0）

- 首次开始中长篇前展示粗略用量范围，并明确“最终费用以服务商账单为准”。
- 提供单次任务、单本书和每日硬上限；到达上限自动暂停，不得自动换模型绕过。
- 记录每次请求的输入/输出用量、估算费用、币种、估价来源和是否为估算。
- 价格未知时按 token 限额工作并醒目标注“无法估价”。

### PR-015 本地书架与阅读器（P0）

书架展示封面、书名、最近阅读位置、已完成/计划章节数和生成状态。阅读器支持字号、行距、页边距、字体、暖色/深色背景、亮度跟随、滚动/分页、目录侧栏、章节进度和位置记忆。

### PR-016 本地隐私（P0）

- API 密钥使用 Android Keystore 包装的加密存储。
- 小说数据库和备份采用应用级加密方案；密钥、数据库、日志明确排除系统自动备份。
- 应用锁、生物识别解锁、`FLAG_SECURE` 和最近任务页遮挡已由用户明确取消，不进入开发和发布验收；设备被解锁或系统生成任务缩略图时，App 不提供额外屏幕级保护。
- 默认通知仅显示“章节已完成”，不显示书名或正文。

### PR-017 手动备份、恢复与导出（P0）

- 一键导出加密项目备份包，包含小说、模板、设置快照、任务状态和清单，但默认不含 API 密钥。
- 恢复前验证版本、哈希、空间和兼容性；先导入临时区，成功后原子替换。
- 支持 TXT、Markdown 导出；导出范围可选单章或全书。
- 自动提醒备份，但未经用户选择不得上传云端。

### PR-018 诊断与日志（P1）

提供“导出诊断包”：应用版本、设备/Android 版本、能力表、错误码和脱敏网络摘要。默认不含正文、模板内容、密钥、完整请求体和完整响应体；用户可明确勾选正文片段。

### PR-019 无障碍与中文排版（P1）

触摸目标、对比度、动态字体、TalkBack 标签、横竖屏恢复、中文标点避头尾和段落缩进应有测试。读者设置不能因为系统字体放大而无法退出。

### PR-020 版本升级与数据迁移（P0）

数据库只能执行已测试迁移。正式构建禁止破坏性回退清库。每次升级前创建内部恢复点；升级失败时保留旧库并给出恢复指引。

### PR-021 内容边界（P0）

- 相关角色必须在模板和生成上下文中明确为成年人。
- 年龄缺失或含糊时，系统先补明确成人设定；无法确认则不进入亲密内容生成。
- 对服务端的内容拒绝按 `POLICY_REFUSAL` 保存，不做自动提示词规避或无限重试。
- 用户可以降低呈现、修改设定或切换自己配置的服务；App 不声称切换后一定成功。

### PR-022 外部数据发送知情（P0）

“本地优先”不代表远程模型调用不发送内容。首次使用某个远程 host 生成小说前，系统必须用非技术语言说明：故事设定、必要的既有摘要/片段和本次任务会发送到该 host；处理、保留和计费受该服务条款约束，织卷无法代替服务商删除其已收到的数据。

- 连接测试只发送通用测试文本，不发送任何小说内容。
- 确认记录绑定规范化的 scheme、host、port 和协议；地址或重定向目标变化后必须重新确认。
- 书籍详情和连接详情可随时查看当前数据目的地。
- 导出为 TXT/Markdown 属于未加密明文文件，导出前提示由用户选择的目标位置负责保护。
- 不使用“完全离线”“绝不上传”等与当前远程连接事实冲突的表述；使用 Ollama 等本地连接时可明确显示“仅发送到该本地地址”。

验收：未确认的新远程 host 不能接收小说生成请求；连接测试仍可使用无私人内容的固定测试词。

## 3. 非功能需求

### NFR-001 数据可靠性（P0）

章节提交、用量台账和任务检查点使用同一原子事务或可证明的一致性补偿流程；崩溃不得产生“正文存在但费用/状态丢失”的孤儿记录。

### NFR-002 安全（P0）

只允许 HTTPS 远程连接；HTTP 仅可对用户明确配置的本机或局域网地址逐项放行。跨主机重定向不得携带 Authorization 或自定义密钥头。

### NFR-003 性能（P1）

万章规模目录首次可交互 < 1 秒（中档测试机、索引已建立）；普通章节打开 < 300ms；流式正文刷新节流，避免逐 token 重组整个 Compose 树。

### NFR-004 可维护性（P0）

提供方协议、能力表、提示模板和数据库结构均有独立版本。核心生成引擎不依赖具体厂商 SDK。

### NFR-005 可测试性（P0）

所有协议适配器可用录制夹具离线测试；时钟、随机数、网络、价格表和后台调度可替换；P0 状态转换有确定性测试。

### NFR-006 可用性（P1）

默认主流程不出现 token、SSE、NDJSON、上下文窗口等术语；诊断页才展示技术详情。

### NFR-007 可恢复（P0）

任何长任务最多损失当前未提交阶段的流式草稿，不得损失此前完成章节。备份恢复必须通过定期演练。

### NFR-008 章节生成响应（P0）

速度按“本地调度、首个完整段落、正文流结束、正式章节提交”分别测量，不用首段已显示掩盖正式章节过慢。固定 2,500–4,000 中文字符参考章和受支持推荐模型档案下，普通后续章首段 P95 ≤ 20 秒、正文结束 P95 ≤ 180 秒、正式提交 P95 ≤ 240 秒；第一章首段 P95 ≤ 90 秒、正式提交 P95 ≤ 300 秒。正常章达到 5 分钟必须进入慢服务安全处置，10 分钟仍未结束属于 P0 发布阻断。任意用户自填模型不做虚假速度保证，未通过基准的组合不得成为默认推荐。

## 4. 明确不接受的实现捷径

- 把所有提供方都当作完全一致的 OpenAI 接口。
- 把 API Key 存入普通 DataStore、数据库明文字段或模板 JSON。
- 用一个布尔值表示所有生成状态。
- 章节编辑后继续使用旧摘要而不标记过期。
- 通过 `fallbackToDestructiveMigration` 解决正式数据库迁移。
- 仅靠 Android 后台服务持续数十小时生成整书。
- 在无费用上限时自动无限重试。
- 把未结束的流式字符串直接覆盖正式章节。
- 用“已经显示一部分正文”掩盖整章检查和提交超过速度门槛。

## 5. 前台生成与低参与控制

- 用户点击开始后，App 可在系统允许时启动可感知的前台生成服务；服务启动不等于已经发出模型请求，联网前仍须经过预算、数据目的地、租约和发送审计。
- 持续通知默认不显示书名、人物、设定或正文，只提供暂停和停止。暂停/停止先写入本地任务，用户无需保持 App 打开。
- 系统收回长时前台执行额度时，App 自动保存“系统限时暂停”原因并退出服务；下次进入只需一次继续操作，不要求用户理解 Android 前台服务术语。
- 通知权限被拒绝不能让生成悄悄常驻；App 内必须仍能查看状态和暂停/停止，系统是否在通知抽屉显示由 Android 决定。
- 前台服务、WorkManager 和界面都不能各自维护另一套任务真状态，统一以 SQLCipher 中的 Job/Stage 为准。

## 6. 自动恢复与维护（P0）

- 用户不需要理解或手动运行“恢复任务”。正式版启动后自动检查一次，之后由 Android 在合适时间执行低频维护；正常状态不弹窗、不要求确认。
- 自动恢复只能处理能够由本地持久证据确定的安全动作：请求前双租约过期回队、已有请求的未知结果审计、到期暂停/停止安全点结算和受保护临时草稿清理。
- 维护执行器没有 Provider 生成接口、连接读取入口或发送许可。即使网络可用，也不得查询远端、创建 Attempt 或产生模型费用。
- 只要出现“请求可能已离开设备”“结果可能已经产生”“本地校验/提交证据不完整”等不确定现场，就保留数据并进入等待或需处理状态；不得以少操作为理由自动重发。
- 启动检查和周期维护均使用唯一任务名，重复打开 App 不会堆积相同工作；单次处理有界、临时失败有限重试，电量或存储不足时推迟非紧急周期维护。
- 自动化的产品目标是减少用户操作，不是隐去风险：只有无法证明不会重复请求时才要求用户参与，界面届时只给出一个推荐主动作。

## 7. Prompt Bundle v1 产品约束（P0）

- 一句话创建产生的不可变快照是生成规则唯一来源；绑定时不能重新猜测或偷偷修改用户已保存的篇幅、题材与呈现选择。
- 系统自动把硬规则、题材基线、呈现规则和当前阶段任务装配到稳定层级，默认不让用户逐阶段选择提示词或逐场确认。
- 用户没有填写新建虚构人物年龄时，可在故事种子/圣经阶段自动补明确成年年龄以减少操作；明确未成年、真实可识别人物或互相矛盾的年龄不能自动改写，相关场景必须在远程请求准备前阻断。
- `细写 + 避免淡出 + CONFIRMED_ADULTS` 自动进入章节计划、正文、检查和修订四个阶段；正文要求与 PR-004 的 100% 关键过程覆盖、0 淡出替代及身体/感官连续性一致。
- Prompt Bundle 只表达用户的创作要求，不保证外部模型接受，也不得用于伪装或绕过服务商拒绝。

## 8. 初始规划三阶段产品约束（P0）

- 用户点击一次开始后，系统应自动完成故事种子、故事圣经和全书总纲；正常路径不要求用户逐阶段确认、复制提示词或手动整理人物表。
- 三阶段必须顺序执行并分别保存安全点。后一步失败时保留已成功的前序结果，下次只从失败阶段恢复，不重复消费已经确认的阶段。
- 故事种子负责把一句设想变成稳定核心；故事圣经负责人物、世界规则和硬事实；全书总纲负责宏观节奏与完整章数覆盖。三者职责不得混成一次自由文本输出。
- 人物成人状态和年龄必须结构化且一致；涉及亲密角色时仅允许虚构且明确成年。用户未填写新建虚构人物年龄时可自动补足成年事实，明确冲突不能自动改写。
- 总纲覆盖目标必须等于创建快照：短篇至少 80 章、中篇至少 300 章、长篇为用户填写的 301–10,000 章。此处只形成宏观区间，不一次生成上千个逐章条目。
- 正常界面只展示“正在整理故事基础/人物世界/全书走向”等自然语言进度。schema、哈希、Stage 和 Attempt 留在诊断详情，不增加默认操作。

## 9. 分卷与逐章窗口产品约束（P0）

- 完成全书总纲后，系统只整理当前需要的一卷和最近 1–8 章，不要求用户决定规划多少章，也不把 300 或 10,000 章全部展开。
- 当前卷最多覆盖 40 章且不能跨越总纲宏观节拍；当前窗口固定最多 8 章。接近边界时自动缩短，不用用户计算。
- 当已规划内容只剩 3 章时，系统应在不打断阅读的前提下准备下一窗；自动调度未接入前，也必须暴露确定性的本地判断，不允许每次打开 App 都重复请求。
- 下一窗必须紧接上一窗，不漏章、不重叠；同一卷未结束时沿用卷身份，进入新节拍或超过卷边界时再建立新卷。
- 窗口只保存章节目标、冲突、转折、结果、钩子和连续性承接，不直接写正文；用户仍可边阅读已完成章节，后台逐步补充后续安全窗口。

## 10. 第一章快车道与第二章硬闸门（P1）

- 默认可自动使用第一章快车道，用户也可关闭；正常路径不增加“选哪种规划策略”等技术问题。
- 快车道只把首章前依赖缩小为已提交故事种子、最小人物表、核心世界规则、结局方向和固定第 1–3 章粗计划，不能跳过人物成年/虚构身份和应用硬规则。
- 最小包必须使用版本化结构化契约并与故事种子逐项一致，不得伪装成完整故事圣经、全书总纲或窗口计划。
- 第一章提交后自动生成完整故事圣经和总纲，且两者必须冻结第一章当前版本 ID 与内容 hash；规划冲突时调整后续规划，不静默覆盖已开放阅读的第一章。
- 打开第二章 Provider 连接前必须由持久事实证明：当前圣经、当前总纲、覆盖第二章的窗口、第一章当前版本和快车道适配绑定均有效。正式提交第二章时再次复核。
- 完整规划模式不走最小包；第一章也必须等待圣经、总纲和首窗。两种模式最终共享同一套第二章及后续门禁。

## 11. 章前上下文预算产品约束（P0）

- 每章正式计划前由本地自动组装上下文，正常用户不选择记忆条数、不计算 token，也不逐项确认材料。
- 应用硬规则、阶段任务、写作与呈现要求、人物成年/虚构身份、世界规则、禁改事实、目标卷章计划，以及第二章起的上一章摘要属于必需事实；已经存在的当前状态、到期伏笔和本次用户补充同样不得被普通裁剪。
- 必需事实必须整项保留，不允许截成半句话或只保留人物事实的一部分。容量不足时在联网前停止，并只提供一个优先建议，例如改用上下文更大的模型或降低本次输出上限。
- 主题、较旧摘要、历史事件/时间线、未到期伏笔和远期规划按稳定优先级整项选入或省略；系统记录省略项及原因，不能悄悄改变故事事实。
- 未确认模型上下文容量时默认不能生成。只有用户明确确认继续，才可采用保守容量值；仍不得突破费用、token 和目的地门禁。
- 成功组装形成不可变上下文快照。真正打开 Provider 前必须再次验证圣经、总纲/窗口、上一章版本和 Prompt Bundle 来源；来源变化时旧快照失效并重新本地组装，不发送陈旧内容。
- 上下文组装是纯本地阶段，不创建远程请求记录，不产生 token 或费用；其失败不会伪装成模型失败。

## 12. 章节正文与有限续接产品约束（P0）

- 章节正文阶段使用固定的 `chapter-draft.v1` 输出契约。模型只返回一个 `body` 字段，App 在本地增量解码后只保存正文，不把 JSON 外壳、解释、标题或 Markdown 混进小说。
- 正常用户只需开始一次。模型达到单次输出上限时，系统保存已完成正文并自动续接，不要求用户复制末段、拼接文本或逐次确认。
- 每次续接必须建立新的请求 Attempt、独立用量记录和受保护草稿；新草稿先复制已经验证的累计正文，再要求模型原样返回 96 码点尾部锚点用于精确校验。锚点只校验一次，不重复写入正文。
- 自动续接最多 3 次，且不得绕过单次、单书、每日费用/token 上限或 Stage attempt 上限。达到任一上限、累计正文超过 4 MiB、返回空/过短、结构无效或锚点不匹配时，保存现场并进入需要处理状态。
- 不能用模糊相似度猜测拼接点。无法证明连续时宁可停止并保留草稿，也不能静默删段、重段或拼错章节。
- Provider 正常 `STOP` 仅表示正文流完整，后续仍须经过摘要/事实提取、一致性检查、有限修订和正式章节提交，才能开放为正式可读章节。
- 如果进程在“已保存响应终态、尚未完成续接结算”之间退出，恢复器只依据本地持久证据完成结算，不重新访问 Provider，不产生第二笔请求。
- TASK-055 已完成上述底层链路和本地假 Provider 验证；开始前确认页、真实预算/目的地许可、整章流水线和边生成边阅读界面仍由后续任务接通。

## 13. 章节记忆提取产品约束（P0）

- 正文冻结后自动提取章节摘要、人物状态事件和故事事实，不让用户手工填写、逐项审核或选择提取器。
- 结果必须绑定最终章节版本 ID、正文 hash、章节 ID 和序号。正文被修订或当前版本变化后，旧结果不得继续影响后文。
- 人物事件必须覆盖会影响下一章的位置、身体、情绪、目标、知识、关系、持有物、承诺与秘密；涉及高强度场景时不能用空泛概述抹掉实际后果和余波。
- 模型不得创建未知实体、修改年龄/成年人状态/真实人物标记或把推断升级为硬设定。结构错误最多自动修复一次。
- TASK-056 已完成契约、严格校验、确定性映射和正式版本记忆重建闭环；TASK-058 已完成候选正文一致性/呈现检查。修订后重提取与正文原子提交仍由 TASK-059 完成。

## 14. 时间线与伏笔自动投影产品约束（P1）

- 章节记忆完成后，系统自动整理正文中真实发生的关键事件以及伏笔的埋设、发展、回收或明确废弃，不要求用户维护表格或逐条确认。
- 时间线不能把计划、比喻、猜测或尚未发生的内容当成事实；人物和地点只能引用故事圣经中已有实体。
- 新伏笔必须是本章已经出现的具体线索，不能把每个未解问题都登记成伏笔。既有伏笔只能沿允许的状态路径变化，并保留每次变化来自哪一章、哪个版本和哪次生成。
- “废弃”不是模型不想写就删除：只有正文已明确使原安排不可能、且没有完成回收时才能使用；不确定时保持原状态。
- 正文版本、章节记忆、既有伏笔或人物集合变化后，旧投影不能联网、落库或继续供后文使用。旧章节编辑引起的跨章重建必须按章节顺序完成。
- TASK-057 已完成正式版本重建底层闭环。普通候选正文只有在 TASK-059 与正文、章节记忆、检查结果一起原子提交后，才成为正式可用的时间线与伏笔状态。

## 15. 一致性与呈现检查产品约束（P0）

- 普通用户不增加检查选项或逐场确认。系统从冻结的创建快照、场景执行契约和故事状态自动决定检查模式。
- 本地规则先检查来源、基本可读性、人物/成年人事实、离场状态、地点移动、物品归属、时间顺序和计划必需事件；出现 blocker/major 时不产生模型检查费用。
- 模型检查覆盖硬事实、视角知识、动机因果、关系/语气、伏笔、动作—反应、空间、身体状态、感官、过程、淡出替代和相关余波；输出不得包含续写、改写稿或正文摘录。
