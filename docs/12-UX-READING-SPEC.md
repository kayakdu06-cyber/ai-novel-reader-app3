# 织卷体验、阅读器与视觉基线

## 1. 体验原则

织卷的核心不是让用户“操作 AI”，而是让用户尽快开始读一本符合设想的书。默认体验遵循：

- 一屏只处理一个主要决定；
- 推荐值先给出，原因可点开；
- AI 在背后补全信息，不用表单审讯用户；
- 高级功能按需浮现，不常驻主流程；
- 错误页直接给“下一步做什么”；
- 生成状态融入书架、目录和正文末尾，不破坏沉浸。

## 2. 减少参与的具体规则

| 场景 | 默认自动做 | 仅在必要时问用户 |
|---|---|---|
| 创建书 | 补人物名、配角、世界细节、基本冲突 | 用户输入自相矛盾或成人状态不明且相关 |
| 选模型 | 当前连接中选推荐模型 | 模型不存在、能力不足或费用上限无法满足 |
| 规划 | 生成故事圣经、总纲、章节计划 | 用户主动开启“先看规划” |
| 续写 | 在预算内自动生成下一章 | 达上限、策略拒绝、结果未知、严重冲突 |
| 质量 | 标准档自动检查一次 | 多次修订仍失败 |
| 模板重开 | 自动提取、归类、保存来源 | 用户只需可选写“这次想改什么” |
| 备份 | 定期提醒、自动自检 | 选择保存位置与备份口令 |

任何“自动”都要可在书籍详情或设置中找到结果和关闭方式。

## 3. 内容呈现命名

面向用户：

- `留白`：关键场景更克制，更多依靠转场和余韵；
- `均衡`：情节推进和场景过程兼顾；
- `细写`：更多动作、心理、环境与过程细节；
不要在书架卡、通知和最近任务页展示直白内容标签。模板分类页也只显示这三个名称。内部仍用精确字段，确保产品命名克制不等于功能含糊；首版不提供第四个自定义入口。

### 4.4 TASK-031 连接向导实现基线

### 4.5 TASK-032 连接管理实现基线

- 有保存连接时再次启动不重复首次说明，并直接进入极简创作页；“模型连接”保留为创作页和后续设置中的管理入口；当前连接在管理页固定排在最前并使用浅赭容器、边框和“当前”文字三重标识；
- 顶部只有一个“添加新连接”主动作；非当前连接提供“设为当前”，其余操作收进“编辑”，减少默认页面按钮密度；
- 卡片只展示名称、模型、host、验证状态和 `••••尾四位`，绝不显示原始密钥或 `secretRefId`；
- 普通编辑只改名称和已发现模型。更换地址或密钥采用“新增并验证成功，再删除旧连接”，避免一次误改破坏唯一可用连接；
- 删除必须二次确认，明确同时撤销密钥但不删除小说；删除当前连接时自动选择确定性后备连接；
- 列表使用有界宽度 LazyColumn、safe drawing inset、48/56dp 触摸目标，并通过 200% 字号、横屏和 API 30/35 验证。

### 4.6 TASK-033 极简创建实现基线

## 7. 阅读排版

默认建议：

- 竖屏正文左右边距 20–24dp；
- 字号约 18sp 起步，随系统字体和用户设置缩放；
- 行高为字号的 1.55–1.75 倍；
- 中文段首缩进 2em，可关闭；
- 段间距与缩进不同时过强；
- 标题与正文留足距离；
- 中文标点避免孤立在行首/行尾的基础排版优化；
- 记忆阅读位置采用章节 ID + 字符偏移/段落锚点，字体变化后可近似恢复。

分页模式需要用真实中文长段落、对话、引号、破折号和省略号测试。MVP 可以先提供稳定滚动和基础分页，不能为动画牺牲位置可靠性。

## 8. 阅读交互

- 点击屏幕中部：显示/隐藏工具层；
- 左右区域：分页模式翻页；滚动模式不抢占系统返回手势；
- 横向滑动打开目录需避免与系统边缘返回冲突；
- 音量键翻页为可选，默认关闭；
- 长按选文、复制等系统能力 P1；
- 当前章生成候选完成时不自动跳转，避免打断阅读；
- 读到已生成末尾后出现“下一章正在织 / 已暂停原因 / 继续生成”之一。

## 9. 生成状态文案

用户可见阶段：

| 内部阶段 | 用户文案 |
|---|---|
| BUILD_STORY_SEED/BIBLE | 正在整理故事设定 |
| BUILD_OUTLINE/PLAN | 正在安排后面的故事 |
| DRAFT_CHAPTER | 正在织第 N 章 |
| CHECK/REVISE | 正在检查第 N 章 |
| BUDGET_EXCEEDED | 已暂停：达到你设置的用量上限 |
| POLICY_REFUSAL | 当前模型没有完成这一章，需要你调整设定或连接 |
| NETWORK_OFFLINE | 等待网络恢复 |
| UNKNOWN_RESULT | 本次结果无法确认，为避免重复费用已暂停 |

默认文案不展示 HTTP、SSE、token 等术语；“查看详情”进入诊断说明。

## 10. 可访问性

- 常规触摸目标至少 48dp；
- 图标按钮均有中文语义标签；

## 12. M0.7 长内容实现基线

本节是性能实现约束，不是正式视觉稿：

- 单章正文按稳定段落锚点拆分并使用惰性列表，只组合视口附近段落；不得把 20 万字正文作为一个巨型 `Text` 常驻布局。
- 目录使用基于数量的惰性行、稳定 key 和稳定 content type；1 万章时不得一次实例化全部行。
- 远距离跳章直接定位目标项，不播放跨越数千行的滚动动画。
- 阅读位置保存为章节 ID + 段落锚点 + 段内偏移；不要保存只能在当前字体和屏幕尺寸下成立的像素坐标。
- 正式数据接入后，段落切分和索引准备放到非主线程，并以不可变结果缓存；正文版本变化时才重建。
- 当前章不能只靠颜色区分；至少同时使用字重、语义选中状态或明确文字。可点击目录行的触摸高度至少 48dp。
- 必须继续覆盖窄竖屏、横屏、系统字体放大、深色模式和 TalkBack；M0.7 已验证前两项夹具可挂载，后四项仍属于正式阅读器验收。

Android 35 x86_64 Debug 模拟器夹具结果：20 万字/2,000 段仅组合 4 个可见段落，末段直接定位约 95.84 ms；1 万章目录仅组合 13 行，末章直接定位约 146.90 ms 并可点击。该结果只证明架构方向可行；正式版本仍需 Macrobenchmark、帧耗时/jank 和物理中档设备验证。
