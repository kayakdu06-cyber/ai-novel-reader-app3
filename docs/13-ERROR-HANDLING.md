# 织卷错误与恢复设计

## 1. 原则

每个错误必须回答：发生了什么、是否损失内容/可能产生费用、系统已经做了什么、用户下一步能做什么。主界面只给一个首选动作，详情页再展示错误码和技术信息。

## 2. 错误分层

| 层 | 示例 | 责任 |
|---|---|---|
| 输入 | URL 无效、人物设定冲突 | 创建/设置页就地修复 |
| 连接 | 无网、DNS、TLS、鉴权 | 适配层标准化，连接页修复 |
| 能力 | 模型不存在、不支持流/结构化 | 能力表降级或用户选模型 |
| 服务 | 429、过载、额度不足 | 有限重试或暂停 |
| 内容 | 策略拒绝、格式无效、输出截断 | 调整/修复/续接，不冒充成功 |
| 生成 | 连续性 blocker、上下文超限 | 重组上下文或暂停 |
| 本地 | 空间不足、数据库错误 | 停止写入，保护旧数据 |
| 生命周期 | 进程被杀、FGS 超时 | 检查点恢复 |
| 备份/迁移 | 哈希错、口令错、schema 不兼容 | 不覆盖当前数据 |

## 3. 用户消息模板

```text
标题：这一章没有完成
说明：当前连接在生成中途断开，已完成章节没有受影响。
费用：服务商可能已经计算了这次请求的部分用量。
主动作：重新连接后继续
次动作：查看详情
错误码：STREAM_INTERRUPTED
```

禁止文案：“未知错误”“生成失败，请重试”作为唯一信息。

## 4. 网络和服务错误

| 错误 | 主文案 | 主动作 | 系统行为 |
|---|---|---|---|
| 无网络 | 等待网络恢复 | 打开网络设置/稍后继续 | 不消耗重试次数 |
| DNS 失败 | 找不到这个服务地址 | 检查地址 | 有限退避 |
| TLS 失败 | 连接无法安全建立 | 检查服务证书/地址 | 不允许跳过验证 |
| 鉴权失败 | 密钥未通过验证 | 重新填写密钥 | 立即停止自动重试 |
| 本地凭据不可用 | 手机暂时无法读取这个密钥 | 解锁/重新保存密钥 | 请求不发出，不误报服务商拒绝 |
| 模型不存在 | 当前服务没有这个模型 | 重新获取模型 | 保留其他连接设置 |
| 429 | 服务请求过多 | 等待后继续 | 遵循 Retry-After，受总时限限制 |
| 余额不足 | 服务额度不足 | 前往对应服务检查 | 暂停全书，不换模型绕过 |
| 服务过载 | 服务暂时忙 | 自动稍后继续 | 有限次数和预算 |
| 策略拒绝 | 当前模型没有完成这一章 | 调整设定或连接 | 不自动规避/无限重试 |

## 5. 生成错误

### 5.1 格式无效

结构化阶段第一次且可修复的失败，使用不含原始创作提示的小型格式修复请求；再次失败暂停，并允许更换模型或由用户明确重试。空输出、无效 UTF-8、超出字节/解析资源上限或没有剩余 attempt 名额时不自动修复，直接暂停。修复次数写在持久 Attempt 链中，重启后不会清零。正文生成的格式问题不能用猜测解析成故事状态。

### 5.2 上下文过大

按既定裁剪顺序重新组装一次，保留硬事实和本章计划。若仍过大，建议换支持更长上下文的模型或降低记忆窗口，不擅自删除圣经硬规则。

### 5.3 输出截断

正文终态为 `LENGTH` 时，先原子保存累计正文、输出 hash、截断分类和本次用量，再使用 96 码点精确尾锚点续接。锚点必须逐码点一致，只校验不重复写入；禁止用模糊相似度猜测拼接点。最多自动续接 3 次，同时受 Stage attempt、4 MiB 累计正文和费用/token 硬上限约束。达到限制或无法证明连续时保存草稿并进入需要处理；默认界面只给一个推荐动作，其他动作放在详情中。

### 5.4 一致性失败

自动修订达到上限后，不继续循环。展示最关键的 1–3 个冲突；用户可接受当前章、重试或编辑设定。若违反硬性成人状态和应用内容边界，不提供“仍然提交”。

## 6. 结果未知

网络超时可能发生在服务端已经完成之后，甚至可能发生在“联网许可已交给执行器、请求已离开设备、Started 尚未写回数据库”的窗口。因此仅有 RequestIntent 也不能推导“没有发送”。

| 恢复证据 | 系统动作 | 用户参与 |
|---|---|---|
| 本地已有完整响应 | 恢复校验/提交，不联网 | 无 |
| 提供方确认原请求仍运行或查询无结论 | 保留原 Attempt 和临时 usage，等待对账 | 默认无 |
| 提供方明确确认未执行，且草稿为空、无已知 usage、发送证据一致 | 自动回队，不立即联网 | 无 |
| 提供方完成但本地无输出 | 最终结算已知 usage，标记结果未知 | 确认是否重新尝试 |
| 查询不支持/超时/报错、仅有 RequestIntent、草稿不可读或证据矛盾 | 标记结果未知并保留草稿/usage | 确认是否重新尝试 |

用户确认只解除持久门禁，不直接创建请求。新执行器领取后才创建新 attempt，并重新检查预算与目的地授权；旧 attempt 永久保留为来源。两个并发确认最多一个成功。界面说明“原请求可能已产生费用”，但不展示提供方原始错误正文。

### 6.1 主动控制与取消失败

- Provider 远程取消不支持或调用失败时，仍完成本地安全点并标记取消结果；这不能证明服务端没有继续产生费用，因此 Usage 未知值保持 UNKNOWN，不伪装为 0。
- 暂停/停止提交后，父 Job 门禁立即禁止新 Provider open、发送标记和流开始标记；已 claim 的执行器在调用 Provider 前仍会再次读控制意图。
- 进程在控制已持久但安全点未完成时退出，不清除 RequestIntent 或草稿；租约到期后恢复入口可代为取消 Attempt 和结算未知 Usage，不能盲目重发。
- 校验/提交与停止竞争时以数据库事务顺序为准：控制先赢则本地提交失败并回滚；提交先赢则保留已完成章，再取消后续 Stage。

## 7. 本地存储错误

- 空间预警：不足以完成当前章时不发新请求。
- 写入失败：临时草稿保留，正式章节指针不变。
- 数据库完整性失败：进入只读模式，禁止自动迁移/生成，优先备份诊断。
- Keystore 失效：锁定 secrets 和正文解密入口，提供恢复备份说明，不删除数据。
- 恢复点写入失败：禁止继续数据库升级。

## 8. 备份错误

| 情况 | 行为 |
|---|---|
| 口令错误 | 不解密、不覆盖；可重试，限制高速尝试 |
| manifest 损坏 | 拒绝导入，当前数据不变 |
| 哈希不匹配 | 拒绝导入，列出损坏部分 |
| 格式版本过新 | 提示升级织卷，不尝试猜测导入 |
| 空间不足 | 在解密前尽早检测，清理临时文件 |
| 迁移失败 | 删除临时导入库，保留当前库和原备份包 |
| 原子切换失败 | 回到旧库，记录迁移审计 |

## 9. 自动重试预算

默认：

- 网络/5xx：最多 3 次；
- 429：最多 3 次且总等待不超过 15 分钟；
- 格式修复：1 次；
- 上下文缩减：1 次；
- 正文续接：所有篇幅最多自动续接 3 次；每次都是独立请求与用量，且不得绕过 Stage attempt、4 MiB 累计正文和费用/token 硬上限；
- 一致性自动修订：标准档 1 次、细致档 2 次；
- 策略拒绝、鉴权、余额、预算、结果未知：0 次。

重试次数是默认上限，任何时候都受剩余 token/费用上限约束。

## 10. 错误记录

记录：标准错误码、阶段/attempt、时间、HTTP 状态、适配器版本、是否可重试、用户动作、脱敏摘要。默认不记录：密钥、Authorization、URL query、完整提示、完整响应、正文片段、真实书名。

## 11. 故障注入验收

测试必须能人工触发：首字节前断网、流一半断网、服务端已处理但客户端超时、重复 SSE 事件、未知事件、usage 晚到、数据库提交前崩溃、提交后 UI 前崩溃、存储写满、Keystore 不可用、FGS timeout、备份包尾部损坏和迁移中断。

## 12. TASK-023 Chat Compatible 错误映射

| 服务端证据 | 标准结果 | 说明 |
|---|---|---|
| 401/403 或明确鉴权 code/type | `AUTH_FAILED` | 不回显服务端 message |
| 402 或余额/配额 code/type | `QUOTA_EXHAUSTED` | 兼容 DeepSeek 的余额不足状态 |
| 429 或 rate-limit code/type | `RATE_LIMITED` | 接受非负秒数或 RFC 1123 HTTP-date 的 `Retry-After`，单次上限 24 小时 |
| 500/502/503/504 或资源不足终态 | `SERVER_OVERLOADED` | 后续由统一重试预算决定是否重试 |
| model-not-found code/type | `MODEL_NOT_FOUND` | 先于通用 404 协议错误判断 |
| context-length code/type | `CONTEXT_TOO_LARGE` | 只使用结构化 code/type，不解析可能含隐私的 message |
| content-filter/safety/policy code/type | `POLICY_REFUSAL` | 流内 `content_filter` 产生 `Refused(SAFETY)` |
| 不支持字段、非法 schema、400/404/405/415/422 | `PROTOCOL_MISMATCH` | 不改用宽松猜测或静默删字段 |
| 缺失 `[DONE]`、读流 I/O 中断 | `STREAM_INTERRUPTED` | 即使已经收到正文和 finish reason 也不假装完成 |
| 其他 HTTP 状态 | `UNKNOWN_RESULT` | 防止自动重发可能已经执行的付费请求 |

适配器会先发 `Started`，再发送增量/usage，最后只允许一个 `Completed/Refused/Failed`。取消协程时关闭在途调用并重新抛出取消信号，不把主动取消误报为网络故障。`Retry-After` 的秒数和 HTTP-date 由统一解析器处理；非法值、负数、控制字符和无法解析的日期不会进入重试调度。

## 13. TASK-022 Responses 终态与错误映射

| Responses 证据 | 标准结果 | 说明 |
|---|---|---|
| `response.completed` | `Completed(STOP)` | 唯一正常提交证据，usage 先发出 |
| `response.incomplete` + `max_output_tokens` | `Completed(LENGTH)` | 保留已收正文，交给后续续写策略 |
| `response.incomplete` + `content_filter` | `Refused(SAFETY)` | 拒绝文案有界保存，不伪装成断网 |
| `response.failed` + `server_error` | `SERVER_OVERLOADED` | 不传播服务商 message |
| SSE `error` | 按结构化 code/type 映射 | 未识别 code 为 `UNKNOWN_RESULT` |
| 401/403、402、429、5xx | 与统一 HTTP 映射一致 | 秒数或 HTTP-date `Retry-After` 统一解析，单值上限 24 小时 |
| 事件名/type 冲突、非法 JSON/usage、重复或倒序 sequence | `PROTOCOL_MISMATCH` | 失败关闭，不重复正文 |
| EOF 前没有语义终态 | `STREAM_INTERRUPTED` | 不把半章提交成完成章节 |
| 未知 `incomplete_details.reason` | `UNKNOWN_RESULT` | 为未来新增终态保持失败保守 |

Responses 不以 `[DONE]` 作为终止证据。新增的非终态事件可忽略；如果未来新增了本实现不认识的终态，连接结束时仍会失败，而不会乐观提交。

## 14. TASK-024 Anthropic 终态与错误映射

| Anthropic 证据 | 标准结果 | 说明 |
|---|---|---|
| `end_turn` / `stop_sequence` + `message_stop` | `Completed(STOP)` | 自然完成或指定停词 |
| `max_tokens` + `message_stop` | `Completed(LENGTH)` | 保留正文，后续续写 |
| `tool_use` + `message_stop` | `Completed(TOOL_CALL)` | 当前小说请求不主动提供工具 |
| `refusal` + `message_stop` | `Refused(POLICY)` | 有界保留 stop_details explanation |
| `model_context_window_exceeded` | `CONTEXT_TOO_LARGE` | 不提交成功章节 |
| `pause_turn` / 未知 stop reason | `UNKNOWN_RESULT` | 后续需要专门续回合策略，当前不冒充成功 |
| SSE `overloaded_error` | `SERVER_OVERLOADED` | 对应非流 HTTP 529 |
| 401/403、402、413、429、500/504/529 | AUTH、QUOTA、CONTEXT、RATE、OVERLOADED | 不解析或回显 message |
| 缺失 `message_stop` | `STREAM_INTERRUPTED` | 即使已有正文和累计 usage |
| block 生命周期或 event/type 冲突 | `PROTOCOL_MISMATCH` | 防止正文错序和类型污染 |

HTTP 400 `invalid_request_error` 与 404 `not_found_error` 当前保守归入 `PROTOCOL_MISMATCH`；精细区分模型不存在、参数能力和端点配置留给 TASK-028 的跨协议错误矩阵。

## 15. TASK-025 Gemini 终态与错误映射

| Gemini 证据 | 标准结果 | 说明 |
|---|---|---|
| `STOP` | `Completed(STOP)` | 有 functionCall 时改为 `TOOL_CALL` |
| `MAX_TOKENS` | `Completed(LENGTH)` | 保留已生成正文，交由续写策略处理 |
| `SAFETY` / `IMAGE_SAFETY` / `SPII` | `Refused(SAFETY)` | 不回显远端 finishMessage |
| `RECITATION` / `BLOCKLIST` / `PROHIBITED_CONTENT` / `ESCALATION` | `Refused(POLICY)` | 明确不是网络错误 |
| `LANGUAGE` / `NO_IMAGE` / `IMAGE_OTHER` | `Refused(UNSUPPORTED_REQUEST)` | 当前文本小说请求不能把它当成功 |
| `MALFORMED_FUNCTION_CALL` / `MISSING_THOUGHT_SIGNATURE` / `MALFORMED_RESPONSE` | `PROTOCOL_MISMATCH` | 响应不能可靠提交 |
| `OTHER` / 未知 finish reason | `UNKNOWN_RESULT` | 未来枚举不乐观放行 |
| prompt `SAFETY` / `BLOCKLIST` / `PROHIBITED_CONTENT` | 对应 Safety/Policy Refused | prompt 被拦截时官方不返回 candidates |
| 401/403、404、413、429、500/502/503/504 | AUTH、MODEL、CONTEXT、RATE、OVERLOADED | 只依赖状态和结构化 status，不传播 message |
| EOF 前没有 finish reason | `STREAM_INTERRUPTED` | 即使已经收到正文或 usage |

`RESOURCE_EXHAUSTED` 只有同时存在有效 `Retry-After` 时才按 `RATE_LIMITED` 处理；缺少重试时间证据时保守归入 `QUOTA_EXHAUSTED`，防止把日配额或账单耗尽误当作短暂限流循环重试。Google 官方说明 500 也可能由上下文过长触发，但仅凭状态码无法安全区分，因此不解析错误 message 猜测，保守归入服务端暂时失败。

## 16. TASK-027 能力证据失败处理

| 情况 | 处理 | 不允许的推断 |
|---|---|---|
| 能力存储不可读或读取抛错 | 使用内置基线；没有基线则全项 `UNKNOWN` | 不因读取失败放行字段 |
| 记录过期或适配器版本变化 | 忽略该来源并等待后续刷新 | 不继续沿用“曾经成功” |
| 地址变化 | 新端点指纹不命中旧记录 | 不把另一中转站能力复制过来 |
| 网络/鉴权/额度/超时导致探测失败 | 保持 `INCONCLUSIVE → UNKNOWN` | 不记为 `UNSUPPORTED` |
| 服务端明确拒绝某个试探字段 | 可在有界有效期内记 `EXPLICITLY_UNSUPPORTED` | 不扩大到其他字段或其他模型 |
| 持久化枚举、时间或流格式损坏 | 丢弃损坏来源，继续保守解析 | 不崩溃、不猜测修复 |
| 用户覆盖未确认风险或确认时间在未来 | 拒绝保存 | 不静默替用户确认 |
| 用户点击恢复自动 | 只删除该模型的用户覆盖来源 | 不删除官方/探测/内置证据 |

能力登记失败本身不是网络错误，也不应自动重试付费请求。请求若包含当前解析结果未明确支持的可选字段，仍在联网前以 `PROTOCOL_MISMATCH` 失败；连接页后续应把它翻译为“此模型尚未验证该选项”，而不是显示底层异常。

## 17. TASK-028 请求证据与统一重试策略

标准错误码本身不足以决定是否重发。每次失败还必须携带请求送达证据：

| 请求状态 | 含义 | 默认风险处理 |
|---|---|---|
| `NOT_SENT` | 已确认请求没有离开本机 | 可等待网络或执行有界重试，不标记外部费用风险 |
| `PROVIDER_REJECTED` | 收到服务端明确失败响应 | 只有限流/过载等白名单错误可有限重试 |
| `RESPONSE_STARTED` | 已收到响应头或流已经开始 | 认为可能产生费用；正文已出现时禁止自动重放 |
| `RESULT_UNKNOWN` | 无法确认服务端是否执行 | 先查询既有请求；只有证明未执行才自动回队，否则提示重复费用风险并等待用户确认 |

13 类远程失败采用固定决策矩阵：

| 类别 | 自动处理 |
|---|---|
| 无网 | 仅 `NOT_SENT` 时等待网络恢复，不消耗重试次数 |
| DNS | 仅 `NOT_SENT` 时有限退避 |
| TLS | 停止，不绕过证书校验 |
| 鉴权 | 停止，要求修复密钥 |
| 模型不存在 | 停止，返回连接/模型选择 |
| 协议不匹配 | 停止，修复地址或协议 |
| 限流 | 仅服务端明确拒绝且尚无正文时有限重试 |
| 额度耗尽 | 停止，不换模型绕过 |
| 服务过载 | 仅服务端明确拒绝且尚无正文时有限重试 |
| 策略拒绝 | 停止，不自动规避或循环改写 |
| 上下文过大 | 仅执行一次既定上下文缩减 |
| 流中断 | 未收到正文可有限重连但明确标记可能已计费；收到正文后要求用户确认 |
| 结果未知 | 仅在 Provider 明确证明未执行且本地证据一致时自动回队；否则用户确认前不重发 |

此外，`FORMAT_INVALID` 只允许一次格式修复，`OUTPUT_TRUNCATED` 进入专用续写而不是原请求重放。自动重试最多 3 次，总等待预算最多 15 分钟；采用带抖动的指数退避，合法 `Retry-After` 是最小等待时间。任何自动动作仍受请求/单书/每日预算约束，预算耗尽立即转为 `BUDGET_EXCEEDED`。

## 18. TASK-029 连接测试部分成功与失败

| 情况 | 返回状态 | 是否可保存连接 | 是否再发请求 |
|---|---|---:|---:|
| 模型列表成功，未做完整验证 | 基础已验证；所选模型为 `LISTED` | 是 | 否 |
| 列表端点被服务端明确拒绝为不存在/不兼容，已手填模型 | 尚未验证；`UNVERIFIED_MANUAL` | 是 | 否 |
| 同上但未手填模型 | 需要手填模型 | 否 | 否 |
| 鉴权、额度、网络、TLS 或未知失败 | 原标准错误 | 否 | 0 次自动重试 |
| 所选模型不在成功列表中 | `MODEL_NOT_FOUND / NOT_SENT` | 否 | 不发送生成探针 |
| 完整验证没有明确费用确认 | 本地参数错误 | 否 | 不联网 |
| 无法确认 16-token 硬上限字段 | 完整验证不可安全执行 | 可保留基础/手填状态 | 不发送生成探针 |
| 探针成功但 usage 缺失 | 生成通路已验证；usage 仍未知 | 是 | 不为补 usage 重试 |
| 探针失败或流无终态 | 保留已成功的列表结果，完整验证失败 | 基础结果可保存 | 0 次自动重试 |
| 能力证据写库失败 | 本次连接结果仍成立；缓存未更新 | 是 | 不重放远端请求 |
| 总时限耗尽 | 连接测试超时 | 否或保留此前已呈现的局部信息 | 不超过 60 秒，不自动重试 |

手填回退只处理“列表端点确实不存在”这一类兼容差异，不能成为错误密钥或网络失败的绕过入口。连接页不得展示服务商原始错误正文。

## 19. TASK-045 章节提交失败分类

| 失败证据 | 处理 | 禁止行为 |
|---|---|---|
| 章节当前版本已变化 | 保持用户版本，Stage 留在 `COMMITTING` 供恢复裁决 | 覆盖用户改稿或静默改父版本 |
| permit、最新 Attempt、artifact 修订/hash 或租约不匹配 | 失败关闭并进入恢复审计 | 使用旧许可重放或重新请求 Provider |
| 派生数据外键/唯一约束/JSON 来源不合法 | 整笔事务回滚，记录低敏错误分类 | 保留正文但丢摘要/记忆 |
| Usage 结算冲突 | 整笔事务回滚 | 把未知费用改成 0，或只提交正文 |
| 下一 Stage 缺失、非 PENDING、跨 Job 或时间倒退 | 整笔事务回滚 | 动态猜测/新建下一 Stage |
| 同一成功 Stage 完全相同重放 | 返回既有版本，允许 Usage 单向提升 | 重复插入版本或累计章数 |
| 同一成功 Stage 的载荷不一致 | 失败关闭并要求恢复审计 | 把不同内容伪装成幂等重放 |

提交失败本身不触发新模型请求。`COMMITTING` 阶段重启后必须先查询 Stage 输出引用、章节版本、派生数据和 Usage，再由 TASK-047 判断是精确重放、恢复完成还是需要用户处理。

## 20. TASK-048 前台服务错误处理

| 情况 | 处理 | 禁止行为 |
|---|---|---|
| Android 拒绝从后台启动 FGS | `requestStart` 返回失败，保持原 Job 状态并在 App 内说明需重新打开开始 | 循环重试、伪装为已开始 |
| 通知权限被拒绝 | 仍按系统要求启动 FGS；App 内保留状态和控制入口 | 因通知不可见而省略前台通知或静默常驻 |
| action/Job ID 非法、任务缺失或已终态 | 立即移除通知并停止 | 猜测 Job、创建新 Job 或联网 |
| 暂停/停止写库竞争失败 | 退出服务，由数据库中较新的持久状态决定后续 | 用内存状态覆盖数据库 |
| Android 15 `onTimeout` | 应用级协调器请求 `SYSTEM_FGS_TIMEOUT`，服务在 1.5 秒硬截止内停止 | 等待网络、长事务或无限期安全点 |
| 超时与用户控制并发 | 既有更强或更早的持久控制获胜；服务仍及时退出 | 改写已落盘的停止为暂停 |
| 服务进程销毁 | 不修改 Job；由 TASK-049 恢复审计 | 在 `onDestroy` 自动重发请求 |

## 21. TASK-049 恢复/维护错误处理

| 情况 | 处理 | 禁止行为 |
|---|---|---|
| 租约未到 60 秒边界或父 Job 仍有活动心跳 | 跳过，等待后续维护机会 | 抢占活动执行器 |
| 扫描后现场被新执行器改变 | 记为 stale，由较新持久状态获胜 | Worker 内反复覆盖或猜测新状态 |
| `PREPARING` 回队时 Stage/Job 任一 CAS 失败 | 同一事务整体回滚 | 只释放 Stage 或只释放 Job |
| 仅有 RequestIntent、查询能力不可用 | 标记未知/需处理并保留 Attempt、Usage、草稿 | 当作未发送并创建第二个 Attempt |
| 暂停/停止卡在网络活动阶段且双租约到期 | 使用现有控制事务结算 | 由 WorkManager 直接调用 Provider cancel/generate |
| 暂停/停止卡在本地校验/提交且证据不足 | 延后并保留 artifact | 猜测提交成功、删除草稿或自动重写 |
| 单个候选发生非并发异常 | 记录通用失败计数，继续其他候选；Worker 最多重试两次 | 把异常原文、ID、正文或连接写入 Work Data |
| 周期维护电量/存储约束不满足 | 交给 Android 延后 | 前台强行运行或要求用户手动维护 |
| Worker 被系统取消 | 协程取消向上传播；已提交事务保留、未提交事务回滚 | 把取消伪装为 Job 失败或重新发送 |

## 27. TASK-055 正文流与续接错误处理

| 现场 | 持久处理 | 用户默认看到 | 禁止动作 |
|---|---|---|---|
| `STOP` 但 JSON 未完整结束 | Attempt `SUCCEEDED + FORMAT_INVALID`，Stage/Job 进入需要处理 | “这次正文格式不完整，草稿已保留” | 把可见前缀当正式完整章节 |
| `LENGTH` 且片段安全 | Attempt `SUCCEEDED + OUTPUT_TRUNCATED`，结算 Usage 后进入 `RETRY_WAIT` | 正常情况下无弹窗，继续显示生成中 | 原 Attempt 内继续写或复用同一 Usage |
| 续接锚点不匹配 | 保留预置旧正文，新内容不追加，标记 `FORMAT_INVALID` | “续接位置无法确认，已保留原草稿” | 模糊匹配、删尾或重复拼接 |
| 第 4 次截断/attempt 上限 | 保存累计草稿，Stage `NEEDS_ACTION` | 一个推荐动作，详情可换模型或降低单章目标 | 重启后清零次数继续收费 |
| 累计正文超过 4 MiB | 联网/追加前失败关闭，保留最后安全版本 | “本章草稿已达到安全上限” | 截断旧正文腾空间 |
| 终态已落库、结算前崩溃 | 本地验证 artifact/hash 后完成原结算，遗失的内存用量记为 `UNKNOWN` | 通常无感；无法验证时才需处理 | 重新调用 Provider 补结果 |

正文流错误不会改写为网络错误；服务商策略拒绝仍按 `POLICY_REFUSAL` 处理，不能借续接机制绕过服务商规则。
| 组装后圣经、窗口或上一章已变化 | Provider-open 失败关闭，旧快照不发送 | 自动重新本地组装 | 使用旧 payload 或只修改 hash |
| manifest/payload/output reference hash 不一致 | 视为本地证据损坏并拒绝发送 | 重新准备本章 | 从部分字段猜测并继续 |
| 用户正在暂停 | 完成本地安全结算后 Job `PAUSED` | 继续时恢复 | 激活远程 Stage 或打开 Provider |

## 30. TASK-058 一致性与呈现检查错误处理

| 情况 | 系统动作 | 默认用户动作 | 禁止 |
|---|---|---|---|
| 本地正文/来源/人物/时间/物品/必需事件为 blocker 或 major | 直接生成退修决定，不创建 Provider 请求 | 通常无操作 | 为“再确认一次”调用模型 |
| 成年或虚构身份门禁不通过 | `SCENE_BLOCKED`，Provider 调用 0 | 补充合法人物资料或调整场景 | 静默改成留白、替用户改年龄 |
| 23 项标准缺失、重复或顺序错误 | 首次有界格式修复，第二次停止 | 通常无操作；耗尽后重试/换模型 | 接受部分报告或自动补“通过” |
| 严格过程节点缺失、重复、乱序或错误引用 | 结构无效或产生固定缺失问题 | 自动退修/一次格式修复 | 用总分代替逐节点证明 |
| 严重度或修订动作不符合问题码 | 拒绝整份模型报告 | 自动格式修复一次 | 允许模型把 minor 升级成 blocker |
| candidate/input/local/scene hash 变化 | Provider-open 前 0 调用；返回旧结果时拒绝 | 按新候选重新准备 | 只改 hash 或复用旧报告 |
| blocker/major 检出 | `REVISE_CANDIDATE`，正文仍为受保护候选 | TASK-059 自动有限修订 | 提前写入正式章节 |
| 只有 minor/无问题 | `ACCEPT_CANDIDATE` | 无操作 | 把“允许提交”冒充“已经发布” |
