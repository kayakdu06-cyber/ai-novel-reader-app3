# 织卷可亲手验证纵向切片规格

> 版本：VS-1
> 日期：2026-08-11
> 目标设备：用户当前 Android 测试机
> 目标 Provider：DeepSeek V4 Flash，经 OpenAI Chat Compatible 连接

## 1. 交付目的

这不是展示页面的原型，也不是宣称完成 1.0。它必须让用户在真实手机上，从一句故事设想到连续阅读 3–5 章，亲手判断：

- 文字是否能看；
- 首段是否够快；
- 剧情是否重复；
- 人物、关系、道具和特殊机制状态是否可信；
- App 是否能在退出、暂停或短暂断网后恢复。

## 2. 用户可见范围

### 2.1 首次使用

1. 打开 App。
2. 阅读一次本地/远程数据说明。
3. 选择 DeepSeek 或 OpenAI 兼容连接。
4. 输入 Base URL 和 API Key。
5. App 自动推荐或验证模型；用户不需要理解协议细节。
6. 连接保存后进入创作页。

连接管理沿用现有功能，不重新设计。

### 2.2 创建一本书

默认只显示：

- 一句话设想；
- 可选题材标签；
- 篇幅；
- 内容呈现：留白、均衡、细写；
- 一个“开始生成”按钮。

高级项默认折叠。用户不填写时由系统补全。

篇幅：

- 短篇：最少和默认 80 章；
- 中篇：最少和默认 300 章；
- 长篇：用户输入 301–10,000 章。

VS-1 为节省测试费用，只实际生成前 3–5 章，但保存真实全书目标，不把测试章数伪装成短篇总章数。

### 2.3 开始前确认

只在首次或实质变化时确认：

- 使用哪个连接和模型；
- 小说内容会发送到哪个 canonical origin；
- 预计本轮 3–5 章测试的 token/费用；价格未知时如实显示未知；
- 当前全书目标章节数；
- “开始”。

用户点击一次后不逐章确认。

### 2.4 生成中

开始后立即进入书籍页面，不停留在技术日志。

页面显示：

- 书名；
- 当前阶段的自然语言状态；
- 已完成章节数 / 本轮目标；
- 暂停和停止；
- 第一章正文流出现后可立即阅读；
- 后续章节在后台继续生成。

用户不需要手动点“生成下一章”。

### 2.5 书架

至少显示：

- 封面占位；
- 书名；
- 已完成章节数；
- 当前状态：生成中、已暂停、需处理、已完成；
- 最近阅读章节；
- 点击进入阅读。

本切片不做广告、签到、商城、会员或社区入口。

### 2.6 阅读器

至少支持：

- 暖纸色正文；
- 高可读字号和行距；
- 点击正文显示/隐藏工具层；
- 上一章、下一章；
- 侧滑或抽屉目录；
- 已完成、生成中、待生成状态；
- 阅读第一章时后台继续生成第二章；
- 新章节完成后目录自动更新；
- 无正文时显示“正在生成”，不显示假内容。

VS-1 不要求复杂翻页动画、全字体库、听书或书签系统。

## 3. 必须打通的技术链

创建快照
→ 目的地确认
→ 预算预留
→ 创建 GenerationJob/Stage
→ total runner 领取双租约
→ 章前上下文
→ chapter-plan
→ 流式正文 artifact
→ 章后合并分析
→ 本地一致性和状态转移校验
→ 可选修订
→ 章节原子提交
→ 书架/目录更新
→ 下一章自动入队

任何一段都不能靠开发者按钮、手动数据库写入或测试假页面跨越。

## 4. 可复用与新增

### 4.1 直接复用

- 连接向导、连接列表和当前连接。
- 创建页、篇幅规则、呈现映射和不可变创建快照。
- 目的地确认和三层预算。
- SQLCipher、Keystore、加密草稿。
- Job/Stage、Attempt、Usage、双租约和恢复。
- Provider adapters、Fake Provider 和统一错误。
- 章前上下文、正文流、截断续接、记忆、追踪、一致性和提交仓库。
- Foreground Service 和 WorkManager。

### 4.2 必须新增或接通

- StartGenerationUseCase / GenerationStarter。
- 完整但有限的 total runner registry。
- chapter-plan.v2 生产执行与提交。
- initial draft 的冻结来源合同和 exact-token 执行。
- chapter-post-analysis.v1 及现有仓库映射。
- 章节自动推进器。
- Library/Reader/Template 的生产导航和 Compose UI。
- 生成中正文投影，只读受保护草稿，不把半章当正式 ChapterVersion。
- UI 状态流与前台服务状态同步。

## 5. 测试书样本

### VS-A：基础网文

- 类型：都市或玄幻；
- 重点：目标、冲突、转折、钩子；
- 验证：每章有推进，不重复上一章。

### VS-B：组合能力

- 类型：修仙 + 恋爱 + 系统 + 道具；
- 重点：境界、系统等级、关系和道具归属分别可信；
- 验证：未出现的能力不占本章 Prompt。

### VS-C：关系后果

- 类型：虚构成年人关系剧情，可选择细写呈现；
- 重点：重要关系事件对信任、承诺、行为和后续剧情产生可追踪后果；
- 验证：不得淡化成“发生过但无后果”，也不得让此能力污染无关章节。

所有测试角色必须有明确虚构与成年人证据。Provider 拒绝时如实记录，不把拒绝当 App 成功。

## 6. P0 验收

### VS-TEST-001 一次开始

- 点击开始只创建一个活动 Job。
- 双击、旋转屏幕或重组不能重复创建。
- UI 立刻进入生成页。

### VS-TEST-002 第一段可读

- Provider 首段到达后 500 毫秒内显示。
- 第一段是受保护草稿投影，不写入正式版本。
- 退出再进可恢复已落盘草稿。

### VS-TEST-003 原子第一章

- 分析与校验通过后，正文、记忆、状态、用量和进度一次提交。
- 杀进程发生在提交中间时，要么全部存在，要么全部不存在。
- 重放不能产生第二份章节。

### VS-TEST-004 自动下一章

- 第一章正式提交后，第二章自动排队。
- 用户阅读第一章不阻塞后台生成。
- 暂停后不打开新 Provider 请求。

### VS-TEST-005 连续 3–5 章

- 章节顺序连续。
- 没有重复核心剧情。
- 计划义务都有状态。
- 人物位置、关系、道具和启用的特殊机制无无证据跳变。
- 任一章失败不损坏已完成章节。

### VS-TEST-006 进程与网络恢复

- 在 PREPARING、STREAMING、ANALYZING 和 COMMITTING 各杀进程一次。
- 已确认未发送的请求可以安全重试。
- 结果未知时进入待处理，不自动重复收费。
- 网络恢复后从权威状态继续。

### VS-TEST-007 预算和目的地

- 未确认目的地不能联网。
- host、端口、scheme 或协议变化要求重新确认。
- 超过单次、每日或单书上限时不打开 Provider。
- 价格未知不能伪造金额。

### VS-TEST-008 阅读体验

- 3,000–5,000 字章节滚动流畅。
- 目录在新章完成后更新。
- 200% 字号和横屏无关键按钮不可达。
- 阅读页不出现调试 ID、hash、Stage 名或密钥信息。

### VS-TEST-009 安全

- 源码、日志、数据库明文扫描和 APK 扫描不含真实 API Key。
- 正文和 Prompt 不进入自由文本日志。
- 自动系统备份继续关闭。

### VS-TEST-010 性能

- 点击开始到 Provider 打开 P95 ≤3 秒。
- 第一可读段 P50 ≤10 秒，P95 ≤25 秒。
- 3,000–5,000 中文字正文 P95 ≤300 秒。
- 正式提交 P95 ≤360 秒。
- 10 分钟仍未完成视为发布阻断故障。

## 7. P1 验收

- 生成状态文字对非技术用户可理解。
- 暂停、继续和停止操作在两步内完成。
- 失败页给出下一步，不只显示异常名。
- 书架状态与数据库权威 Job 状态一致。
- 夜间模式和至少三档字号。
- 目录能跳转任意已完成章节。
- 真实 token/用量可查看，但默认不打扰阅读。

## 8. 不允许的假完成

- 只在单元测试中生成，不从 App 页面启动。
- 用硬编码小说正文代替 Provider。
- Fake 成功但没有真实 API 合同测试。
- 只显示流式文本，不写正式章节和记忆。
- 只写数据库，不在书架和阅读器可见。
- 每章要求用户手动继续。
- 为通过演示关闭预算、加密、租约或恢复门禁。
- 等完整 80 章后才给用户 APK。

## 9. 交付物

- Debug/内部 APK。
- APK SHA-256。
- assembleDebug、test、边界检查和 secret 扫描日志。
- Fake 3–5 章报告。
- DeepSeek V4 Flash 真实测试报告。
- 设备验收截图或日志，必须脱敏。
- 已知问题列表。
- Git commit 和已同步远端。

## 10. 退出条件

用户亲手使用后做一次产品裁决：

- 若文字质量和速度可接受：进入模板、阅读完善和 20 章可靠性。
- 若质量不足：先调整策略包、计划和章后分析，不扩大 UI。
- 若速度不足：减少远程阶段、压缩 Prompt 或调整模型参数，不牺牲本地提交安全。
- 若恢复不足：暂停真实长跑，先修 runner。
- 若 API 兼容不足：只修 Provider/合同边界，不推翻本地数据架构。
