# 工作汇报：开放题材与状态适配器边界澄清

> 日期：2026-08-11
>
> 项目：app开发3 / 织卷

## 1. 用户指出的问题

原文“小说可同时组合修仙、恋爱、系统、悬疑、亲密关系、道具成长等能力”虽然包含“等”，仍容易在开发时被误读为有限支持列表，进而产生两类严重偏差：

1. 未列出的题材、关系、机制、结构或文风被拒绝、丢弃或改成默认类型；
2. 为了扩大“支持类型”，按每一种题材增加专用代码、状态表、Prompt 和重复测试。

## 2. 统一裁决

- 用户创作意图是开放词汇：可以自由描述并任意组合，不存在题材白名单。
- 快捷预设只减少操作，不限制实际内容。
- BookCapabilityManifest 不是支持类型表，只选择需要确定性跨章约束的内部状态适配器。
- 没有专用适配器的题材仍由通用叙事、人物连续性、叙事义务和证据语义处理，不能因此拒绝生成。
- 只有数值、归属、阶段、承诺等需要长期不变量的机制，且真实可靠性缺陷证明通用处理不足时，才新增专用适配器。
- 开放文本输入不等于开放可执行扩展；首版仍不做动态插件、运行时 skill 或用户自定义 capability。

## 3. 已同步文档

- PRD 与功能清单：明确 13 类预设不是支持范围，自由输入必须原样保留。
- 开发总规划与策略包规格：拆开“开放创作意图”和“有限状态适配器”。
- Vertical Slice 与任务清单：测试样本不定义题材范围；TASK-122 增加一个未列入预设的自由题材最小用例。
- 模板与 UX：分类标签仅用于查找和展示，不裁剪模板内容。
- 决策日志与追踪矩阵：新增 DEC-084，并记录实现和最小验证边界。
- 当前 AI 上下文：将该裁决写成后续开发硬规则，避免上下文切换后再次误读。
